# 本地直跑 vs Docker 沙箱 测试执行耗时对比

- 生成时间：2026-10-27T00:58:50
- 环境：Windows / Docker / 镜像 mta-test:py312（限额 1.0 CPU / 1024MB）
- 命令对等：两侧同跑 `pytest -q --tb=short -rfE --cov=. --cov-report=term`
- 口径：冷=建容器+快照+装依赖+执行；热=复用常驻容器只重跑 pytest；本地=宿主 subprocess 直跑
- 对等性：宿主已装 pytest+pytest-cov；两侧均 PYTHONDONTWRITEBYTECODE=1
- 轮次：本地 6 轮取后 5 轮；容器 冷1 + 热4；表内为 均值±标准差（秒）

## 结论（论文口径）

- 容器沙箱**热运行显著快于 Windows 宿主直跑**（≈0.8s vs ≈3.1s，约 3.8 倍）：Windows 进程创建与安全软件扫描开销主导，Linux 容器内 pytest 更精简。
- 容器化的性能代价只有**一次性冷启动 ≈1.3s**（建容器 0.37 + 快照 0.1 + 执行 0.85），常驻容器 + exec 复用后边际成本低于宿主。
- 因此「容器化降低测试效率」的直觉在本机环境不成立：容器既提供隔离/可复现/资源限额，又无性能 penalty——这正是本课题 L4 选型的量化依据。

### 诚实边界

- n=5 轮、单机（Windows 宿主 + Docker Desktop）、微型被测对象（1~3 文件）；
- 热运行口径不含依赖安装（demo 场景无 requirements.txt）；带依赖项目的首跑耗时由依赖体量决定，可用 volume 缓存 ~/.m2 / pip 缓解；
- Linux 宿主上「容器快于宿主」的差距预计收窄，该结论仅在 Windows 宿主语境下成立。
