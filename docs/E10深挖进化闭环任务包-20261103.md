  E10 把这些数据**反哺回生成与审查管线**，闭环"学习-进化"叙事（论文第 6 章从统计升级为闭环实证）。
- 物理账同 E9：3 亿 ≈ 2,083 元；单机 3h 上限 ~8,000 万 → 分波执行（E9 建的并发队列+停车线直接复用）。
- 前置：E9 已完成（数据集/并发基础设施/停车线机制）。

## 3. 交付物（论文与系统各得什么）

1. **第 6 章新三节**：失败知识反哺的收敛曲线（Arm 1）/跨模型审查一致性矩阵（Arm 2）/演进退化斜率（Arm 3）——每节都是"别人没做过"的组合创新；
2. **oracle 可靠性闭环**：Arm 3(投票)+Arm 4(对抗) 连起来 = "投票生成→变异验证→R1 重写→再验证"完整证据链；
3. **系统新能力**：双模型客户端（R1 记账）/动态陷阱库/演进序列生成器——都是可写进工程贡献节的机制；
4. **数据集**：E9+E10 两代数据对比 = "学习环是否真的学习"的最终答案。

## 4. 护栏（继承 E9 全套）

- 停车线 3 亿（llm_calls 实时累计熔断）/ 失败率 >20% 降并发 / 每跑 JSON 留档；
- R1 特有：reasoning token 单独记账（model 字段区分，成本换算按双价目）；R1 延迟高（思考链）→ 并发数按实测收敛；
- 角色分离红线不变：R1 审查的提示词 ≠ chat 生成的提示词；证人保护对 R1 同样生效；
- **对照诚实纪律**：Arm 1 若"知识反哺无提升"=发现二的规模化复现，如实写（负结果双倍价值：静态与动态知识注入都无效→瓶颈铁证在 oracle）。

## 5. 需要用户确认的三件事

1. **总预算**：E9+E10 合计 ~4,200 元级别（停车线各 3 亿）——授权或砍 Arm；
2. **R1 计费**：deepseek-reasoner 思考链 token 单价高于 chat，实测汇率需重校准（预计 1 元 ≈ 60-80k）；
3. **演进序列的"合成 commits"口径**：注入缺陷=不可发现的诚实声明（测试的对象是"套件随演进的退化"，不是修复合成缺陷的能力）。
