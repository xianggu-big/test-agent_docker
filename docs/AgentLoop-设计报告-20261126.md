## 1. 两个节点各自的任务契约

"干好活"必须先能被量出来。下面每个指标都由脚本从运行账本、工作区源码和生成用例里确定性计算，不靠模型自评。

### 1.1 strategy

任务：规划前读代码，指出具体的风险点，产出能指导用例设计的优先项。

| 指标 | 定义 | 目标 |
|---|---|---|
| S-K1 收尾率 | 以 finish 结束的循环数 ÷ 全部循环数 | 100% |
| S-K2 具体率 | 点名了具体符号或文件的优先项数 ÷ 优先项总数 | ≥ 80% |
| S-K3 真实率 | 具体的优先项里，点名的符号在被测源码里确实存在的比例 | ≥ 90% |
| S-K4 落地率 | 真实的优先项里，点名符号出现在该任务生成用例里的比例 | ≥ 60% |
| S-K5 平均步数 | 每次策略循环的平均步数 | ≤ 4 |
| S-K6 成本 | 每格 token 相对盲跑基线（v1 测量批）的增幅 | 见测试报告 A6 |

"具体"的判定：从优先项的 `why`、`feedback`、`targets` 里抽出标识符（字母开头的词，长度 ≥ 3，去掉语言关键字），或形如路径的字符串。抽到至少一个就算具体。`.`、`./...`、`tests`、单独的项目名不算。

### 1.2 diagnose

任务：补测之前判定上一轮失败属于哪一类，并给出和类别自洽的建议。

| 指标 | 定义 | 目标 |
|---|---|---|
| D-K1 类别准确率 | `kind` 与夹具设定类别一致的格数 ÷ 有效夹具格数 | ≥ 8/9 |
| D-K2 引用有效率 | 指向本次循环里真实存在的证据条目的引用数 ÷ 引用总数 | 100% |
| D-K3 置信校准 | 证据充分的夹具上给出 medium 或 high 的比例；证据不足时必须是 low | ≥ 2/3；不得虚高 |
| D-K4 建议自洽率 | 建议动作与类别自洽的比例 | 100% |
| D-K5 恢复率 | 诊断之后的下一轮，有效执行至少 1 条用例的格数比例 | 只观察，不设硬线 |

类别与建议的自洽表：

| 类别 | 自洽的建议动作 |
|---|---|
| `scaffold_error` | `scaffold_fix` 或 `generate` |
| `expectation_dispute` | `generate` 或 `report_human` |
| `env_error` | `env_fix` |
| `product_defect` | `report_human` |

"有效夹具格"的口径：该格第一轮判定确实是补测，且账本里有诊断循环。夹具没把诊断触发出来的格子不算数，也不算失败。

## 2. 修复项

七项必须做，外加一项小的。每项都先红后绿。

### F-AL1 证据摘录进观察包（核心）

**改什么**

1. `CapResult` 加一个字段 `excerpt`（进观察空间的正文摘录）。`normalize_result` 按模式截断：strategy 1,500 字符，diagnose 1,200 字符。
2. 各处理器填 `excerpt`，只填最有信息量的那段：

| 能力 | 摘录内容 |
|---|---|
| `test.observe.read` | 窗口里的正文 |
| `test.observe.read`（list） | 条目列表 |
| `test.observe.read`（grep） | 命中行 |
| `test.observe.logs` | 错误输出尾部 800 字符在前，标准输出尾部 400 字符在后 |
| `test.run.unit` | 指标行，加前几条失败信息 |
| `test.observe.coverage` | 未覆盖的文件和行 |
| `test.observe.env` | 技术栈的关键字段 |

3. `_execute_capability` 把 `excerpt` 带回来（`tool_loop.py:91-92` 的键列表加上它）。
4. 循环把它放进证据条目；观察包里每条证据渲染成"头行 + 缩进的正文"。
5. 观察包总上限 12,000 字符不变。超限时只裁证据正文的中间部分，**永远不裁"## 输出"及之后的指令段**。现在是整包硬截（`tool_loop.py:139`），会把尾部的指令截掉。

**验收**：读文件之后，观察包里有该文件至少一行真实代码；取日志之后，观察包里有错误输出的文字；总长不超上限；尾部指令段完整。

### F-AL2 诊断一开工就拿到失败摘要

**改什么**

1. `diagnose_node` 在调用循环之前，从状态里确定性地生成一份摘要：轮次、判定、归因、通过/失败/跳过数、退出码；失败用例清单（最多 20 条，每条带用例名、错误类、消息前 160 字，复用 `repair.failing_nodeids`、`failure_summary_of`、`error_class_of`）；错误输出尾部 800 字符；命中的可疑信号（复用 `attribution` 里现成的环境和用例侧特征表）。
2. 通过 0、失败 0 的时候，摘要里显式写一行："**零执行**：没有任何用例被执行，不是覆盖率不足"。
3. 摘要作为第 0 号证据进入循环，观察包里单列一节。模型可以直接引用它，不必再花步数取证。

**验收**：给一个 0/0 的状态，观察包里有"零执行"；给一份含 `Cannot find module` 的输出，失败清单里有那条用例，可疑信号里有它。

### F-AL3 菜单按阶段过滤

**改什么**

1. 每项能力标注两个属性：是否需要容器、是否需要上一轮的运行结果。
2. strategy 模式的菜单只留不需要容器的：读代码和宿主侧的技术栈探测。diagnose 模式照旧只留只读能力。
3. 策略模式的目标文案补一句："现在是规划阶段，还没有容器，不能运行测试；你的任务是通过读代码定位具体风险点。"
4. 模型仍然调用不可用能力时，拒绝原因写清楚："该能力在当前阶段不可用（容器未创建）"。

**验收**：strategy 的菜单里没有 `test.run.unit`；diagnose 的菜单里有它；拒绝原因如上。

### F-AL4 参数提示带范围

**改什么**：`_schema_hint` 输出上限和取值范围，例如 `tail_n:int(≤50)`、`limit:int(1-200)`、`timeout_s:int(≤600)`。

**验收**：提示串里能看到上限。

### F-AL5 提示词 v3：策略必须具体

**改什么**

1. strategy 的收尾示例换成模型真正看得到的形态："读到了某文件某行的什么 → 所以测哪个边界"。
2. 明令：每条优先项必须点名具体的符号（函数、类、接口路径）和具体的边界；禁止 `.`、`./...`、`tests`、单独的项目名；`why` 写成"读到了什么 → 所以测什么"。
3. diagnose 补一个收尾示例，证据引用指向失败摘要的编号。纪律加两条：失败摘要已经够用的时候直接收尾，不必为了凑步数再取证；证据不足才给 low。
4. 加一道机器闸：strategy 模式下，finish 里的优先项全是泛指目标，这次 finish 不算数。循环追加一条证据"策略全是泛指目标，请点名具体函数、文件或边界后重新收尾"，然后继续。最多重试一次；第二次仍然泛指就接受，但在产物上标 `strategy_valid=false`。
5. 版本戳升到 `v3`，注释写明 v2 到 v3 改了什么。任务一刚改过的版本锁测试和黄金演示夹具，同步到 v3。

**验收**：全是泛指的策略触发一次重试；具体的策略直接通过；版本锁测试更新为 v3。

### F-AL6 策略的目标传给下游

**改什么**

1. 进规划提示词的策略段，每条优先项加一行目标（来自参数提示，截 120 字）。
2. 生成用例的提示词也注入策略段，最多 5 条，每条一行。没有策略就是空串，输出逐字节不变。生成提示词有两条拼装路径，必须共用同一个 helper。11-20 那次端点缺口补测，就是因为只接了一条路径而失效。

**验收**：有策略时，规划和生成的提示词里都能看到目标；没有策略时逐字节不变；已有的五环节 AST 锁测试不破。

### F-AL7 `test.gen.cases.targets` 接线

这是 Q4 设计方案登记的范围外发现 F1：schema 声明了 `targets`，但生成函数不读它。

**改什么**：`generate_tests` 消费 `targets`，注入一段"定向补测目标"。不传就是空串。

**验收**：传了，提示词里有目标；没传，逐字节不变。

如果实施时发现参数链的改动面比预期大，允许降级为"从 schema 里删掉 `targets`，改能力描述"。二选一，在完工记录里写明选了哪个。

### 不做的

- **不移动 strategy 节点的位置。** 备选方案是挪到环境准备之后，让它能真的跑一遍现有测试。等这轮测完，看落地率再决定。
- **不改评估节点对零执行的判定文案**（检查报告 C5）。那是 R-Loop 主链路的行为，改它会波及没开循环的任务。
- **不改"诊断永不写判定"。**
- **不跑循环开和关的对照臂。** 用历史基线对比，省一半预算；结论里如实写明"历史基线来自不同时期，部分混档"。

## 4. "一直开着"的方案

**放行**：测试任务报告第 6 节的预注册判据全部通过，才把 `config.py:236` 的默认值翻成开。同时把默认关态的测试改成显式关，做法和 Q1 落地时一样。全量 pytest 绿，单独提交。

**不放行**：有任何一条没过，保持默认关，写明哪条没过、差多少。

**运行期护栏**（都已经在代码里，列出来备查）

- 循环里任何异常都变成 `hard_error`，主链路照常走默认路线。
- 预算：8 步、30,000 token、600 秒；策略模式里观察能力最多 3 步。
- 模型构造失败（余额不足、断网）时产出空策略，不炸任务。
- 静态项目不进策略节点。

**关闭方法**：`MTA_AGENT_LOOP=0`。

**监控**：`scripts/agentloop_kpi.py`（测试任务里要写的脚本）可以随时离线重算上面这些指标。
