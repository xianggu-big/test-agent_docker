## 0. 实测锚点（研究文档 §1，直接引用）

- qwen3:4b-instruct 原生 262k ctx；4GB 卡 KV 预算：f16≈9k tok / q8_0≈19k / q4_0≈38k；
- 真实提示词分布：94% ≤8k，6% >8k，max 40,634；KV 溢出 CPU=5 倍掉速（已实测）；
- L1（环境变量，非代码）：`OLLAMA_FLASH_ATTENTION=1 + OLLAMA_KV_CACHE_TYPE=q8_0` → 16k 可用，覆盖 99.8% 历史调用。

## 1. 实现项

1. **步骤2·截断对账闸**：make_chat 本地端点路径，调用后从响应 usage（或 Ollama 返回的 prompt_eval_count）读实际 prompt_tokens；≥ num_ctx×0.95 → 台账与返回消息打 `context_truncated: true` + 建议（"减小源码预算或分模块生成"）。llm_calls 增列 `truncated INTEGER DEFAULT 0`（第 32+1 表内加列走 _MIGRATIONS，动守卫则同步）；
2. **步骤3·ctx_budget 与预算降采样**：profile 增可选 `ctx_budget`（local=16384）；build_user_prompt 增 `ctx_budget` 参数：超预算时①源码按 radon 热点+入口文件排序降采样（token 估算 chars/2.5 起步，用 llm_calls 实测校准系数）②末尾显式声明"（源码已按预算截断至 X 字符，共 Y 字符）"；
3. **步骤4·段落裁剪顺序**：预算仍不足时按序砍：方法骨架示例段→覆盖缺口明细→条件尾部→源码尾部，每段砍多少留痕；
4. **步骤5·真机**：构造 >16k 提示词任务（大源码仓或调大源码预算），验证对账闸告警+降采样生效+最终用例产出正常；
5. **步骤6**：数据回填研究文档 §1.2 与 AGENTS.md。
