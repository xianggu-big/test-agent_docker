## 1. 现状：自动环境配套做到哪一步了

**已有能力（真实）**

| 能力 | 现状 | 位置 |
|---|---|---|
| 语言探测 | analyze 节点语言占比 → 主语言分级（full/static_only） | graph/nodes.py:292 |
| 固定镜像注册表 | python→mta-test:py312、javascript→mta-test:node20-jest、java→mta-test:jdk17-maven | config.EXEC_LANGUAGES |
| 镜像自动补齐 | 缺镜像按本地 Dockerfile 自动构建（ensure_image，模式③一条龙/AUTO_PREPARE_ENV/任务勾选） | sandbox/runner.py + graph/nodes.py:197 prepare_task_image |
| 依赖三清单安装 | probe_deps_manifest：requirements.txt / pyproject / setup.py 分流 + package.json(npm ci --ignore-scripts) | skills/install_deps |
| 环境预检 | Docker/镜像/Key 三胶囊 + 一键准备 + 409 下发守卫 | sandbox/preflight.py |
| 降级 | 非深度语言 → Tier3 static_only（确定性扫描+设计草稿，报告明示未执行） | skills/static_scan.py |

**伪能力（界面上像有其实没有）**：无。"按项目拉对应 Docker 环境"目前**只覆盖三个预置镜像对应的三种语言**——不是任意项目。问"能否按项目自动拉/构建"时，诚实答案是：**预置语言内=已做到；预置外=靠静态降级，没有真执行环境**。

**缺口**

1. 语言覆盖写死：Go/Rust/C++ 等直接 static_only，无路径升级。
2. 依赖安装只认 Python 三清单与 npm——poetry/poetry.lock、pnpm/yarn、Gradle 多模块、cargo 等不认。
3. 镜像内容固定（Python 3.12/JDK17/Node20）：项目要 3.9 或 3.13 时无解（装不上旧版依赖→假 env 失败）。
4. 无用户自带 Dockerfile/devcontainer 的消费路径。
5. 服务型依赖（测试需要起 Postgres/Redis）完全无机制（L3 只起被测服务本身）。

## 4. recipe JSON schema（v1）

```jsonc
{
  "schema_version": 1,
  "language": "python",              // enum: python|javascript|java|go|rust
  "runtime_version": "3.11",         // 必须命中 base_images 白名单里存在的版本
  "base_image": "mta-test:py311",    // enum 白名单：从基础镜像池选择，不允许任意字符串
  "package_manager": "pip",          // enum: pip|pip-tools|poetry|npm|pnpm|yarn|maven|gradle|go|cargo
  "install": ["pip install -r requirements.txt"],  // 每条都必须通过命令白名单正则闸
  "build": [],                        // 可空
  "test_cmd": ["pytest", "-q"],       // 由系统最终拼接，recipe 只给框架名+参数白名单
  "services": [],                     // v1 留空（Postgres/Redis 等 v2；写死禁用）
  "system_packages": [],              // apt 包白名单子集；空=不装
  "network": "restricted",            // enum: restricted(默认,仅 PyPI/npm 镜像)|off
  "timeout_s": 600,
  "evidence": {"detected_from": ["requirements.txt", ".python-version"],
               "confidence": "high"}  // LLM 必须声明探测依据；无依据=校验闸拒
}
```

## 5. 安全边界（LLM 乱写命令/供应链风险的防线）

1. **LLM 只做选择题不做填空题**：base_image/package_manager/runtime_version 全部 enum 白名单；install/test_cmd 逐条过正则白名单（允许 `pip install -r <file>`、`npm ci`，禁止 `curl|sh`、`sudo`、写盘外路径、`--index-url` 指向非白名单源）。
2. **确定性校验闸零 LLM**：schema（字段/枚举/类型）→ 命令白名单 → 版本在基础镜像池存在性 → 预算（Dockerfile ≤8 层、镜像 ≤2GB、构建 ≤10min）。不过=整个 recipe 拒绝，不带病进入构建。
3. **供应链可审计**：recipe 原文+校验结果+构建日志全量落库（新表 image_recipes，审计链同 review_decisions 先例）；依赖只从官方 PyPI/npm 源（`--ignore-scripts` 已有先例沿用到 npm/pnpm/yarn 全系）。
4. **容器侧不变的红线**：非 root、无 privileged、CPU/内存限额、快照预算（任务B）全部沿用——recipe 管的是"镜像怎么来"，不管"容器怎么跑"。
5. **失败降级**：自修复 ≤2 次仍失败 → static_only（现状），任务不因环境配套失败而炸——环境探索与测试执行解耦。

## 6. MVP 范围与不做项

**做**：python（pip/pip-tools/poetry 三 pm + 版本池 py3.9/3.10/3.11/3.12/3.13 五镜像）+ javascript（npm/pnpm/yarn 三 pm + node18/20/22 三镜像）；detect_stack 确定性探测；recipe schema+校验闸；基础镜像池构建脚本（FROM python:X-slim + pytest/coverage 薄层，复用 docker/python-test 模式）；健康检查探针；失败自修复 ≤2 轮；recipe 落库；static_only 降级。

**不做（v1 明确排除）**：java/go/rust 执行链路（镜像池与测试框架注入留 v2）；services（数据库容器编排 v2）；任意 Dockerfile 字符串生成（只有白名单拼装）；devcontainer.json 完整 spec（只消费 image+features 里的 runstall 步骤，v2）；远程沙箱。

| 项 | 估计 | 说明 |
|---|---|---|

| recipe schema+校验闸+单测 | 1 天 | 白名单正则集中 config |
| 基础镜像池（8 个薄镜像 Dockerfile+构建脚本） | 0.5 天 | 模板复用现有 docker/*-test |
| 构建编排+健康检查+缓存键 | 1 天 | 镜像 tag=recipe 内容哈希 |
| 自修复循环+落库+API/界面（环境配套卡片） | 1 天 | phase=recipe_propose/recipe_repair 记账 |
| 端到端联调+受控测试（无 LLM 路径+LLM 路径 stub） | 1 天 | 照任务C受控测试模式 |
| **合计** | **~5 个工作日** | 在"最小 2 周实现路径"预算内 |

**风险**：LLM 提案质量（缓解=白名单化，LLM 错误被闸拦住的最坏结果=降级 static_only，无新失败面）；镜像池构建时间（一次性，构建脚本缓存层）；poetry/pnpm 等包管理器沙箱内行为差异（探针覆盖）。
**回滚**：开关 `RECIPE_ENABLED` 默认关（沿 V 系开关先例：关=EXEC_LANGUAGES 旧路径逐字节不变）；镜像池是纯增量不覆盖现有三镜像。

## 8. 结论：是否值得做 + 2 周路径

**值得做，但限定 MVP 范围**。理由：①当前"自动拉环境"的口碑承诺与三语言现实有落差（用户已实际问到）；②降级路径已存在（static_only），新增失败面≈0；③论文价值——recipe 白名单化 = "LLM 提案 + 确定性闸 + 诚实降级"框架的又一实例（与 AI 代审 D1/D2、生成三道闸同构，答辩叙事连贯）；④Repo2Run（字节）验证了同题可行性，但其归档+面向运行镜像，说明"测试沙箱专用 recipe"有差异化空间。

**最小 2 周路径**：第 1 周=任务F MVP（§7 的 5 天）+ 受控测试；第 2 周=真机验证 5-8 个样本项目（含无 Dockerfile/大 data/旧 Python 版本三类）+ 论文 5.x 节补写 + 界面环境配套卡片。**启动条件：用户确认本设计。**
