## 1. 实验设计（定稿）

### 1.1 被测对象：corpus-003 会议室预约 API

任务卡原定"data/demo/场景A 或 multi-module-demo 的 utils 模块"，定稿改为 **data/corpus/corpus-003/project**（三源文件 128 行，app.py 95 行 ≤100），理由：

1. 场景A（calc.py）无答案键，multi-module-demo 不存在；corpus-003 有**预注册答案键**（ground_truth.json：D1~D5 真缺陷 + D6/D7 诱饵，含每缺陷 location/expected_assertion）；
2. **需求文本与系统臂逐字一致**（REQUIREMENT.md 就是系统臂当初吃的文本，零改写）；
3. E7 已有同语料系统臂历史数据（e7_task_*.json）可交叉对照。

与任务卡偏差声明：任务卡说"含 1 已知缺陷"，实取 5 缺陷版——更强的答案键基础设施，方向一致，如实记录。

### 1.2 三臂

| 臂 | 内容 | 计时 |
|---|---|---|
| 人工臂 | 2~3 名同学各限时 60 分钟，从需求文本+净化版源码出发手写 pytest 单元测试 | 墙钟（参与者自记+文件 mtime 复核） |
| 系统臂 | 同需求同项目跑一轮标准 L1 任务（local/deepseek 档各标注口径） | 墙钟（驱动计时）+ token 台账 |
| 混合臂 | 系统臂产物 + 人工 10 分钟审查修改 | 墙钟相加 |

### 1.3 统一评分（同一把尺，scripts/run_g_scoring.py）

- **检出判定 = 逐缺陷反事实差分**（项目已有的 diff-gate/LIBRO 思想，确定性零 LLM）：套件在 buggy 项目上跑出失败集 F；对每个缺陷 Di 应用唯一修复（修法注册表唯一依据 = ground_truth 描述）跑出 Fi；F−Fi 非空 = Di 被检出，差集即"检出了 Di 的测试"。人工套件没有 RTM/场景链，E7 的链路匹配口径用不了——反事实差分对两臂口径完全一致。
- **变异杀死率**：复用 mutation_kill.py 算子与判定口径（对 3 个项目源文件确定性算子变异，killed=基线之外新失败）。
- **基线中未对应任何缺陷的失败**（人工臂常见=写错/写崩的测试）如实列入 unmatched_failures——不冒充检出也不隐藏。
- decoy（D6/D7）不进分母；检出率分母恒为 5。
- 修复模式每条必须恰命中源码 1 处，否则 ValueError 如实报错（禁模糊替换）。

### 1.4 盲化（防答案键泄漏）

项目源码内联注释即答案键（`# D1：边界差一` 等）。人工臂发放 **docs/G材料/project_clean/** 净化版：剥离全部缺陷注释与"已种植缺陷"文档串，代码结构经 AST 等价校验（文档串归一后 dump 相同，单测锁死）；禁词扫描（D1~D7/ground_truth/缺陷/答案键/种植）零命中。评分一律跑原始 buggy 项目（净化只动注释/文档串，执行语义不变）。

### 1.5 四格指标（每臂产出）

| 指标 | 人工 | 系统 | 混合 |
|---|---|---|---|
| 耗时（墙钟） | ✓ | ✓（自动） | ✓ |
| 用例数/行覆盖 | ✓ | ✓ | ✓ |
| 变异杀死率 | ✓ | ✓ | ✓ |
| 检出已知缺陷（答案键，5 分母） | ✓ | ✓ | ✓ |
| token/人力成本 | 时间×时薪估算 | token 台账 | 两者相加 |

## 2. 诚实边界（预注册，防答辩翻车）

- n=2~3 小样本：只写"方向性观察"，不做统计检验；参与者水平差异如实记录（问卷 3 题：pytest 熟练度 / 该项目语言经验 / 测试经验，见参与者指引附卷）；
- 需求文本是系统的主场（明确、结构化）——论文注明"比较前提=按明确需求生成结构化单元测试这一切片"；
- 人的时间没有消失只是转移：混合臂专为量化"审查成本"而设；
- 人工套件因环境（fastapi 版本）全军覆没时如实报 error 不出分（评分管线内置）；
- 探索式测试不在对比内（人工主场，系统覆盖不了，见 W 卡范围外声明 §3.4）。
