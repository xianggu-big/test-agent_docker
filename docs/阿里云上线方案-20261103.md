## 1. 架构决策（单机起步）

```
用户浏览器 ──HTTPS──▶ nginx(:443) ──▶ uvicorn(:8000, 应用)
                                        │
                                        ├─▶ Docker 引擎（同机，mta-test:* 沙箱容器，逐任务创建销毁）
                                        └─▶ SQLite（data/test_agent.db，WAL，云盘）
```
- **应用不容器化、沙箱容器化**：应用直接跑在 ECS（systemd 守护），沙箱 Docker 同机——最简且符合
  "每任务一个容器"的现有架构。不要搞 ECS 里再套 Docker-in-Docker。
- **单 worker 队列已是串行**（exec_queue），单机单应用实例即可撑演示规模（压测：读 485 RPS/写 116 RPS）。
- **升级触发条件**：需要多机沙箱池、或多实例应用 → 此时才按报告任务 14 迁 PostgreSQL + Redis。

## 3. 安全组（第一道闸，最容易漏）

| 端口 | 开放 | 说明 |
|---|---|---|
| 22 | 你的 IP /32 | SSH，**禁止 0.0.0.0/0** |
| 80 | 0.0.0.0/0 | 仅跳转 HTTPS |
| 443 | 0.0.0.0/0 | HTTPS 业务 |

## 4. 部署步骤（从零到 HTTPS）

```bash
# 1) 基础
apt update && apt install -y docker.io nginx python3.12 python3.12-venv git
useradd -m -s /bin/bash testagent && usermod -aG docker testagent   # docker 组=root 等价，仅此一人

# 2) 代码与依赖
sudo -iu testagent git clone https://github.com/xianggu-big/test-agent_docker.git ~/app
cd ~/app && python3.12 -m venv .venv && . .venv/bin/activate && pip install -r requirements.txt
python scripts/build_images.py        # 预构建 mta-test:py312 / node20-jest（jdk17 可选）

# 3) 配置（绝不进代码库）
cat > ~/app/.env << 'EOF'
DEEPSEEK_API_KEY=sk-xxx
EOF
# config 从环境读 Key 的现状：确认 DEEPSEEK_API_KEY 注入 systemd EnvironmentFile

# 4) systemd 守护
cat > /etc/systemd/system/testagent.service << 'EOF'
[Unit]
Description=Test Agent (uvicorn)
After=network.target docker.service
Requires=docker.service
[Service]
User=testagent
WorkingDirectory=/home/testagent/app
EnvironmentFile=/home/testagent/app/.env
ExecStart=/home/testagent/app/.venv/bin/uvicorn test_agent.api.server:app --host 127.0.0.1 --port 8000 --workers 2
Restart=always
RestartSec=5
NoNewPrivileges=true
ProtectSystem=full
[Install]
WantedBy=multi-user.target
EOF
systemctl enable --now testagent

# 5) nginx 反代 + HTTPS（certbot 免费证书，域名需先解析到 ECS）
cat > /etc/nginx/sites-available/testagent << 'EOF'
server {
  listen 80; server_name your.domain.com;
  return 301 https://$host$request_uri;
}
server {
  listen 443 ssl http2; server_name your.domain.com;
  ssl_certificate     /etc/letsencrypt/live/your.domain.com/fullchain.pem;
  ssl_certificate_key /etc/letsencrypt/live/your.domain.com/privkey.pem;
  client_max_body_size 20m;                       # 需求文本/大 payload
  location /api/ { proxy_pass http://127.0.0.1:8000; proxy_read_timeout 300s; }
  location / { proxy_pass http://127.0.0.1:8000; }
}
EOF
ln -s /etc/nginx/sites-available/testagent /etc/nginx/sites-enabled/
apt install -y certbot python3-certbot-nginx && certbot --nginx -d your.domain.com
```

## 5. 上线前必修清单（按审计结果）

| # | 项 | 状态 |
|---|---|---|
| 1 | HTTPS 强制（token 走明文=可被中间人截获） | 上线必须（nginx 层已配） |
| 2 | SQLite 备份：`crontab: 0 */2 * * * sqlite3 data/test_agent.db ".backup /backup/$(date +\%F_\%H).db"` + 每日 OSS 归档 | 上线必须（SQLite 单文件优势=备份廉价） |
| 3 | 默认口令改掉：admin/admin123、dev/dev123 首启即改 | 上线必须 |
| 4 | 注册开关：公网建议暂时关闭开放注册（`auth.register` 加 config 门）或仅邀请 | 强烈建议 |
| 5 | IDOR（caller 可读任意任务）：演示语义可接受；公网若多租户，给任务查询加 `user_id` 过滤（server.py 4 处 SELECT 加 WHERE） | 公网多租户前必须 |
| 6 | 日志轮转：uvicorn 日志+data/workspaces 清理 cron（快照预算已有 512MB 上限，但磁盘仍会爬） | 建议 |
| 7 | DEEPSEEK_API_KEY 费用告警（DeepSeek 控制台设置余额提醒）——caller 可创建任务烧 Key，即费用攻击面；可给 caller 角色加每日任务数配额（login_events 同款限速思路） | 建议 |
| 8 | Docker 纵深：沙箱容器非 root tester+资源限额已有；**更硬的隔离（gVisor/kata）列后续**——注意 docker 组成员=可逃逸到宿主，应用进程被攻破即整机，故 NoNewPrivileges+最小用户已配 | 风险接受/后续 |

## 6. 攻击面清单（你说要主动打——按优先级当靶子）

1. **登录/注册接口**：限速已加（login 20 次/5min 每 IP、register 10 次/h），试试绕过（X-Forwarded-For 伪造 IP——**能绕**：`_client_ip` 读 request.client，nginx 反代后全是 127.0.0.1，且未信任 XFF 头——绕过难度在于所有攻击者共享同一限速桶，反可被 DoS 他人登录。修复方向：nginx 传 X-Real-IP + 应用信任它）。
2. **repo_url 注入**：白名单校验（仅 http(s)/git@/ssh 或本地路径）——试试 Option 注入、`ext::sh` 语法、本地路径读 /etc（本地路径放开了！**能 clone 服务器任意可读目录**——公网前建议关本地路径或加白名单目录）。
3. **生成用例逃逸容器**：import 白名单+非 root+资源限额——试试 import socket 外连、容器内 curl 公网（**网络未隔离，历史上列过 TODO-06**）。
4. **IDOR**：caller 角色横越（见 §5.5）。
5. **XSS**：esc 全量转义（F01 加固过）——试试 SVG/事件属性/模板注入点。
6. **下载/导出端点**：导出 Markdown 前端拼装，无服务端文件读取——安全。
7. **nginx 层**：限速（limit_req_zone）建议加在 login/register 路由（应用层限速可被并发绕，nginx 层更稳）。

## 8. 决策记录
- 不容器化应用本身：沙箱=容器、应用=systemd，避免 DinD 复杂度。
- SQLite 上线够用（压测 116 写 RPS、队列已串行化）；多实例时迁 PG（报告任务 14 的迁移点）。
- Redis 仅在多实例/日志推送时引入（报告任务 17）。
