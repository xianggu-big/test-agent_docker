# 种子自举模板设计（2026-11-05，用户提出，待实施）

## 用户想法（原话要点）
不同项目语言/结构不同 → 用例结构不同 → 先让 AI 造**一条能跑通的用例模板**，
环境验证通过后，用这个已验证的结构做固定模板，批量生成"同结构、不同内容"的用例。

## AI 复审：成立，附三个修正
1. **验证标准拆开（关键）**：种子要验证的是**结构与环境**（collect 通过 + 无导入/依赖错误），
   **断言失败不算模板失败**——抓到缺陷反而证明结构有战斗力。混淆两者会导致种子被错误重写
   （甚至迁就实现=踩防造假红线）。
2. **两层模板要分清**：传输 JSON（cases 数组）本来就固定；本设计创新在**代码结构模板动态化**
   （import 形态/函数包装/断言风格按项目实测锚定），与静态 T1/T2/T5 互补（静态保底/动态自适应）。
3. **防两坑**：种子强制最简形态（单函数单断言，禁参数化/fixture）；种子只锚结构不锁内容
   （测试内容仍按条件自由，保多样性）。

## 与现有机制的关系
- 静态槽位模板（T1/T2/T5）=结构保底通道；**本设计=第三通道"动态种子"**（自适应特殊项目）；
- 痛点命中：JS 生成废案率最高（jest 配置/导入形态千变万化，散装 JS 修复即同题）——种子自举
  对 JS 轨收益最大；
- 与 A 源（repo 用法锚点）互补：A 源锚"怎么调用被测代码"，种子锚"用例文件本身怎么写"。

## 实现设计
1. **种子阶段**：提示词（最简形态：单函数/单断言/覆盖最简单的一条条件）→ 生成 1 条 →
   容器内 collect-only 验证 → 失败重试 ≤2 次（带失败原因）→ 仍失败=环境真有问题，诚实降级；
2. **特征提取（确定性）**：AST 解析种子 → import 语句形态/函数包装/断言风格/装饰器清单；
3. **批量阶段**：种子全文作为"结构锚点"注入批量提示词（"严格按此结构，替换测试内容与条件"）
   + 条件清单 → 批量产物过同样 collect 闸；
4. **开关与消融**：SEED_BOOTSTRAP_ENABLED 默认关 + X-SEED 格 n≥3；
5. **判据**：批量 collect 废案率（对比自由通道）/种子重试次数分布/三臂对比（自由 vs 静态模板
   vs 动态种子）。

## 量
后端 1（种子阶段+特征提取）半天；提示词与接线 2h；消融跑数随充值批次。合计半天~1 天。
