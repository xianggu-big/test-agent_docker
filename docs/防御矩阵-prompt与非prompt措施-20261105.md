# 失败模式防御矩阵：Prompt 措施 vs 非 Prompt 措施（2026-11-05）

> 前提认知（设计第一原则）：**Prompt 的正确分工是"提供信息"，不是"阻止行为"**。
> 信息缺口类失败（AI 不知道考场布局/字段来源）→ prompt 是最优解；
> 行为/能力类失败（截断、模型漂移、通过压力、JSON 合规）→ prompt 只能降低概率，
> **必须确定性闸兜底**——因为 LLM 无法承诺遵守任何措辞。
> 判据：如果这条失败"AI 知道了就不会犯"→ prompt；"知道了也可能犯"→ 闸。

## 二、新设计的 Prompt 措施（此前未覆盖，可直接抄）

### P1 · 环境契约统一段（整合现有散落纪律为一段，gen_tests 系统提示词追加）

```
## 执行环境契约（必须遵守，违反=全部用例作废）
1. 你生成的用例文件将写在项目根目录（不是 test/ 子目录）：__dirname/`.` 即项目根，
   禁止 path.join(__dirname, '..') 等上跳写法。
2. 只允许 import 在「被测源码」中出现过的模块与符号，及 pytest/标准库；
   禁止假设任何未列出的依赖已安装。
3. 状态码与响应 schema 以「API 行为文档」为准；业务字段名以 spec 为准，禁止自拟。
4. 输出预算：最多生成 {MAX} 条用例（超出部分会被丢弃，宁精勿滥）。
5. 整体响应永远是最外层 {"imports":..., "cases":[...]}；template+slots 只是元素内字段。
6. 禁止 @pytest.mark.parametrize / 参数化装饰器（单条用例=单个测试函数）。
7. 禁止 mock 被测模块本身；仅允许 mock 网络文件系统时钟等外部依赖。
```
（{MAX} 由 generate 按条件数动态填；1/6/7 是本轮新增，2-5 为已有纪律整合）

### P2 · 反惯例"正例锚定"（比负面清单有效——writing-for-agents 教训）
对 A9/A11/A12：每个纪律配一个 3 行正确示例 + 3 行错误示例（错误示例标 ❌ 为什么错）。
措辞要求（"不要迁就"）对 LLM 是弱信号；**对照示例是强信号**。

### P3 · 结构化输出（比任何措辞都硬，值得一次实测）
DeepSeek API 若支持 `response_format={"type":"json_object"}`（JSON mode），在所有
JSON 输出调用点开启——A3/A4/A8 三类格式漂移从"容错"升级为"结构保证"。
（待实测：JSON mode 与长输出的兼容性；不行则维持宽容解析现状。）

## 三、Prompt 防不住的四类（诚实清单——这也是论文论点）

1. **物理上限**（输出截断）→ 输入侧降采样，prompt 无用；
2. **模型漂移**（字面量/键名变化）→ 训练层决定，prompt 措辞无法保证 → 确定性容错；
3. **通过压力**（迁就倾向）→ 训练目标（RLHF 让模型讨好）所致，措辞只能减弱 → 结构性闸
   （证人冻结=不可迁就）+ 变异标定照穿；
4. **示例诱惑**（给了占位符仍照抄字面值）→ few-shot 示例对 LLM 的吸引力强于指令——
   确定性注入替换。

**结论句（论文可用）**：提示词工程的作用边界=弥补信息缺口；凡涉及模型能力上限、采样
随机性与训练偏置的失效模式，必须由确定性代码在生成前后拦截。本系统实践支撑该论点
（A7/A3 两案例均为 prompt 失效、闸成功的实锤）。
