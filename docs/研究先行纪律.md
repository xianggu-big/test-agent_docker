# 研究先行纪律（所有 zcode / Agent 任务必须遵守）

> 目的：避免重复造轮子、避免凭记忆编方案。适用于本仓库的所有自动化任务与人工开发。
> 每个任务开工前先读本文件；任务报告必须附“检索记录”，否则该任务视为未完成。

## 1. 什么时候必须检索

满足任一条件：
- 要新建一个模块、服务、表、页面、执行链路；
- 要实现一个你没有十足把握的机制（沙箱、镜像、解析器、SSE、调度、评测）；
- 要引入新依赖、新工具、新框架；
- 连续两次修复失败，或问题原因不确定；
- 用户明确说“调研一下有没有现成方案”。

## 2. 检索范围（至少两类来源）

1. **GitHub**：仓库名、star 数、最近提交时间、license、维护状态、是否可直接嵌入/薄封装；
2. **官方文档 / 论文**：官方 spec、README、arXiv/DOI、会议论文；记录标题与链接；
3. 可选：包管理器/镜像仓库（npm、PyPI、Docker Hub、Maven）看成熟度与许可。

## 3. 记录格式（写进任务报告/commit message）

| 候选 | 链接 | star/版本 | 最近更新 | License | 适配点 | 风险/不采用理由 |
|---|---|---|---|---|---|---|

至少 2 个候选；如果只找到 1 个，要说明检索词与为什么没有第二个。

## 4. 决策规则

1. 优先**复用**成熟方案；其次**薄封装**；最后才自研。
2. 自研必须回答：为什么现成方案不满足？改造成本 vs 自研成本？维护/许可风险？
3. 不允许“凭记忆写 arXiv 编号/DOI/star 数”；写之前必须核验；核验不了就标注“未核验”。
4. 不允许把“搜索不到”当成“没有”；记录检索词与平台。
5. 引入依赖前检查：license、维护活跃度、安全公告、离线可跑性、是否破坏现有锁定版本。

## 5. 任务报告必须附

- 检索关键词与平台；
- 候选表（至少 2 行）；
- 选择结论与理由；
- 未采用方案的风险；
- 若没有网络/无法检索：明确写“检索不可用”，并把任务标 blocked，不得直接自研。
