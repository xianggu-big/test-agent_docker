# 任务卡-G：人机同题对比实验协议（决择单 #13，2026-11-09）

> 用户问题："和人工对比，效率又会提升多快呢？"
> 定位：本卡只交付**协议与材料**——执行需要真人参与者（2~3 名同学），由用户组织；系统侧跑法全自动。
> 结论框架（已定，论文按此表述）："首次生成快一个数量级、回归近零边际、检出率打折、人退到审查位"——三个维度分开说，不合成一个总倍数。

## 1. 实验设计

- **被测对象**：同一模块（data/demo/场景A 或 multi-module-demo 的 utils 模块，≤100 行、含 1 已知缺陷+答案键）；
- **人工臂**：2~3 名同学，各限时 60 分钟，从同一段需求文本出发手写 pytest 单元测试（不给看系统输出；记录耗时/用例数/中途提问次数）；
- **系统臂**：同需求同模块跑一轮标准任务（本地或 DeepSeek 档各一，标注口径）；另加"系统臂+人工 10 分钟审查修改"混合臂（对应"人退到审查位"论点）；
- **四格对比**（每臂产出）：

| 指标 | 人工 | 系统 | 混合 |
|---|---|---|---|
| 耗时（墙钟） | ✓ | ✓（自动） | ✓ |
| 用例数/行覆盖 | ✓ | ✓ | ✓ |
| **变异杀死率**（E4 仪器，mutmut 现成） | ✓ | ✓ | ✓ |
| 检出已知缺陷（答案键） | ✓ | ✓ | ✓ |
| token/人力成本 | 时间×时薪估算 | token 台账 | 两者相加 |

## 2. 诚实边界（预注册，防答辩翻车）

- n=2~3 人的小样本：只写"方向性观察"，不做统计检验；参与者编程水平差异如实记录（问卷 3 题：pytest 熟练度/该项目语言经验/测试经验）；
- 需求文本是系统的主场（明确、结构化）——论文注明"比较前提=按明确需求生成结构化单元测试这一切片"；
- 人的时间没有消失只是转移：混合臂就是为量化"审查成本"而设。

- [ ] 参与者指引（一页：任务/规则/禁则——禁问人禁联网搜索答案可查文档）

- [ ] 结果汇总表模板（四格×指标，均值±离散）+ 论文段落骨架（三个维度分述）
- [ ] 系统臂自动化跑批脚本（同需求一键跑两档模型）
