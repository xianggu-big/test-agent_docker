# 任务卡-D：测试路线注册表 + UI 幂等路线（决择单 #9，2026-11-09）

> 用户想法原话："有没有一种办法让调用的 LLM 拥有几套测试路线……比如测网页某个按钮一直点或突然点两下会不会出现不符合断言的事情，就调用 Playwright 自动化测试"。
> 背景：task 687（纯 HTML 项目）走 static_only → 扫描 0 文件 → 无任何执行出口。本卡补两条：路线声明式注册表（方法论）+ HTML/UI 路线最小闭环（救 687 类项目）。
> 纪律：新能力旗标 **MTA_ROUTER 默认关**（关=现有四级接力行为逐字节不变）；新表动表数契约须同步守卫；回归不降。

## 0. 现有资产（已核实）

- 路线雏形已存在：L1 单元(py) / L2 契约+场景(httptest·TestClient) / L3 / L4 / **UI(ui_assert skill + mta-test:playwright 镜像，含 DOM 可达性树/selector 三形态真值闸/动作 schema 闸)** / DB(db_assert+sidecar) / gRPC / 静态扫描（黑3~白5 任务包已交付）；
- 缺的不是能力，是**注册表+路由器**：谁决定"这个项目走哪条路线"——现在由语言分级 if-else 写死；
- oracle 二维框架（产生观察 × 判据类型）见 docs/黑盒白盒方法组合与沙箱自适应设计.md。

## 1. 路线注册表（routes.py）

```python
ROUTES = {
  "unit_py":      {precond: 语言含python,      toolchain: pytest镜像,      oracle: 断言,  cost: 中},
  "ui_playwright":{precond: 存在.html/.vue/.jsx 或前端框架特征, toolchain: playwright镜像, oracle: DOM断言+状态不变量, cost: 高},
  ...
}
```
- **precondition 必须是确定性代码判定**（文件特征/语言/服务可启动性）——LLM 不得越过前置条件选路线（防幻觉核心）；
- 注册表覆盖现有全部 8 条路线 + 本卡新增 1 条（§2）。

## 2. 新路线：ui_interaction_idempotency（交互幂等）

- **观察**：Playwright 对目标按钮执行 单击 ×1 / 双击 / 快速三连击（间隔 <200ms）；
- **oracle = 状态不变量**（确定性，不依赖 LLM 判定）：提交后列表条目数 == 预期（如 1 条）、后端计数器增量 == 点击数、或 UI 显式错误提示存在；
- 用例来源：LLM 从需求/页面可交互元素提取"提交类按钮 + 期望副作用"清单 → 渲染进 ui_assert 现有动作 schema（**复用其 selector 三形态闸与运行时派生元素放行规则，不新造解析器**）；
- 归因沿用三分类：不变量失败且页面状态异常 = product_defect 证人（防"双击重复提交"这类真缺陷被回炉）。

## 3. 路由器（router）

- 输入：项目特征（analyze 已产出）+ 需求文本；输出：`[{route_id, selected, reason}]`，落新表 `route_plan`（第 33 表：task_id/route_id/selected/reason/priority）；
- **未通过前置条件的路线也记录"被剔除原因"**（可审计，论文素材）；
- MTA_ROUTER=1 时路由器接管分级决策（language=unknown 但有 HTML → ui_playwright 候选）；关闭时走现行 if-else（逐字节不变）。
