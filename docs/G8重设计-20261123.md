## 1. 两败复盘——三个被判死/证伪的假设

| 跑次 | 假设 | 实测 | 定性 |
|---|---|---|---|
| v1（三跑） | 快链占位（js-calc ≈80s）撑得住竞态窗口 | 占位在竞态格出题期间就跑完，worker 空闲秒认领 | 快链不能当占位 |
| v2 | 慢链占位（java-multimodule-slow ≈4min）+ 出题前置 + 三档 1/3/8s | 三档全 miss + **占位格自身同指纹熔断 failed**（项目自带恒定失败，Agent 修不动） | **两病同根：占位格不健康 → 提前终态 → worker 空闲 → 竞态格秒认领**。1/3/8s 档全过仍 miss 说明：只要占位健康窗口在，stop 反而**必然**命中 queued（根本不需要抢——单 worker 串行，竞态格在占位未终态前就是 queued）。"真竞速"（stop 与认领同刻）已被三跑×三档证明**不可稳定制造** |
| 机制面 | — | A4 三道闸有 13 例单测覆盖（queue 行条件更新/认领守卫/run 拒 cancelled） | 真机格的职责是**机制在真库真 worker 下的端到端实证**，不是制造微秒级竞速 |

## 2. v3 设计：双臂，臂 A 为机制主证（不再依赖占位格）

### 臂 A（确定性臂，主证，≈¥0.1）

竞态格两阶段任务：阶段一出题至 `ready_for_review`（有题有据）→ 放行阶段二（入 `exec_queue`，状态 queued）→ **放行后立即 stop（此时任务必然 queued——单 worker 串行，无竞速依赖）**。

预注册判据（全过才 PASS）：
1. stop 返回 200，任务终态 `cancelled`；
2. `exec_queue` 行 `cancelled`（A4 闸①条件更新真机实证）；
3. **零执行证据**：`llm_calls` 0 条新行、无 agent_messages 执行段、无容器创建（docker ps -a 复核）；
4. **不可复活**：对同任务再次放行被拒（幂等；复活=回归 bug）；
5. 停止 5 分钟后终态仍 cancelled（不被任何轮询复活）。

### 臂 B（加强臂，可选，≈¥0.4）

占位格换 **php-api-book 全链**（demo 家族，非 slow 变体、无自带失败前科；备选 java-api-book）。**上岗前健康预检**（学 v2 教训）：先单跑一次全链，`done` 才允许进入竞态编排；预检失败即整臂熔断不硬凑（占位格自证健康再上岗）。

时序：臂 B 竞态格出题前置 → 占位格放行并被认领（exec_queue running 确认）→ 期间放行臂 B 竞态格 → stop@1s。判据：竞态格 cancelled+零执行 且 占位格最终 done（健康对照）。**若臂 A 已 PASS 而臂 B miss，G8 判 PASS**（机制证明以臂 A 为准，臂 B 只是加强）。

### 明确不做

- 不再用 java-multimodule-slow（自带恒定失败两跑实锤）；不再追求"真竞速"窗口（三跑×三档已证死，微秒级竞速归单测覆盖）。
