## 一、L1 依赖闭包扩展（辅助层，默认开）

### 1.1 目标
路由命中模块 A 后，自动把"A 调用的"和"调用 A 的"代码（1-2 跳）加进源码范围
——防"bug 在被调用函数里"的漏测（diff-cover 测试选择的经典做法）。

### 1.2 文件级改动

**改动 1：`test_agent/skills/project_index.py` 新增函数（~60 行）**

```python
def dependency_closure(index: dict, module: str, hops: int = 1,
                       callgraph: dict | None = None) -> list[str]:
    """命中模块的依赖闭包（L1）：返回应并入 scope 的模块名列表。

    callgraph 形态（复用 skills/callgraph.py 的 build_call_edges 输出）：
        {"edges": [(caller_file, callee_file), ...]}
    步骤：
    1) 把 index["modules"][m]["files"] 映射到"文件→模块"反查表；
    2) 找 module 文件在 edges 里的出边（A 调用的）与入边（调用 A 的），
       对端文件所属模块即 1 跳邻居；hops=2 时对邻居再迭代一次；
    3) 返回 [module] + 邻居模块名列表（去重，排除 _root 大杂烩——
       根级散文件不属于任何模块，闭包不收防爆炸）。
    边界：callgraph 为 None（语言不支持/图空）→ 只返回 [module]（降级=主方法行为，
       逐字节不变）。邻居数 >5 时按 (LOC 降序) 取 top5 防提示词爆炸，其余记 skipped。
    """
```

**改动 2：`test_agent/skills/gen_tests.py` 收集循环（在现有 scope_paths 过滤前，~10 行）**

生成侧入口（generate 内调 `_collect_sources_detailed` 处）：若
`state.get("index_scope_paths")` 非空且 `state.get("index_closure")` 非空，
把闭包模块目录也并入 scope_paths（闭包模块的文件照常进源码收集）。

**改动 3：`test_agent/graph/nodes.py` analyze 接线块（命中 module 分支内，~12 行）**

```python
hit = match_requirement(idx_doc, requirement)
if hit["kind"] == "module":
    closure = dependency_closure(idx_doc, hit["module"], hops=1,
                                 callgraph=idx_doc.get("callgraph"))
    state["index_scope_paths"] = [f"{m}/" for m in closure]
    state["index_closure"] = closure
    msg(..., f"[analyze·index] 需求命中模块 {hit['module']}（置信 {hit['confidence']}）"
             f"+依赖闭包 {len(closure)-1} 模块（L1）——源码范围已锁定")
```

**改动 4：`test_agent/skills/project_index.py` build_index 增 callgraph 邻接（~15 行）**

Python 项目：调 `callgraph.build_call_edges`（现有函数，文件级边）；
其他语言：正则粗边（import/require → 同仓文件名匹配），无法建图则不输出
`callgraph` 键（L1 自动降级）。

**改动 5：`test_agent/graph/state.py` 加 1 键（366 教训）**：`index_closure: list[str]`。

### 1.3 验收测试（tests/test_index_l1_closure.py，新建 ~100 行）

| # | 用例 | 判据（红→绿） |

## 二、L2 覆盖率闭环兜底（急救层，每路由格自动校验）

### 2.1 目标
路由格跑完后校验"需求条件在锁定模块里有没有覆盖"——零覆盖=标签漏了（路由到
错模块或需求条件实际落在闭包外），自动扩圈重跑一次；仍零覆盖=放弃路由回退
全库（急救失败的诚实出口，CODAMOSA 思想）。

### 2.2 文件级改动

**改动 1：`test_agent/skills/project_index.py` 新增（~50 行）**

```python
def coverage_check(state: dict, per_file: list[dict]) -> dict:
    """L2 校验（跑后钩子）：需求条件的覆盖是否落在锁定范围内。

    输入：state（含 index_scope_paths/index_closure/requirement）、
          per_file（evaluate 产出的逐文件覆盖行，字段 file/miss/cover）。
    判定：
    - scope 内文件存在且 cover>0 → {"verdict": "ok"}（标签正确，结束）；
    - scope 内全部 cover=0 或文件缺失 → {"verdict": "zero_coverage"}（标签漏了）；
    - state 无 index_scope_paths（非路由格）→ {"verdict": "not_routed"}（跳过）。
    """
```

**改动 2：`test_agent/graph/nodes.py` evaluate 节点（verdict 判定后、INSERT
evaluation_rounds 前，~35 行）**

```python
# L2 覆盖率闭环兜底（2026-11-18 设计方案）：仅路由格触发
if state.get("index_scope_paths") and config.INDEX_L2_RESCUE_ENABLED:
    chk = coverage_check(state, per_file_rows)
    if chk["verdict"] == "zero_coverage" and not state.get("_l2_rescued"):
        msg(..., "[index·L2] 锁定模块零覆盖——标签可能漏了，扩圈重跑一次（急救）")
        # 扩圈：闭包 hops 1→2；无闭包则全库（scope_paths=None）
        state["_l2_rescued"] = True
        state["index_scope_paths"] = expand_scope(...)   # 或置 None 回退全库
        return {"verdict": "repair_gen",
                "stop_reason": "L2 急救：扩圈重跑（零覆盖自愈）"}
    if chk["verdict"] == "zero_coverage" and state.get("_l2_rescued"):
        msg(..., "[index·L2] 扩圈后仍零覆盖——放弃路由回退全库（急救失败诚实出口）")
        state["index_scope_paths"] = None
        return {"verdict": "repair_gen", "stop_reason": "L2 急救失败：回退全库重跑"}
```

**改动 3：`test_agent/config.py` 旗标**：`INDEX_L2_RESCUE_ENABLED = _flag("MTA_INDEX_L2_RESCUE", True)`——默认开（跑后校验零成本，重跑才有 LLM 成本且被
repair_gen 轮次预算天然约束：一轮急救 = 一次 repair_gen 轮）。

### 2.3 验收测试（tests/test_index_l2_rescue.py，新建 ~90 行）

| # | 用例 | 判据 |
|---|---|---|
| L2-1 | 路由格 + scope 内 cover>0 | verdict="ok"，不触发重跑 |
| L2-2 | 路由格 + scope 内全 0 cover | verdict="zero_coverage"→触发急救（扩圈/回退） |
| L2-3 | 非路由格（无 scope_paths） | verdict="not_routed"，零行为变化（旗标关=主方法不变） |
| L2-4 | 急救一次后再零覆盖 | 第二次=放弃路由回退全库（_l2_rescued 防死循环） |
| L2-5 | 旗标关 | L2 整段不执行（逐字节不变锁） |
| L2-6 | 集成：假 evaluate 返回 | 消息留痕含 "[index·L2]"（tmp 库驱动） |
| L2-7 | 成本护栏 | 急救至多触发一次（evaluation_rounds 轮数不超 MAX_REPAIR_ROUNDS） |

## 三、L3 失败语料自学习（长期层，人工审后进表）

### 3.1 目标
真实失败聚类（trapkb_v2 已有）top 簇 → 候选别名条目 → **人工审核落表**——
词表从失败里长出来，但禁止自动写入（防脏词污染路由）。

### 3.2 文件级改动

**改动 1：`scripts/suggest_aliases.py` 新建（~70 行，纯脚本零 LLM）**

```
读 data/reports/e10/trapkb_v2.json 的 top 簇 → 对每簇：
  a) 从簇内 sample_proj/sample_tasks 反查 test_tasks → 项目的 module 列表；
  b) 从簇内 top_messages 提取名词候选（正则：函数名/路径段）；
  c) 产出候选表 data/reports/e10/alias_suggestions.json：
     [{cluster_signature, size, suggested_alias, suggested_module, evidence_n}]
人工流程：打开 JSON → 每条标 accept/reject → accept 条目由人手动补进
  project_index._ALIAS_GROUPS（一行一词，代码评审可见——不搞运行时写表）。
```

**改动 2：`tests/test_project_index.py` 补 1 例**：别名表快照锁——
`_ALIAS_GROUPS` 的键数与词数落快照文件，改表必须同步快照（防无审漂移）。

### 3.3 验收测试

## 四、端到端真机验收（三层合验，共 3 格 ≈¥1）

| # | 项目 | 需求 | 验什么 | 通过判据 |
|---|---|---|---|---|
| E2E-1 | go-rest-api-master | "测所有 REST 接口" | 主方法+接口对账 | 消息含"[analyze·index] 接口清单"且 count≥6；用例数≥端点数或有缺口说明 |
| E2E-2 | js-calc（有依赖小项目） | "测试计算边界" | L1 闭包 | 消息含"依赖闭包 N 模块"；scope 外文件在跳过台账 |
| E2E-3 | 构造格：需求说"测支付"但项目无 pay 模块 | L2 急救 | 路由 none→全库；或误命中后零覆盖→扩圈/回退消息留痕 | 有 "[index·L2]" 或回退消息且终态合法 |

**总判据（预注册）**：三层各自的"失败诚实出口"全部走通=机制达标；
任何一层把任务引向更差结果（错误锁定导致熔断）=不达标，回设计。

全程旗标两态留测（L2 旗标默认开但关态逐字节不变锁必留）；报告落
