## 3. 各问题多思路对比与选择

### P1 三闸生产接线
- 思路 1：改代码默认 True —— 违反 526 基线保护纪律，弃。
- 思路 2：**环境变量旗标**（MTA_ENV_GATE/MTA_DIFF_GATE/MTA_FLAKY_RERUNS）——SWE-bench
  harness 同思路（开关经环境进评估环境）；代码默认不变，生产/实验一键开。**采纳**。

### P2 双败格细分
- 思路 1：LLM 日志分类（ReportPortal 的 AI 层）——引入不确定性，与「证据必须确定性」
  纪律冲突，弃（列未来工作）。
- 思路 2：**确定性证据收窄**=金丝雀复跑（环境健康？）+ bug/对照两版 stderr 错误特征表
  （ECONNREFUSED 系→环境特征；Cannot find module/ImportError 系→用例特征）。零 LLM，
  只收窄证据不改标签。**采纳**（task_366 stderr 诊断段的归因侧复用）。

### P3 .git 进容器
- 思路 1：容器内 clone（SWE-bench 正牌做法）——A 轨正式路径，随 fetch_baseline 接线做。
- 思路 2：**copy_dir_into 加 keep_git 参数**（差分场景显式带 .git，默认仍剥=Task B 语义
  不变；git 只读 ref 操作）——最小 diff，**本轮采纳**。
- 思路 3：宿主切 git+重拷双通道——多一次拷贝且时序复杂，弃。
- 注：思路 2 只救「宿主工作区有 .git」的 clone 类任务；本地目录快照类任务仍无解（真机
  验证报告已声明），彻底解=思路 1。

### P4 A 轨拉取协议（本轮实测拍板）
- 实测：`git clone`（github.com）**blocked**——URL 级代理 127.0.0.1:7890 未开、直连
  reset（历史坑复现）；`codeload.github.com` tarball 通道 **HTTP 200 可用**（api.github.com
  同通）。
- **拍板协议**：A 轨走 codeload tarball 双版本（buggy/fixed 两 commit 各一包）+
  **测试文件取 fixed 版**（SWT-bench fail-to-pass 口径——实测发现 BugsInPy bug 的
  失败用例常随 fix 提交新增，buggy 快照里不存在，必须把 fixed 测试文件套在 buggy
  源码上跑才构成 fail-to-pass 对；BugsInPy framework 的 bugsinpy-checkout 同此语义）。

## 4. 本轮实施记录

### Track A：三闸生产接线（P1）+ 缺口②最小修复（P3）
- `config.py`：`_flag()` 环境变量旗标 helper；ENV_GATE_ENABLED/DIFF_GATE_ENABLED/
  FLAKY_RERUNS 改由 MTA_* 环境变量求值（默认 False/0 逐字节不变）。
- `sandbox/runner.py`：`copy_dir_into(..., keep_git=False)`——keep_git=True 时排除集合
  去掉 .git；`nodes.py` provision 接线：`keep_git=config.DIFF_GATE_ENABLED`（旗标开=
  差分场景=.git 随行进考场；后续 gen_tests 回灌 tar 合并不删已有 .git）。
- 单测：`test_config_gate_flag_defaults_off_and_env_override` /
  `test_config_gate_flags_reload_from_env` / `test_snapshot_plan_keep_git_includes_dotgit`。

### Track B：双败格细分（P2）
- `attribution.py`：`_ENV_FAIL_HINTS`/`_CASE_FAIL_HINTS` 特征表 + `_double_fail_evidence()`
  （金丝雀复跑+两版 stderr 扫描，零 LLM）；`run_diff_gate(..., bug_stderr="")` 双败时
  detail 附证据（金丝雀通过/未通过 + 环境或用例特征错）；标签不变仍 case_defect。
- `nodes.py`：evaluate 差分闸调用传 `bug_stderr=state["last_stderr"]`。
- 单测：`test_run_diff_gate_double_fail_env_evidence_split` /
  `test_run_diff_gate_double_fail_case_evidence_split`；旧测试路由补金丝雀。

### Track C：A 轨真值拉取实测（P4，真网络完成 1 例）
- 通道实测：git clone blocked / codeload OK（证据见 §P4）。
- **真拉 BugsInPy tqdm bug 9**（format_sizeof 边界舍入缺陷，999.95 vs 1000——与本项目
  边界值分析方法同题）：framework 真值库 470KB + 双 commit tarball（各 ~75KB）落
  data/benchmarks/repos/（已 gitignore，不 vendor）。
- manifest 入库：`data/benchmarks/manifests/py-tqdm-bug9.json`（A 轨，双 ref 校验 OK）。
- **fail-to-pass 真实验证**：buggy 源码 + fixed 测试文件 → `test_si_format` FAIL
  （`assert '10.0K ' in format_meter(1, 9999, ...)` 实败，10.00K 错误舍入暴露）；
  fixed 版 `scripts/env_checkup.py --exec` → **体检卡 status=ok**（build_ok+tests_ok，
  10.5s，卡落 repos/tqdm-bug9-healthcard.json）。
- 宿主卫生：体检装的是 buggy/fixed 旧 tqdm（1.0），已恢复 host tqdm 4.70.1。

## 5. 对「准确性保证」结论的更新

| 原缺口 | 本轮后状态 |
|---|---|
| 三闸默认关、生产没接线 | ✅ 环境变量一键开（MTA_*），代码默认仍保护基线 |
| 双败格不可分 | ✅ 缓解：金丝雀+stderr 特征收窄证据（标签仍保守） |
| .git 进容器未拍板 | ✅ 拍板：本轮 keep_git（clone 类任务）+ A 轨正式路径=容器内 clone/codeload 双版本 |
| A 轨拉取未实测 | ✅ 1 例真拉+真值 fail-to-pass 验证+体检卡全绿；规模扩展（5-10 bug/语言）待充值后批量 |

**仍然没有保证的（诚实边界不变）**：归因精确率 ≥80% 的统计验证、B 轨真实项目外部效度、
oracle 本质限制（断言反演只能靠差分闸检测+人工裁决）。

## 6. 未采用方案的风险备忘

- ReportPortal LLM 分类层不引入：归因统计粒度依赖确定性证据，LLM 层等 A 轨统计样本
  建立后再评估（否则准确率测量本身被 LLM 噪声污染）。
- NonDex/idoft：Java 工具链不适用，但 idoft 的 Python flaky 用例清单可作未来 flaky 闸
  的外部语料（引用前需核验许可）。
- SWE-bench 全套 harness 不引入：仅采纳「git 随行进容器」思路；其 conda-per-repo 镜像
  体系与本平台 recipe 池重叠，引入即双轨维护。
