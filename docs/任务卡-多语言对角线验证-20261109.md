# 任务卡-F：多语言对角线验证（决择单 #11，2026-11-09）

> 用户判断："不止 Go 有缺口，其它语言我都还没测过。"——单语言验证 = 架构未被证伪。
> **收缩口径（已拍板）**：不追 6 语言全矩阵，**每语言打通一条端到端主路线**（对角线），治理结论跨语言复现是论文叙事（"语言是变量，治理是不变量"）。全矩阵=未来工作。
> 背景资产：docs/oss-testing-pipeline-comparison.md（9 开源项目×8 维度，P4 范式定位已立）；各语言链路已交付（黑3~白5 任务包+Go 工具链修复），但"链路在"≠"真实项目可演示"（687 是活例）。

## 1. 对角线定义（每语言一条主路线）

| 语言 | 主路线 | 理由 | 现状 |
|---|---|---|---|
| Python | 单元 + PBT | 最成熟，PBT 已实现 | ✅ 基线在 |
| JavaScript/TS | 单元（jest） | js-calc/tomli 真机已过 | ✅ 大体在 |
| Go | 单元（go test）+ 缺口回灌接线 | go126 镜像刚修完（680/681 双臂 PASS） | ⚠️ 单元在，回灌未接（AGENTS 缺口⑥） |
| Java | 单元（junit）+ 变异标定 | PIT 是工业标杆，能出"有效性"数据 | ⚠️ smoke 7/7，变异未接 |
| PHP | 单元（PHPUnit） | smoke_php 7/7 | ✅ 大体在 |
| HTML/静态 | **UI 交互幂等**（任务卡-D） | 687 类项目唯一出路 | ❌ 待 D 卡交付 |

## 2. 执行内容（以验证为主，开发仅限回灌接线一处）

1. **每语言一个真实 mini 项目**（data/demo/ 或真实仓库本地路径，≤500 行，含 1~2 个已知缺陷+答案键）——禁止用生成物当被测对象；
2. 每语言跑完整四级流程中的**主路线 leg**（L1 或对应路线），产出标准报告（通过率/覆盖率/缺陷归因/证人）；
3. **治理一致性核对表**（本卡核心产出）：每语言逐项核对 ✓/✗——expected_basis 落库？归因三分类工作？证人冻结生效？审计台账完整？报告双闸通过？——**这张表就是论文"治理不变量"的证据**；
4. Go 缺口回灌接线（唯一开发项，AGENTS 缺口⑥最高性价比）：coverprofile 解析 → term-missing 等价物 → generate 提示词注入，复用 Python 侧既有 V4 机制结构；旗标默认关；
5. 能力矩阵副产品：对角线跑完自然产出 `语言 × 黑盒法/白盒法` 现状表（四态：已通/半通/缺/不适用），落 docs/（这就是当初版本-A 矩阵的免费形态）。

## 3. 验收清单

- [ ] 6 语言各有 1 个真实项目端到端跑通主路线，报告可演示；
- [ ] 治理一致性核对表 6×5 全落档（含 ✗ 项的诚实原因）；
- [ ] Go 缺口回灌：真机一格验证"关→开"检出差异（n=1 方向性即可，诚实标注）；
- [ ] 能力矩阵表落 docs/；AGENTS.md Go 缺口清单更新（⑥闭环）；
- [ ] 回归不降；旗标纪律全程（回灌默认关）。

## 4. 边界（不做）

各语言第 2/3 条路线、变异/模糊对全语言铺开（Java 变异、Go fuzz 仅在主路线内自然出现才做）、swag/ godoc 提取（缺口①⑦，列矩阵"缺"格）、性能压测。

## 5. 坑预判

- demo 项目选择贪大 → 时间失控（≤500 行铁律）；
- "链路在"的幻觉：先跑 preflight/冒烟确认镜像与工具链，再排正式跑（687 教训）；
- 治理核对表别让 LLM 自评——逐项用 SQL/台账实查（空洞通过的教训 415）。
