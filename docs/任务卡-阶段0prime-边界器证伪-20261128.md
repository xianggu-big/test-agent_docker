# 任务卡：阶段 0'——确定性边界器证伪实验（预注册，2026-11-28）

> **真源**：docs/设计方案-AgentLoop重设计-专家式策略与诊断-20261127.md §13（设计修订）。
> **要证伪的命题**：把"命中靶点"从"模型碰巧"变成"机制保证"——确定性边界器（零 LLM）从需求与签名解析数值区间，生成端点/越界用例，能否把留出项目的检出从 1/5（阶段 0 B 臂）提到预注册线以上。
> **纪律**：判据与抽取规则在跑评测前冻结；边界器**只准读 REQUIREMENT.md 与函数签名，禁止读任何 ground_truth.json**（防泄漏测试锁定）；评测=宿主侧反事实重放（run_g_scoring，零 LLM、零 API），高峰段可执行。

## 1. 边界器 v0 的范围（诚实声明）

- 只覆盖"需求/签名里写了数值或枚举约束"的缺陷类。三种通用规则：
  ①签名数值默认参 → 端点/越界（lib 型）；②需求文本"X~Y / [X, Y] / X 到 Y"区间 → 端点用例（REST/lib 通用）；③"X 折/比例"计价 → 阈值用例（REST 型）。
- 每类项目一个执行模板（lib=直接调函数；REST=fastapi TestClient+建资源前置）。模板是实验脚手架，不是产品；主张只落在"区间→端点用例"这一步是确定性的。
- 不覆盖：纯语义缺陷（如 corpus-003 D3/D5 类）、无数值约束的缺陷。

## 2. 格子与判据（跑评测前冻结）

| 项目 | 评测 | 预注册判据 |
|---|---|---|
| corpus-001（留出，3 个真缺陷=同一根因的三处表现，2 decoy） | 反事实重放 | **detection_rate ≥ 2/3 且 D1（check_length 根因）必检出** |
| corpus-003（5 真缺陷+2 decoy） | 反事实重放 | **≥ 2/5**（D1 时长端点与 D4 相邻时段为设计靶点；D2 计价阈值为加分项不计入判据） |
| coupon-api（干净项目） | 边界用例全量直跑 | **0 条失败**（任何一条失败=误报，判不过） |

- **总判读**：三条全过=机制证成（"区间→端点用例→必踩"成立），进假设单最小件与平台集成实验（0''，低价窗）；任一不过=回设计桌。
- **对照基线**（引用阶段 0 数据，不重跑）：A 臂泛需求在 corpus-001 检出 1/4、B 臂大纲 1/5——边界器若 ≥2/3 即显著超过两条 LLM 臂。

## 3. 防泄漏与验收

- 泄漏守卫：extractor 源码与单测不得出现 ground_truth 字样（测试锁定）。
- 抽取器单测先红后绿（区间正则/签名默认参/用例渲染三组）。
- 评测用 run_g_scoring --corpus corpus-001 既有修法（根因唯一补丁），不新写评分逻辑。

## 4. 执行清单

1. 写卡（本文）→ 提交冻结。
2. 边界器 v0 + 单测（红→绿）。
3. 生成三项目边界套件 → 反事实重放评测（零 API）→ 判读。
4. 过 → 准备 0'' 平台集成实验（边界用例经 cases API 注入，泛需求对照，低价窗跑）；不过 → 回设计桌。
