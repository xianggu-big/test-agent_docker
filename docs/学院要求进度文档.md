### 1.2 三方向组合规则

- 主方向必须达到该方向的独立标准。
- 另外两个方向达到辅助最低要求。
- 三个方向必须端到端集成，不能是三个独立 Demo 的简单拼接。
- 三组合完成效果：**用户 → 应用 → 智能体 → Skill → 数据库 → 返回完整链路**。

### 1.3 本项目定位

- **主方向：Test Agent 智能体开发。**
- **辅助方向一：AI 应用。** 提供完整管理端、交互端、任务流程和报告返回。
- **辅助方向二：Skill 开发。** 为智能体提供可注册、可授权、可审计、可测试的能力。

### 3.3 已发现但尚未补齐的结构性问题

1. **缺少统一 `run_id`**
   - 同一任务重跑后，评估轮次等数据会覆盖。
   - 会话、工具调用、LLM 调用和报告无法可靠组成多次运行账本。
   - 影响任务完成率、响应时间和多次实验对比。

2. **Agent 轨迹 API 尚未形成专用前端**
   - `GET /api/tasks/{tid}/agent-loop` 已存在，但返回任务级汇总。
   - 当前前端没有消费该接口形成决策时间线。
   - 证据：`test_agent/api/server.py:802-827`。

3. **`agent_prompt_version` 未声明在 TaskState**
   - 存在被 LangGraph Schema 过滤的风险。
   - 影响提示词版本、模型版本和实验可比性。
   - 证据：`test_agent/graph/agent_nodes.py:66-75`、`test_agent/graph/state.py:64-77`。

4. **四项主指标没有形成统一指标契约**
   - 任务完成率：缺失。
   - 工具调用成功率：有公式，但为任务级。
   - 幻觉率：缺失。
   - 响应时间：报告字段目前未使用。

## 7. 待补充任务清单

### P0：主方向达标必需

#### P0-1 制定指标口径文档

需要明确：

- 任务完成率的成功定义、有效运行分母、环境失败处理。
- 工作流完成率与任务完成率的区别。
- 工具调用成功率的分子、分母和状态分类。
- 幻觉率的事实性 claim 类型、证据标准、分母和复核方法。
- 排队耗时、执行耗时、总响应耗时的起止点。

验收：每个指标都有公式、示例、数据来源和异常边界说明。

#### P0-2 建立运行级账本

建议新增：

- `agent_runs`：一次智能体运行的目标、起止时间、停止原因、完成判定和汇总指标。
- `agent_steps`：每次观察、决策、Skill 调用、拒绝、Finish 和停止的步骤级证据。

验收：同一任务连续运行两次，形成两个独立 `run_id`，数据不覆盖、可分别回放。

#### P0-3 接入指标采集

采集点：

- `builder.run_task`：运行开始、会话创建、配置快照。
- `tool_loop.run_tool_loop`：每次决策、调用、拒绝、预算和停止。
- `report`：运行结束、终态、报告和总耗时。

同时补齐 `TaskState.agent_prompt_version`，持久化模型、提示词和关键配置版本。

验收：四项指标可由数据库确定性重算，不依赖模型自报。

#### P0-4 补自动化测试

至少覆盖：

- 同一任务多次运行的 `run_id` 隔离。
- 重跑不覆盖历史运行。
- 完成率公式及环境失败边界。
- 工具成功率包含 `failed / timeout / denied`。
- 幻觉标注与证据引用完整性。
- 响应时间起止点和零分母处理。
- Agent 轨迹 API 不跨运行串账。

### P1：管理与演示必需

#### P1-1 增加 Agent 运行中心

页面内容：

- 运行列表：目标、模型、状态、步数、四项指标、停止原因。
- 决策时间线：目标→观察→策略→Skill 调用→结果→诊断/重试→Finish→报告。
- 步骤详情：输入、输出摘要、证据、拒绝原因、token、耗时。
- 多次运行切换与对比。

验收：不查数据库也能现场讲清一次 Agent 运行过程。

#### P1-2 固化黄金演示脚本

建议选择已有 `js-calc` 或 `go-rest` 场景，展示：

1. caller 创建任务。
2. developer 确认并下发。
3. Agent 读取证据并规划。
4. Agent 调用 Skill。
5. Docker 真执行。
6. 捕获预期缺陷。
7. 数据落库并返回报告。
8. Agent 运行中心展示四项指标。
9. 负例展示越权或错误参数被拒绝并留痕。

验收：完整链路可现场重复，关键结果可由数据库和 artifacts 复核。

#### P1-3 整理代表 Skill 契约样例

选择一个原创 Skill，输出：

- 名称与功能。
- 输入 Schema。
- 输出结构。
- 权限与风险等级。
- 超时、异常和降级。
- 正常、异常、权限、边界四类测试。
- 一次真实调用日志。

### P2：证据整理与论文材料

- 优先复用已有 24 格 Agent Loop 实验和已有基准结果做指标回算。
- 历史数据缺少 `run_id` 的部分应如实标注，不能伪造补齐。
- 若现有数据不足以计算幻觉率，再另行申请小样标注，不自动启动大规模实验。
- 输出主方向指标表：n、mean±std、P50/P95、失败分类和证据路径。
