## 调研收敛（2024-2025 文献+开源实践）

1. **grounding 是主流解法**：LLM 生成测试的弱预言问题，2024-2025 的缓解主策略=把生成锚定在
   API 文档/规范/领域知识上——RAG、微调、意图提取（"Domain Knowledge is All You Need"金融域
   实证 380845052；"Test Intention Guided"意图驱动 oracle；程序无关生成工具用"库/设计文档/
   配置文件"而非仅源码做 grounding）。TU Delft 实证：**software context 直接影响 oracle 质量**。
2. **测试运行器反馈的迭代生成**（Self-Refining）：与本课题 R-Loop 回灌同思想，文献证实显著
   改进——本项目的方向被文献背书。
3. **"语言陷阱清单"无直接文献**（学术词=test smells/anti-patterns/flaky）——**curated 清单
   本身是空白点**，做出来即有新颖性（组合创新：清单×错误推测法×消融验证）。
4. 开源实践映射：Keploy=流量录制作真实行为锚点（与本方案 A 源同思想）；Diffblue Cover=内置
   领域启发式（B 源同思想）；SymPrompt=repo 内符号上下文（C 源同思想）。

## 三源注入方案（按据可依程度排序）

| 源 | 内容 | 依据 | 实现路径 |
|---|---|---|---|
| **A·repo 内校准** | 自带 tests 中**通过的用例**作为 few-shot 行为锚点注入 gen_tests（"你的预期应与这些已验证行为一致"） | 192 条自带测试全过=现成金矿；Keploy/SymPrompt 同思想；context→oracle 质量文献 | gen_tests 提示词注入段（workspace tests/ 目录的通过用例摘录，确定性提取） |
| **B·语言×类型陷阱库** | curated 清单：Python（浮点比较/可变默认参数/编码/弱引用时序）Web（并发幂等/时区/缓存穿透）CLI（信号/退出码）……按 analyze 出的语言/类型分级注入错误推测法 | 空白点=新颖性；对应资深测试人员经验（用户命题） | prompt_library 新 ERROR_GUESS_KB 段+消融格 X9 |
| **C·API 文档 grounding** | 目标函数 docstring/README 段落注入（analyze 已抽 AST，docstring 同源可得） | grounding 文献主流；tenacity stop_after_attempt docstring 大概率写了调用语义 | prompt 段（docstring 摘录） |

**与已有机制的关系**：A 源解决"预言无依据"（①类失败的直接解法——LLM 预期将与 192 条已验证
行为对齐）；B 源解决"不知道测什么"（资深经验的广度）；C 源解决"行为语义猜错"（g2 类）。三者
正交可叠加，各自带消融格（X-A/X9/X-C）。
