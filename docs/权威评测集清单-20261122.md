## 2. 论文中的三段结构（外部效度标准写法）

1. **主实验=自建语料**（corpus-003 三方盲测：出题人-答题人-阅卷人隔离+植入缺陷附答案键）——方法论贡献：真值可控+防自证；
2. **外部效度锚点=权威集复现**："为验证结论不依赖自建语料，以 BugsInPy（ESEC/FSE 2020）真实缺陷 13 例复现核心检出结论"——本地 13 manifest 即此用途；
3. **口径引用**：fail-to-pass 判定引 SWT-bench/BugsInPy；n≥3 复跑引 non-determinism 论文。

**答辩防线**（预判"为什么不全用权威基准"）：权威集的 bug 难度/分布不可控（本实验已实证天花板效应——r1 检出率 0.95 时 KB 增益不可测）；自建语料真值可控可对账（planted 级）。**互补不可替代**——SWT-bench 论文自身也构建了专用真值集，先例成立。

## 3. 诚实边界（引用时必写）

1. **HumanEvalFix 语义转换**：其本职是"修 bug"（gold patch=修复代码）不是"写测试"——用它做测试生成真值=把 gold patch 引入的**行为差异**定义为"应被抓出的行为差异"，需一层显式转换声明，不得表述为"测试生成基准"。
2. **SWT-bench 是 repo 级重环境**：完整 harness 依赖真实仓库构建——引用其**口径与发现**，不直接跑其数据（单格成本与任务形态均与本项目不符）。
3. **BugsInPy 13 例≠全集**：393 bugs 中选 13（跨 5 项目）——样本选择标准（manifest 预备时的 bug 难度/可复现性筛选）要在论文写明。

## 4. KB 收敛难锚点推荐路径

1. **Pilot（¥1-2）**：本地 13 manifest（BugsInPy python）——管线零改造，验证"难锚点+planted 级对账"判据流程；
2. **主力（零 API 转换 ≈1 天）**：HumanEvalFix 每语言 15-20 函数→转平台任务格式（gold patch diff→planted 清单→逐缺陷对账）——六语言独立 KB 收敛直接对齐 Wave2 设计；
3. **真值对账**：续接 corpus_truth grade 管线（命中 planted 数而非笼统 detected）。
