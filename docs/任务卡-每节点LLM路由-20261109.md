## 1. 设计（定稿，不重开讨论）

1. **app_settings 的 llm_profile 值升级**为：
   ```json
   {"default": "deepseek", "profiles": {"deepseek": {...}, "local": {...}, "qwen": {...}},
    "routing": {"generate": "local", "review_report": "deepseek"}}
   ```
   - 读到**旧格式**（单 profile 对象）→ 自动迁移为 `{default: 旧值, profiles: {}, routing: {}}` 并写回（幂等）；
2. **路由解析**：`make_chat(phase=X)` → routing[X] 命中则用 profiles[该值]，否则 default；显式传 model/api_key/base_url 仍最高优先（逃生口，ai_reviewer 的 per-role 模型因此零改动）；
3. **phase 枚举**：从代码 grep `make_chat(` / `phase=` 实测提取（已知含 plan/generate/gen_feedback/gen_tests/repair/report/review_report/static_draft/defect_analysis/understand/log_analyze/ui_assert/grpc_assert/l2/l3/l4 等），**禁凭记忆列**；未列出的 phase 回退 default；
4. **ctx_budget 字段**（衔接任务卡-H）：profile 增可选 `ctx_budget`（local=16384，云端省略=不限），路由解析后一并生效；
5. **备胎互斥升级**：目标 profile 为 local 时备胎跳过（现有逻辑按 config 判断，改为按路由后的实际端点判断）。

## 2. API 与前端

- `GET /api/llm-routing`（staff）：{profiles, routing, phases:[{phase, calls_7d, current_model}]}——calls_7d 从 llm_calls 聚合（确定性 SQL），无数据标"—"；
- `PUT /api/llm-routing`（**admin**）：body={phase: profile_id|null}（null=回退 default）；逐项校验 profile_id 存在；
- 设置页新增"节点→模型"表格卡：每行 phase + 下拉（default/各 profile）+ 近 7 天调用量徽章 + 保存即生效；混合模型任务的报告页/详情页加"模型构成"徽章行（llm_calls 按 phase 聚合，确定性代码算，禁 LLM 编）。

## 3. 诚实纪律

3. 切换留痕沿用 app_settings.updated_by/at；不做切换历史页（边界）。
