# bench3 三方权威基准实验报告（2026-11-22）

> 状态：71 格全部终态（第四轮 5 格收官 + wrap 单格补跑并入）。原始留档：`data/reports/bench3/bench3_results.json`（合并写索引）+ `run_bench3.py`（判据预注册载体）+ `summarize_bench3.py`（三表聚合器）+ TEMP tmp 库（每格完整台账）。

## 1. 背景与动机（为什么做这个实验）

平台此前所有检出证据（js-calc clamp 闭区间、go DELETE 幂等、corpus-003 自埋缺陷）本质都是**自己出题自己考**：缺陷要么是项目自埋（corpus-003），要么是已知答案的真库缺陷（六语言对照）。答辩/审稿最大软肋："缺陷是不是你自己埋的？你是不是知道答案才测出来的？"

用户 2026-11-22 拍板"拿三个最值得的基准进行测试"——目标：**把检出能力的主张从自证升级为他证**（第三方公开基准、第三方造的 bug、文献同源判据）。

## 2. 基准三选（难度阶梯设计）

| 基准 | 出处 | 缺陷形态 | 难度/真实度 | 格数 |
|---|---|---|---|---|
| HumanEvalFix | BigCode'23 | 注入的单行逻辑 bug，小函数 | 浅（单元考试） | 30（python） |
| QuixBugs | Lin et al. 2017 | 经典算法单行 bug | 中（数学规格明确） | 40 |
| BugsInPy | ESEC/FSE'20 | 真仓库真历史 bug | 深（真仓库场景） | 1（tqdm bug9，pilot） |

三选逻辑：**沿"注入→经典→真实"画能力包络**——即使深层 miss，衰减曲线本身也是论文素材（适用范围一节）。

## 3. 判据（预注册——跑之前写进驱动器，非事后诸葛）

- **P0 答案键预检**（零 LLM）：official（HEF 官方 check 脚本 buggy 必败 fixed 必过）/ behavioral-diff（tqdm 999.95 边界差分）/ diff-structural（QuixBugs 官方单行修复 diff 存在）。预检不过的格不进真格。
- **P1 平台真格**：完整平台链路（analyze→plan→generate→provision 拉容器→容器内执行→evaluate→report），每格独立 tmp 库+工作区。
- **P2 复演**（容器内，与真格同镜像 mta-test:py312）：生成用例拷进 fixed 版复跑，junitxml 逐用例解析。
- **逐用例转移矩阵**：fp（buggy 败+fixed 过=真检出）/ ff（两头都败=坏断言）/ pf（buggy 过+fixed 败=迁就 buggy 行为）。
- **四级判级**：detected（fp≥1）/ scaffold_broken（有失败但复演没跑起来）/ not_detected（复演真执行但零命中）/ no_tests。**driver_error 不进分母**（基础设施错不算 agent 的账，且自动重试）。
- **C1 放量闸**：pilot 5 格 detected≥2 且破碎≤1 才放量；异常格>8 停车。
- **不拍及格线**：只报三阶梯实测值+梯度+坏用例率（预注册决定）。

## 4. 执行史（四轮，两起驱动器事故全部取证修复）

### 第一轮（pilot 5 格）
HEF Python_0/1/2/3 四格 detected + tqdm scaffold_broken。**口径升级现场**：整文件 exit 口径把 2 格真检出（22 条 fail-to-pass 证据）误判——升级为逐用例转移矩阵后反转。

### 第二轮（线程并发 21 格 → 停车闸触发）
放量后 8 格 driver_error。**事故一（DB 线程踩踏）**：6 线程共享全局 `config.DB_PATH` 互相覆盖 → `database is locked` ×4 + `UNIQUE users.username` ×3。修法：worker 子进程隔离（E9 同款，进程内 config 改写出不了进程）。
顺带修三处：driver_error 误判终态 no_tests（永不重试）/ 402 归 driver_error / 结果合并写（防索引覆盖事故复发）。

### 第三轮（worker 子进程 60 格 → 又停车）
**事故二（跨容器串账，新坑）**：容器名 `mta-run-{task_id}` 全格共享（tmp 库自增都=1）→ 并发下 B 的 `ensure_container(fresh=True)` 删掉 A 正在用的容器 → A `containers.get("mta-run-1")` 拿到 B 的容器、在 B 工作区执行、把 B 的用例结果记进 A 的账。**取证**：Python_13（gcd 格）账里全是 string_sequence 用例；16/17 账里同一份 substring 用例；18 账里是 19 的 sort_numbers。修法：每格唯一 9 位随机 task_id（驱动器侧，平台零改动）。
**审计假阳性教训**：Python_4 被误判串账——LLM 把 mean_absolute_division 缩写为 `test_mad_*`，字面 token 匹配抓空。"审计器先自证口径"第 N 次。
修复后重跑：断点正确跳过 11 格干净真账，60 格完成，重试平反批量兑现（Python_13 串账冤案→detected fp=9）。

### 第四轮（6 死循环格，90s 轮超时——5 格终态+wrap 补跑）
**发现一：死循环陷阱的时钟经济学**。单轮执行超时默认 600s，挂死用例每轮烧满 → repair 再生成再挂 → 烧穿 worker 1200s 封顶 = 整格 driver_error（检出信号丢失）。修法：`BENCH3_ROUND_TIMEOUT_S=90`（90s 对非挂用例 50 倍余量）+ replay 超时不再炸 worker。
**发现二：wrap 死循环取证（类③）**。官方修复 diff 只是循环后补 `lines.append(text)`（丢尾行缺陷），**循环体两版一致**，共有非终止边界（余文以空格开头+窗口内唯一空格 → `rfind` 返 0 → text 原样不动）→ 两版都挂死，挂死不构成检测证据，属坏用例。
**发现三：死循环三分类及第四轮实证归位**：
- ①buggy 独挂 fixed 能过=最强检测信号；②用例自带无界循环=坏用例；③两版共挂=坏用例
- 第四轮 5 格归位：**类③实锤 3 格**（bitcount/sqrt/to_base——replay 300s 超时被杀，"fixed 版也挂死"如实记录=时钟修复生效的证明）；**证据蒸发 1 格**（find_first_in_sorted——replay exit=0 67 条全过=用例健康，但 buggy 侧 failed=0：官方 bug `while lo <= hi` 恰是类①形态，90s 整轮超时杀 pytest 后 junit 未落盘→失败证据蒸发。**这是 per-test 粒度超时（交接文档任务 3）的活案例**：整轮超时杀进程=证据丢失，per-test 超时才能把"挂死即证人"落账）；**证据蒸发+ff 混合 1 格**（Python_10——fixed 版也有断言失败，buggy 侧 failed=0 无配对基础）
- C1 停车闸误伤插曲：pilot 5 格全为死循环重试格（detected 0/5<2 触发停波），wrap 排第 6 未被放量→单格 `--cell` 模式补跑并入（闸语义对重试场景不适配，已知限制记录在案）。**wrap 补跑终态=not_detected，replay exit=137（fixed 版挂死被杀）——类③实锤闭环**

## 6. 结论与论文价值映射

1. **检出能力他证**（表 1）→ 实验章主表：第三方基准 + 预注册判据 + 机械可复核口径
2. **能力梯度=需求放大率衰减**（表 3）→ 适用范围一节：HEF docstring 详尽→100%；tqdm 需求笼统探不到 999.95 边界→0%；与消融 X2（需求显式化 0.78）互证 → 改进方向=规格提取/需求显式化
3. **坏用例率基线**（表 2）→ 讨论章：每 8-17 条用例约 1 条坏用例=静态闸/差分闸/审查轨存在的定量论据；pf 仅 8 条=防迁就纪律有效的证据
4. **497 条 fail-to-pass 单证**→ 任何人可拿留档复跑复核（证据条数，不是只有格子数）
5. **死循环三分类**（§4 第四轮）→ 讨论章：非终止缺陷的测试语义（超时即证人+挂死归属分类）
6. **两起驱动器事故取证**（§4）→ 威胁与缓解章：数据完整性审计实战（串账取证+审计假阳性教训）；平台本体在 71 格×4 轮并发压力下零产品缺陷（所有错误均在驱动器侧）
7. **方法论第三次验证**：断点/幂等/隔离是批量驱动器的第一行代码（批3 → bench3 二轮 → bench3 三轮）
