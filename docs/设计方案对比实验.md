> 实验基础设施全部复用现有控制变量体系：run_grid 格子 + grade_corpus 阅卷 + 宿主重放 + 新增变异标定仪器。

## 0. 一页结论

1. **三方案全部实现并上真实链路**（6 格 = 3 方案 × 2 语料 + 10 任务变异标定），回归基线 87→**99 绿**（新增 12 个机制单测）。
2. **主指标 recall：三方案均未提升**——corpus-001 三格全部 0.2（落在基线 X1 自身 n=3 的波动区间 0.2~0.4 内）；corpus-002 三格全部 0 证人（recall 维持 0）。
3. **但三个独有指标各讲出了一个不同的故事**（这正是对比设计要的东西）：
   - **A（弱断率）**：基线弱断率已≈0~2.4%——expected_basis 纪律把弱断言问题在源头压住了，闸在本语料**空转**。它的价值是"回归护栏"（有人换模型/改提示词时兜底），单测已锁。
   - **B（变异杀死率）**：PBT 招募**成功**（corpus-001 生成 2 条、corpus-002 1 条真不变量：`payable+discount==subtotal` 守恒律、`0≤score≤5` 界属性），但占比太小没拉开 recall。**真正的大发现来自仪器本身**：corpus-002 三格套件在 100% 通过率下只杀死 **45.8%** 变异体（discount_engine 行为基本没被锁定），而老基线套件是 **100%**——**通过率完全看不见的套件有效性差异，被变异标定一次照穿**。
   - **C（RTM 条件覆盖）**：机制生效（corpus-001 补生成 15 条用例 45→60），但 RTM 覆盖本已饱和（42/42），**+33% 用例成本换不来 recall 提升**——首轮生成 + LLM 映射在这个语料上已经"名义全覆盖"。
4. **方法论再验证（与上午复盘 §2.2 同源）**：A/B/C 全是首轮生成侧干预，而这两个语料的瓶颈在 **oracle 侧**（断言驯化，X5 已实锤）与**循环表达**（证人冻结首轮即停）——在瓶颈之外加码，主指标当然不动。生成侧干预的下一步应指向 V7（断言独立性约束在 oracle 侧）或不停机模式。
5. **仪器踩坑两枚**（§6）：C 盘 Temp 撞 Windows 保留 junction 导致变异全 0 假象；`-rf` 不显示 ERROR 行导致收集错误被误判"存活"。修复后数字才可信。

## 2. 三方案设计

**共同协议（部分相同的测试方向）**：同基线（X1 n=3，corpus-002 用任务46）｜同语料（corpus-001/002）｜
同执行链路（run_task 端到端）｜同阅卷（grade_corpus LLM 仲裁）｜共享指标 recall/detected/extra/用例数/覆盖率。
**独特点**：每方案干预不同层 + 各带一个对方没有的指标。

| 方案 | 干预层 | 机制 | 文献锚点 | 独有指标 | 开关/格子 |
|---|---|---|---|---|---|
| **A 断言质量闸** | L3 静态闸（第 1.5 道） | AST 审计断言强弱：强=具体关系比较/is True/False/raises(异常)；弱=裸真值/is (not) None/isinstance/无断言；全弱用例剔除（度量恒算、闸由开关控） | 2412.14137（为通过而设计断言）+ UW ASE'25 + 2410.21136 | **弱断言率** | `ASSERTION_GATE_ENABLED` / A1 |
| **B 属性测试第七法** | L3 知识库 + L4 依赖 | 提示词追加 PBT 骨架段（@given 策略 + 真不变量 + max_examples=20 + 弱断言禁令）；install_deps 随开关装 hypothesis（容器+宿主） | Tanaka 2510.25297 + Etna 2603.27002 + Hypothesis 官方 | **变异杀死率**（新仪器 mutation_kill.py） | `PBT_ENABLED` / B1 |
| **C 条件缺口回灌** | L2 流程（plan→generate 闭环） | 生成后用与 map_requirements 同源的 2-gram 映射查无用例对准的条件 → 带已有用例名单定向补生成**恰 1 轮**（预算纪律） | Gotel & Finkelstein 1994（post-traceability）+ CoverUp 回灌模式 + X2 实证（需求显式化=检出驱动） | **RTM 条件覆盖** | `COND_FEEDBACK_ENABLED` / C1 |

## 3. 实现与单测

- `gen_tests.py`：`assertion_audit`/`_audit_one_assert`（纯函数）、`apply_assertion_gate`（度量恒算+可选闸）、
  `_condition_gaps`+`refill_condition_gaps`（llm 注入，fake 可单测，同 repair_strategy 模式）、pbt 标志传入提示词
- `prompt_library.py`：`PBT_SECTION`（骨架示例带弱断言禁令，防与方案A 口径打架）、`cond_forced` 强制覆盖模式 + 已有用例名单防重复
- `builtin.py`：install_deps 随 `PBT_ENABLED` 装 hypothesis
- `scripts/mutation_kill.py`：AST 算子变异（比较符/布尔联接词/算术，链式比较每 op 一点）→ 宿主重放 →
  killed=基线差集新失败（证人污染免疫），收集错误计杀死，基线收集健康度显式校验
- `scripts/run_grid.py`：新增 A1/B1/C1 三格；`scripts/compare_proposals.py`：跨格聚合（独有指标对基线回算）
- 单测：tests/test_design_proposals.py ×12（强弱断言分类/闸保留混合案/PBT 开关/缺口发现/回灌合并与防重/诚实降级/无缺口不发 LLM 调用）；**回归 99 passed 1 skipped**

### 4.2 深挖

- **corpus-001 的 0.2 是"仲裁波动"而非"检出丢失"**：三格 D1 全检出；D5 证人用例**实际存在且失败着**
  （都在 extra_suspect：`test_is_strong_*_boundary`），但本轮阅卷判成 uncertain（基线轮同型用例判 detected）。
  n=1 阅卷 + LLM 仲裁温度 0.1 的波动与"20% 人工抽查"待办互相印证——**三格 n≥3 前不下"变差"结论**。
- **corpus-002 的真故事在杀死率**：三格套件 100% 通过、35 条用例、弱断率 0——表面完美；但 24 个变异体只杀死 11 个
  （全部集中在 coupon_engine，**discount_engine 的行为没有任何用例锁定**）。老基线（任务46）24/24 全杀。
  这就是 X5"断言被驯化"的定量版：**通过率、覆盖率、弱断率三个指标全都看不见的差异，变异标定一次照穿**。
- **C 的机制学证据**：任务71 用例 45→60（+15 条补生成），RTM 覆盖本已饱和 → 名义全覆盖 ≠ 检出提升；
  `覆盖了≠测到了`在条件层同样成立。
- **B 的 PBT 招募**：提示词段成功招出真不变量（守恒律/界属性/参照实现等价），与 Tanaka 2510.25297 的
  "LLM-PBT 特征"吻合；但 1-2 条的占比不足以拉开套件级杀死率——招募率提升（few-shot/模板化）是 v2 方向。

## 5. 诚实结论

1. **三方案在本双语料上均未提升 recall**（各自 n=1；corpus-001 三格落在基线自身波动区间内）——如实报告，不洗。
2. 方案A 的闸在"expected_basis 纪律已生效"的生成器上是**空转护栏**：它的价值在后防（换模型/改提示词的回归保护），本语料测不出增益。
3. 方案B 的提示词级 PBT 招募可行但产量低；**变异杀死率是本轮最有价值的产出**——它是第一个能区分"看起来一样好"的套件的指标，建议进 collect_metrics 成为常规指标（仪器已就绪）。
4. 方案C 机制正确但加在不饱和的问题上才会有效；RTM 条件覆盖饱和（LLM 映射口径）时它退化为成本项——使用前提是"映射口径可信且未饱和"。
5. **两个语料的瓶颈都不在生成侧**：corpus-001 卡在证人冻结的表达面（循环机制不可测），corpus-002 卡在 oracle 侧（断言驯化）。下一步的杠杆在 **V7 断言独立性约束**（oracle 侧）与**不停机补测模式**，不在继续加码生成提示词。
6. 仪器教训见 §6：假 0 比没有数字更危险——基线收集健康度校验已内置进仪器。

## 6. 仪器踩坑（复现警示）

1. **C 盘 Temp junction 坑**：pytest 扫描 `C:\Documents and Settings`（Windows 保留 junction）PermissionError →
   整轮收集失败。mutation_kill 临时目录已固定 `data/tmp_mut/`（D 盘），勿改回系统 Temp。
2. **`-rf` 摘要盲区**：只列 FAILED 不列 ERROR → 收集错误变异体被误判"存活"（首轮全线 0.0 的假象来源）。
   已改 `-rEf` 且 failing_nodeids 本就兼容 ERROR 行。
3. **基线健康度前置校验**：基线（未变异）跑不干净，后面全部数字作废——仪器已在基线步显式校验并拒绝出数。
4. **registry 不落 skill 输出**（skill_invocations 只有 args/tokens/error）：gen 摘要只能靠 agent_messages 的
   400 字截断消息——P2 老问题再添一条罪状，round_metrics 表（复盘 §4-C）的又一理由。
