## 2. 实验数据修正与新发现（论文口径，重要）

### 2.1 X1 recall 修正：0.80 是旧口径，修正为 0.4

AGENTS.md 旧记录"X1 实测 recall 0.80=4/5"是**阅卷根修前**的数字（旧版证人集未过滤失败用例）。根修后重阅卷（grade_task45.json）：

- detected 2（D1+D5）+ uncertain 1（D4）+ not 2（D2/D3 占位），**recall = 0.4**
- extra_suspect 从 11 条降到 4 条

论文引用一律以 grade_task*.json 为准。

### 2.2 X 格对比（corpus-001，每格 n=1）

| 格 | 开关 | recall | detected+uncertain | extra_suspect | 失败 nodeid（宿主重放）|
|---|---|---|---|---|---|
| X1 默认 | — | 0.4 | 2+1 | 4 | 10 |
| X2 五方法关 | V2=False | 0.4 | 2+1 | 1 | 3 |
| X3 plan/RTM 关 | V3=False | **0.2** | 1+0 | 0 | 2 |
| X4 缺口回灌关 | V4=False | 0.4 | 2+1 | 0 | 2 |

**结论①（论文可用）**：plan/RTM 是唯一在本语料上表达出来的开关——关掉后 recall 0.4→0.2，丢失的正是 D5（is_strong 边界强密码误判）。这是"测试分析阶段（条件拆解）提升检出能力"的第一条控制变量证据。
**结论②（协议缺陷）**：V2/V4 几乎无表达机会——**所有格子第 1 轮就撞上证人冻结（product_defect 即停）**，缺口回灌这类只作用于补测轮的机制根本没运行。对照格设计必须区分"首轮检出能力"与"循环修复能力"两类被测机制，后者需要不触发证人冻结的语料（见 §4-D、§5）。

### 2.3 语料协议缺陷：占位缺陷进了 recall 分母

出题人答案键自述 D2/D3 为**占位说明（无真实缺陷）**，但 grading 分母 planted_assertion=5 把它们计入 → corpus-001 的 recall 结构性上限只有 0.6，且 grader 判 D2/D3=not 反而是正确行为却被计作漏检。

**修正口径（二选一）**：① ground_truth 增加 `decoy: true` 字段，阅卷分母剔除占位项（诚实 recall = 2/3 ≈ 0.67）；② 语料补足真实缺陷数。协议修正要同步写进链路方法测试文档。

### 2.4 噪声与 n=1 诚实边界

同一语料上 X1 首轮 10 个失败 nodeid vs X4 只有 2 个——LLM 采样波动（temperature=0.2）远大于部分开关效应。**每格 n≥3 + 记录采样差异**之前，X 格对比只能当方向性证据写，不能当结论写。

### P2：记录在案，可延后

4. **static_only 短路守卫是死代码**：report 节点对 static_only/Java 短路路径也会插报告行 → review 里 `"no_report" in output` 永不触发，这些任务照样走完整评估链（0/0/0 指标 + 叙述）。行为不算错但与注释意图不符（nodes.py:373）。
5. **test_reports.duration_ms 恒 None**：报告节点从未测量端到端时长；"工具耗时"图用的是 skill 台账，任务级耗时缺失。
6. **跨轮同名用例**：LLM 两轮生成同名用例时，prune 按 name UPDATE enabled=0 会误伤他轮同名用例；阅卷侧同因放大（X1 的"10 个失败 nodeid 命中 16 条证人"即此现象）——DB 用例名只保证单轮唯一，不保证任务全域唯一。
7. **rewrite 台账缺 module_id**：repair_strategy 插 test_scripts 不带 module_id，与主生成路径字段不一致。
8. **超时后台线程继续跑**：registry future.result 超时后底层 LLM 调用/容器 exec 仍在执行（容器侧已有 fresh 重建兜底；LLM 侧超时后仍在烧 token，无取消）。
9. **API 小毛病**：stop 对终态任务也返回 stopped=True（误导）；toggle 在工作区被手删后会 500（_rebuild_imported_file 直接 write_text）。

## 4. 改进提案（按论文收益/成本排序）

- **[P0-A] 阅卷协议修正（协议部分 ✅ 2026-10-29 完成；n≥3 复跑仍待 DeepSeek 余额）**：ground_truth 加 decoy 字段（corpus-001 D2/D3、corpus-002 D3）+ grade_corpus 分母剔除（split_planted/compute_metrics 纯函数 + `--recompute` 离线重算 16 份明细，仲裁判决沿用未重调 LLM，单测 5 个锁语义）+ 重算聚合见链路方法测试文档文末——X 格四结论定性全部不变，X2 上限 0.47→0.78、X3 垫底 0.20→0.33 且与 X1/X4 差距拉大，plan/RTM 正贡献证据更强。
- **[P0-B] rerun 幂等**：plan 节点先 `DELETE FROM test_conditions WHERE task_id=?`；provision（或 clone）后调 `_rebuild_imported_file` 重建 imported 文件。各一行级改动，各配 1 个单测。
- **[P1-C] round_metrics 表**：evaluate 节点把每轮 (round, passed, failed, coverage, verdict, fingerprint) 落第 16 张表，collect_metrics 改读表。根治 P1-3 的正则脆弱性，也让"评估链单快照"语义有了更干净的载体。
- **[P1-D] V8 开关"证人冻结+继续补测"（✅ 2026-10-29 已实现，config.WITNESS_CONTINUE_ENABLED，编号从 V5 纠正为 V8——V5 已被"出题模型独立性"占用，见链路方法测试文档 §3 矩阵）**：product_defect 时冻结证人不再重写，但**继续走缺口回灌补测**，终态仍 stop 且缺陷如实上报。这是解开 §2.2 结论②的钥匙——循环类机制（缺口回灌/定向修复）只有在"不停机"的语料/模式下才可测量；同时更贴近真实测试流程（发现缺陷 ≠ 停止补齐其余覆盖）。实现语义：断言失败用例累积为冻结证人（当轮产生当轮生效）、证人失败行不进指纹（有意保留≠原地打转，不误触熔断）、只剩证人时按覆盖率决定继续补测或终态上报、新非证人失败照常熔断/预算分流。
- **[P1-E] token 成本台账**：skill_invocations 加 prompt/completion tokens 字段（langchain response.usage_metadata 可取）→ 新指标"每检出 1 个缺陷的 token 成本"，论文可画成本-质量曲线，X 格对比多一个维度。
- **[P2-F] 断言强度审计**：AST 静态分级生成用例断言（`assert x is not None`/真值断言=弱，具体值比较=强），报告新增"弱断言率"。配合 UW ASE'25 oracle 实证（§5-④）是现成论文叙述。
- **[P2-G] 用例最小化**：按行覆盖做贪心集合覆盖，报告"精简率"（冗余用例占比）。纯确定性代码，零 LLM 成本。
- **[P2-H] 方法骨架扩容**：五法 → 七法（+属性测试、+蜕变关系，见 §5-①②），V2 开关天然支持对照。

## 5. 新软测方法发散（外部锚点 → 本系统接口 → 论文位置）

### ① 属性测试（Property-Based Testing）——当前最值得吸收的方向

- 锚点（2026-10-28 编号核验后修订）：原记"OOPSLA 2025 实证属性测试杀 ~50× 变异体"**出处未能定位，找到原文前该数字不得进论文**；已核验锚点=Etna PBT 评估平台（arXiv 2603.27002）、LLM 生成 PBT 边界特征研究（arXiv 2510.25297）、PBT CPS 护栏（arXiv 2505.23549）。
- 接口：gen_tests 的方法骨架加第七法"属性测试"——LLM 生成 `@given(hypothesis.strategies...)` 属性函数 + `settings(max_examples=50)`，容器镜像装 hypothesis 即可。 expected_basis 纪律照用（属性先于执行确定）。
- 论文位置：理论章"测试设计技术"扩容；实验章可做"属性用例 vs 示例用例的变异杀死率对比"（E4 仪器现成）。

### ② 蜕变测试（Metamorphic Testing）

- 锚点（2026-10-28 口径核验后修订）：蜕变测试正统综述=Chen 等 ACM CSUR 2018（DOI 10.1145/3143561）；LLMORPH（ASE 2025，arXiv 2603.23611）方向是**用蜕变测试测 LLM 系统**而非"LLM 生成 MR 测程序"，引用时注意方向（详见 docs/literature-map.md §5）。
- 接口：对无 oracle 函数（Barr 综述的正主），让 LLM 提炼蜕变关系 MR（如"输入排序不影响 check 合法性"）并生成 MR 用例。归因时 MR 违反=疑似 product（与现有三分类兼容，新增强信号）。
- 论文位置：oracle 问题讨论的工程出路，答辩"无规格怎么办"的标准答案。

### ③ 变异引导的生成闭环——把 E4 仪器从"标定"升级为"信号"

- 锚点（2026-10-28 编号核验后修订）：Meta **MutGen**（arXiv 2501.12862，即原记 ACH，TestGen-LLM 官方续作，变异引导+oracle 推断生产级）；**Test vs Mutant 对抗双 agent**（arXiv **2602.08146**，旧记 2505.15253 系编号错误）；原记 GEM（2408.13156）编号失实且原文未定位，该思想改用 MutGen/Test vs Mutant 表述（详见 docs/literature-map.md §5）。
- 接口：mutmut 变异体已能在容器里跑（E4 现成）→ 新闭环：RTM 条件 × 变异体矩阵，要求每条条件至少被一个"杀死变异体"的用例覆盖，杀不死的条件回灌 generate（比行覆盖更强的缺口信号——覆盖了≠测到了）。新指标"条件级杀死率"。
- 论文位置：方法章核心升级点；把 E4（归因标定）和 R-Loop（补测闭环）两条线拧成一条，是全文最有故事性的扩展。

### ④ Oracle/断言质量审计——为防造假纪律补实证

- 锚点：UW **Do LLMs Generate Useful Test Oracles?**（ASE 2025）；**Test Overfitting on SWE-bench**（2511.16858，"迁就测试通过而不修 bug"的实证——正是 expected_basis/证人冻结要防的事）。
- 接口：①P2-F 断言强度审计落地后，可做"expected_basis=需求明示 的用例 vs 源码推导 的用例，谁更少出现迁就性断言"——直接验证本系统防造假设计的有效性，全部数据已在 test_cases 表里。
- 论文位置：评估章新增小节"断言质量分析"；引用 2412.14137（LLM 会写验证 bug 的断言）+ ASE'25 形成证据链。

### ⑤ 测试验证基准（SWT-bench）与语料 v3

- 锚点：**SWT-Bench**（NeurIPS 2024，1,900+ 真实 issue+补丁+测试，测"生成能验证 bug 修复的测试"）；SWE-Tester 等后续。
- 接口：语料 v3 除继续自建（修复 decoy 分母 + 增加"循环表达型"语料）外，可从 SWT-bench 抽 3-5 个 Python 样例做"真实世界缺陷"补充格——出题人=真实世界，比自植缺陷更有说服力。
- 论文位置：实验章语料来源多元化；相关工作章引用其测试验证设定。

### ⑥ 回归选择与演进（增量模式）——"一次性"走向"持续"的天然下一步

- 锚点：Evaluating LLM-Based Test Generation Under Software Evolution（2603.23443）；经典 RTS/RTP。
- 接口：RTM 已有 条件↔用例 映射 → 反向使用：repo diff → 变更函数 → 命中的条件 → 只重跑相关用例子集。表结构零改动（rtm_maps + per_file 已够推导），是"未来工作"里成本最低、最像产品的方向。
- 论文位置：展望章主菜；答辩"你这系统只能跑一次吗"的回答。

### ⑦ Flaky 检测——ISTQB "tests wear out" 的落点

- 接口：终态 pass 的任务在容器里把套件重跑一遍（只对失败样本+抽样通过的重复），不一致率=flaky_rate 入报告。成本≈一次 run_tests，V 开关可关。
- 论文位置：评估指标扩容 + 诚实边界（当前报告的"通过"隐含单次执行假设）。

### ⑧ 跨模型交叉审——补上 v1 未做的"LLM 交叉语义审"

- v1 留白的生成用例 LLM 交叉语义审，建议审稿人用**不同家族的模型**（与盲测协议"同源模型边界"声明呼应）：第二模型只审"断言是否可证伪、是否迁就实现"，不接触生成提示词。与 §4-E 的成本台账一起，可量化"交叉审的边际收益 vs token 成本"。
