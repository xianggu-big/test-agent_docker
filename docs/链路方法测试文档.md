> 状态：2026-10-28 建立。本文 = 盲测集协议 + 控制变量矩阵 + 全部实验数据的唯一记录处。
> 配套：docs/experiment-design.md（B1 实验设计 RQ1-RQ5 蓝图）、docs/industry-testing-research.md（方法依据）。
> 纪律：每次实验**只改一个变量**，其余保持默认；每条数据注明语料、变量、n 与日期。

## 1. 实验思想（用户原始想法 → 优化定稿）

用户原始想法：AI 自己构建测试集（网站），但**生成不能在同一个窗口**——让子代理生成，
这样测试方"不知道网页的底细"；子代理同时列出植入的漏洞/性能问题清单，测试后对比。

优化定稿为**三方盲测协议**（出题—答题—阅卷分离）：

| 角色 | 谁 | 职责 | 隔离规则 |
|---|---|---|---|
| 出题人 | 独立子代理会话（无 Test Agent 上下文） | 生成被测项目 + 植入缺陷 + 写 ground_truth.json | 产物不含任何泄题标记；answer key 不进工作区 |
| 答题人 | Test Agent 标准链路 | 按需求文档测试，报告疑似缺陷 | **物理隔离**：ground_truth.json 存 corpus 根目录，工作区快照只含 project/ 子目录 |
| 阅卷人 | grade_corpus.py（确定性比对 + LLM 仲裁） | 报告缺陷 ↔ answer key 对齐，算检出率/误报/漏检 | 仲裁结果供人工抽查 |

为什么这个设计有价值：它给了归因器一个**可控真值来源**（与 E4 变异标定互补——mutmut 产"机械缺陷"，
盲测语料产"语义缺陷"），这正是论文"检出率/误报率"两个核心指标的数据来源（feedback_annotations 的
自动化前传）。

**诚实边界**：首批出题人与答题人同源模型（GLM 系子代理 / DeepSeek 答题），非完全独立——
论文表述为"上下文隔离的出题-答题分离"，完全异构出题（如换开源小模型）列为语料 v2。

## 2. 盲测语料协议

目录结构（data/corpus/<corpus_id>/）：

```
data/corpus/corpus-001/
├── project/              # 唯一进工作区的内容（答题人可见）
│   ├── checker.py        # 被测模块（含植入缺陷，无泄题标记）
│   └── REQUIREMENT.md    # 自然语言需求（行为契约，测试方的需求输入）
└── ground_truth.json     # 答案键（阅卷人可见，答题人不可见）
```

ground_truth.json schema：

```json
{
  "corpus_id": "corpus-001",
  "theme": "密码强度校验器",
  "requirement_summary": "需求一句话概括",
  "planted_defects": [
    {"id": "D1", "type": "boundary_off_by_one", "location": "checker.py::check_length",
     "description": "长度≥8 应通过，实现用了 >8，恰好 8 被拒",
     "expected_assertion": "check_length('a'*8) 应为 True",
     "detectable_by": "assertion"}
  ],
  "notes": "出题协议：缺陷全部为可通过 pytest 断言暴露的行为缺陷"
}
```

**detectable_by 分层（漏检率分母规则）**：`assertion`=单元断言可暴露；`integration`=需多模块交互；
`performance`=v1 系统不测性能，**预期检不出，计入"预期漏检"而非漏检**——防止指标虚高。

**decoy 占位标注（2026-10-29 协议修正，模块复盘 [P0-A] 落地）**：`decoy: true` = 出题人自述
无真实缺陷的占位说明条目（corpus-001 D2/D3 原文「此条为占位说明」、corpus-002 D3
expected_assertion="待替换"）——**不进 recall 分母**：占位条目判 not 是正确行为，计入分母会把
corpus-001 的 recall 结构性上限压到 0.6。分母 = detectable_by=assertion 且非 decoy。
历史明细由 `python scripts/grade_corpus.py --recompute <corpus_id>` 离线重算（沿用已落盘仲裁
判决，不重调 LLM；明细新增 decoy_excluded/recompute_note 溯源字段，原判决全量保留作证据）；
无 decoy 字段的老语料口径逐字节不变（单测锁定，tests/test_grade_corpus.py）。

### 语料主题约束（能力域对齐）

v1 语料 = 小型 Python 工具模块（60~120 行、3~5 个函数、纯标准库）——与 Test Agent 深度支持域
（pytest 单元+轻量集成）对齐；"网站/Web 项目"形态需 Flask test client 支持，列为语料 v2（记入 §6）。

## 3. 控制变量矩阵（每次只动一格，其余保持默认 True/prune）

| 变量 | 含义 | 开关 | 默认 | 对照值 |
|---|---|---|---|---|

| V6 | 边界攻击纪律 | config.GEN_BOUNDARY_ATTACK | False | True（X5 已实测） |
| V7 | 断言独立性纪律 | expected_basis 闸 | — | 语料 v2 改进实验（未做） |

| V9 | 生成用例 LLM 交叉语义审 | config.GEN_CROSS_REVIEW_ENABLED | False | True（2026-10-29 已实现：vision §3.6 第 3 道闸，审查者角色逐案审断言是否对应需求；fail 单独重造 1 次、复审批量一次、仍 fail 剔除单案不拖累整批；审查/复审不可解析 fail-open 放行留痕；phase=cross_review/regen_case 进 llm_calls 台账；真机消融待 DeepSeek 余额） |

**指标定义**：
- 检出率 = 检出的 planted_defects（detectable_by=assertion 且非 decoy 的分母）/ 该分母总数（2026-10-29 起剔占位，见 §2）
- 误报 = 报告的疑似缺陷中与 answer key 无法对齐的条目（其中可能含"出题人都没想到的真缺陷"→
  阅卷标记 extra_suspect，供人工复核后二次归类）
- 漏检 = 分母内未检出的缺陷清单（逐条列出，论文附表）
- 每格同时记录：轮次数、终态 verdict、覆盖率、LLM 调用数、端到端耗时（沿用 E2 口径）

### 2026-10-28 X1-X4 + corpus-002 结果分析（论文实验章素材）

1. **V3（plan/RTM）是四格中唯一与检出率正相关的变量**：X3（无 plan）recall 0.2 vs 其余格 0.4——
   测试条件拆解把"需求说应怎样"显式化，生成器才有对抗实现的锚点。n=1 弱证据，X 格各复跑 n=3 后定论。
2. **corpus-002 recall 0.0 是本轮最有论文价值的发现**：36 条生成用例 35 过 1 败——生成器对"满减阈值
   边界差一"类缺陷**不主动构造边界攻击输入**，用例断言倾向跟随实现行为（arXiv:2412.14137 批判的
   直接实证）。改进方向：plan 条件里显式生成"边界值用例模板"（边界值分析骨架已有，但需求未给数值
   契约时失效）→ 语料 v2 的 REQUIREMENT.md 要求数值契约更明确，或 gen 提示词强制"每函数至少 1 条
   边界外输入"。
3. **阅卷器本身需要标定**：旧阅卷器（未过滤失败用例）给出 recall 0.8，根修后同任务真值 0.4——
   教训=评测脚本与被测系统一样会骗人，答案键对齐逻辑必须有可复现明细（grade_task*.json）供人工抽查。
4. **四格执行面指标高度一致**（1 轮收敛、证人保留、覆盖率 98-100%）：说明控制变量只影响了"测出什么"，
   没有破坏"怎么测"——实验设计的内部效度成立。
5. 复跑纪律（预注册）：每格 n>=3 后才允许进论文正文；当前全部 n=1，仅作趋势与机制证据。

**结论四条**：
1. **X3（无 plan/RTM）以 0.20±0.00 三跑全部垫底且方差为零**（X1/X4 0.33、X2 0.47）——plan/RTM
   测试条件拆解对缺陷检出率的正贡献从 n=1 弱证据升级为 n=3 稳定证据，可进论文正文（X 格核心结论）。
2. **X2（无五方法骨架）0.47 反而最高**（与 X1 0.33 差异在噪声内）——诚实发现：检出率的驱动
   因子是"需求→条件的显式化"，不是方法骨架本身；五方法骨架的价值要在覆盖率与用例结构上看，
   不在检出率上（论文里如实写，避免过度声称）。
