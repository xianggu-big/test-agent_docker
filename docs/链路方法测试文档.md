## 1. 实验思想（用户原始想法 → 优化定稿）

用户原始想法：AI 自己构建测试集（网站），但**生成不能在同一个窗口**——让子代理生成，
这样测试方"不知道网页的底细"；子代理同时列出植入的漏洞/性能问题清单，测试后对比。

优化定稿为**三方盲测协议**（出题—答题—阅卷分离）：

| 角色 | 谁 | 职责 | 隔离规则 |
|---|---|---|---|
| 出题人 | 独立子代理会话（无 Test Agent 上下文） | 生成被测项目 + 植入缺陷 + 写 ground_truth.json | 产物不含任何泄题标记；answer key 不进工作区 |
| 答题人 | Test Agent 标准链路 | 按需求文档测试，报告疑似缺陷 | **物理隔离**：ground_truth.json 存 corpus 根目录，工作区快照只含 project/ 子目录 |
| 阅卷人 | grade_corpus.py（确定性比对 + LLM 仲裁） | 报告缺陷 ↔ answer key 对齐，算检出率/误报/漏检 | 仲裁结果供人工抽查 |

为什么这个设计有价值：它给了归因器一个**可控真值来源**（与 E4 变异标定互补——mutmut 产"机械缺陷"，
盲测语料产"语义缺陷"），这正是论文"检出率/误报率"两个核心指标的数据来源（feedback_annotations 的
自动化前传）。

**诚实边界**：首批出题人与答题人同源模型（GLM 系子代理 / DeepSeek 答题），非完全独立——
论文表述为"上下文隔离的出题-答题分离"，完全异构出题（如换开源小模型）列为语料 v2。

## 2. 盲测语料协议

目录结构（data/corpus/<corpus_id>/）：

```
data/corpus/corpus-001/
├── project/              # 唯一进工作区的内容（答题人可见）
│   ├── checker.py        # 被测模块（含植入缺陷，无泄题标记）
│   └── REQUIREMENT.md    # 自然语言需求（行为契约，测试方的需求输入）
└── ground_truth.json     # 答案键（阅卷人可见，答题人不可见）
```

ground_truth.json schema：

```json
{
  "corpus_id": "corpus-001",
  "theme": "密码强度校验器",
  "requirement_summary": "需求一句话概括",
  "planted_defects": [
    {"id": "D1", "type": "boundary_off_by_one", "location": "checker.py::check_length",
     "description": "长度≥8 应通过，实现用了 >8，恰好 8 被拒",
     "expected_assertion": "check_length('a'*8) 应为 True",
     "detectable_by": "assertion"}
  ],
  "notes": "出题协议：缺陷全部为可通过 pytest 断言暴露的行为缺陷"
}
```

**detectable_by 分层（漏检率分母规则）**：`assertion`=单元断言可暴露；`integration`=需多模块交互；
`performance`=v1 系统不测性能，**预期检不出，计入"预期漏检"而非漏检**——防止指标虚高。

### 语料主题约束（能力域对齐）

v1 语料 = 小型 Python 工具模块（60~120 行、3~5 个函数、纯标准库）——与 Test Agent 深度支持域
（pytest 单元+轻量集成）对齐；"网站/Web 项目"形态需 Flask test client 支持，列为语料 v2（记入 §6）。

## 3. 控制变量矩阵（每次只动一格，其余保持默认 True/prune）

| 变量 | 含义 | 开关 | 默认 | 对照值 |
|---|---|---|---|---|
| V1 | 定向修复策略 | config.REPAIR_STRATEGY | prune | rewrite / hybrid（E2 已单独对比） |
| V2 | 五方法骨架 | config.GEN_METHODS_ENABLED | True | False（自由发挥） |
| V3 | plan/RTM 测试条件 | config.PLAN_ENABLED | True | False |
| V4 | 覆盖缺口回灌 | config.COVERAGE_FEEDBACK_ENABLED | True | False |
| V5 | 出题模型独立性 | 出题人来源 | 同源子代理 | 异构模型（语料 v2） |

**指标定义**：
- 检出率 = 检出的 planted_defects（detectable_by=assertion 分母）/ 该分母总数
- 误报 = 报告的疑似缺陷中与 answer key 无法对齐的条目（其中可能含"出题人都没想到的真缺陷"→
  阅卷标记 extra_suspect，供人工复核后二次归类）
- 漏检 = 分母内未检出的缺陷清单（逐条列出，论文附表）
- 每格同时记录：轮次数、终态 verdict、覆盖率、LLM 调用数、端到端耗时（沿用 E2 口径）
