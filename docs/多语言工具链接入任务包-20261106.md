## 0. 通用接入流程（每个语言都走这六步，本卡只记录各语言差异点）

| 步 | 内容 | 产出物 | 参照先例 |
|---|---|---|---|
| S1 前置调研 | 报告格式、闸门工具、镜像基座的开源方案核验（GitHub star/维护状态/license），结论写回本卡 | 调研记录段落 | attribution/repair 的研究先行先例 |
| S2 镜像 | Dockerfile（只装工具链不装项目依赖）+ config.IMAGE_BUILD_CTX 注册 + build_images 自检 | 镜像 tag | mta-test:py312 / node20-jest |
| S3 探测+recipe | stack_detect 加语言特征正则（工程清单文件）；recipe 白名单加启动命令模板与依赖清单探测 | 探测分支 + recipe 模板 | install_deps 三类清单探测 |
| S4 生成+闸门 | prompt_library 加该语言用例代码渲染层（五方法骨架不变，只换渲染）；确定**语法/编译闸**（闸不过=整案剔除） | 渲染模板 + 闸门函数 | gen_tests import 白名单 + node --check |
| S5 执行适配器 | 新建 `<lang>_adapter`：该语言测试报告 → pytest 风格等价文本（passed/failed 计数、FAILED nodeid 行、覆盖表）——**下游 evaluate/repair/report 零改动** | adapter 模块 | js_adapter（jest→pytest 文本） |
| S6 归因+验收 | 堆栈/报错解析按语言分支入归因三闸；真机 demo 项目跑全链路（生成→闸→执行→覆盖率→归因→评估五工具） | 验收记录 | Tier2 JS 真机链路 |

**关键纪律**：
- S5 是整个扩展的枢纽——只要 adapter 输出统一文本，归因三分类、R-Loop 剪枝、评估五工具、四级接力全部自动继承，**禁止**为新语言改下游节点逻辑。
- 语言差异只允许出现在：镜像内容、探测正则、recipe 模板、渲染模板、adapter 解析、堆栈正则——六个确定性位置。**prompt 骨架（五方法）禁止按语言分化**，语言事实只能作为只读上下文注入。
- 每阶段先立失败测试/最小 demo，再动实现；不动真实库、不跑真实任务链。

## 阶段 1 · TypeScript 升级 Tier2（P1，约 2 天，复用度最高）【✅ 已完成 2026-11-07，验收 PASS】

- **现状卡点**：ts-jest 需项目级配置，全局镜像预装跑不了 → 目前 Tier3。
- **解法（对齐"依赖随项目走"原则）**：镜像只加全局 `tsc`；TS 项目的 `typescript/ts-jest/@types/*` 由 install_deps 在容器内按项目 `npm i -D` 安装。
- **六步差异点**：
  - S3：stack_detect 加 `tsconfig.json` 特征；install_deps 识别 TS 项目追加 devDependencies；
  - S4：静态闸在 `node --check` 之前加 `tsc --noEmit`（类型闸）；
  - S5：**几乎零成本**——ts-jest 输出仍是 jest JSON 格式，js_adapter 直接兼容，仅需验证 coverage 的 source map 回映射。
- **验收**：TS demo（tsconfig + ts-jest）真机全链路：生成 .test.ts → tsc 闸 → jest 执行 → 覆盖率映射回 .ts → 归因/报告正常。
  - ✅ **PASS（2026-11-07 02:37，8/8 checks）**：smoke_ts.py 全图真机（Docker+LLM，tmp 库）——语言判定 typescript / 生成 .test.ts / framework=jest 落库 / R-Loop 轮次落库（16 过 3 败）/ 逐用例结果落库 / **覆盖率映射回 .ts（容器臂直接验 coverageMap 键=/work/src/calc.ts + adapter 文本 src/calc.ts 覆盖行）** / **埋的 clamp 上界未钳制缺陷被边界值用例抓到（product_defect 证人如实上报）** / 终态产出。证据=data/reports/ts_accept/smoke_ts_20261107-023706.json；回归 653 过 1 跳 + 守卫 138 OK/0 FINDING。
  - **S1 调研结论（2026-11-07 容器探针，生产代码路径）**：①镜像全局件实测 jest 29.7.0/tsc 5.9.3/ts-jest@29 在位，tsc 类型闸正例 exit 0/负例（string 传 number）exit 2；②**全局 ts-jest transformer 不可用**（npm 全局布局把 jest 依赖嵌套在 jest 包内，ts-jest require('jest-util') 经 NODE_PATH 顶层解析不到；扩展 NODE_PATH 补救亦失败）——「依赖随项目走」是唯一通路，本地补装后两形态（带 package.json/散装）均跑通；③npm install --no-save 在无 package.json 目录实测 exit 0 可用 → probe_deps_manifest 新增 ts_loose 形态（不破「真无清单=零执行」契约）。
  - **返工 3 轮（每轮真机/容器实锤）**：第 1 轮=LLM 把五方法知识库 Python 示例照抄进 .test.ts（import pytest/@pytest/def test_/assert）混写穿透解析层旧过滤（def test_ 或 JS_CASE_RE）→ tsc 闸整案废案三轮全灭；修=解析层语言形态闸（_parse_cases 加 lang，JS/TS 只认 jest 形态+pytest 槽位模板同剔）+ refill/cross_review 透传 + lang_rules 禁混写纪律 + collect 闸废案留档（data/reports/collect_gate_reject/）。第 2 轮=_pkg_declares_jest 子串判定被 "test": "jest" scripts 值误命中 → 不注入内联配置 → 全局 jest 无配置拒跑 suite 全挂；修=JSON 解析判顶层键。第 3 轮=smoke 判据两处错（nodeid 期待 .test.ts:: 前缀，实际 jest fullName 形态；per_file 走错数据源——100% 全覆盖文件行有意不进 per_file 是 B2 缺口回灌设计口径，test_prune 守卫）；修=判据对齐真实形态+新增 verify_sourcemap 零 LLM 容器臂直接验 coverageMap 键。
  - **实现偏差（如实入档）**：散装 TS 补装以 probe ts_loose 显式形态实现（任务卡只说 install_deps 识别 TS 项目——真机证明无清单目录也必须补装）；「覆盖率映射回 .ts」验收走容器臂（per_file 是 B2 口径不承载该证据）；demo 目录 ts-calc（tsconfig+package.json+src/calc.ts 埋上界未钳缺陷）。

## 可选加强项 · 新语言迁移性小格验证（[可选]，不阻塞收口判定）

> **目的**：E9/E10 的机制结论（X-BREADTH token -25%、五方法骨架、失败知识重跑）实验语料全部为
> Python（corpus-001/002/003 共 6 个 .py 源文件）。机制作用在语言无关层（提示词骨架/采样策略/
> R-Loop 编排），架构上可平移，但**效果数字不自动平移**——本项把"可平移"从架构承诺变成实测证据，
> 回答辩"外推有效性"之问。

- **触发时机**：某语言真机验收（阶段【验收】）通过之后，由**用户开实验窗口**执行。
- **做法**：复用 E9 既定格格式（e9a1 同构，具体入口以 scripts/ 与 E9 任务包为准），在该语言的
  接入 demo 语料上跑 n=3 小格，与 Python 语料基线对比。
- **对比指标**：每格 token 消耗与 token/条（主指标）；用例产出数；生成用例静态质量抽查
  （条件分布是否出现同函数域膨胀——X-BREADTH 结论在新语言上是否复现）。
- **成本预估**：每格约 2-3 万 token，单语言三格 <10 万 token，zcode 每日赠送额度可覆盖。
- **纪律红线**：E9 任务链属真实任务链，**zcode 闲时任务禁止执行本项**（与每日提示词护栏一致），
  必须用户本人在实验窗口跑，避免污染 E9/E10 台账与并发计费。
- **产物落点**：结果 JSON 落 `data/reports/e9_full/`（沿用命名 `e9a1_<lang>_n{k}.json`），
  对比结论摘要写回本卡对应语言阶段验收栏下方，标注"迁移性验证"。
- **答辩口径**：论文 E9/E10 结论作用域声明为 Python 语料；新语言迁移性由本项小格实测佐证
  （每个接入语言一组 n=3 数据点）；数字不一致时如实报告差异并归因（用例形态/mock 文化/编译闸）。
- **终验关系**：本项**不进入**终验必验矩阵（终验提示词只验各阶段【验收】条目），缺本项不影响
  收口判定；仅作为论文证据链的加强项。
