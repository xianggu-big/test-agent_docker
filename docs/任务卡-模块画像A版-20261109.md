## 0. 现状（已核实）

- `modules` 表每项目仅 1 行（path='.'，口径 b 整仓策略）——"模块"概念不存在，本卡补齐；
- 画像所需数据全部确定性可得：radon 复杂度（已接入 plan）、per_file 覆盖（test_reports 556 份）、语言/文件统计（analyze）；
- 历史数据教训：现有报告 182 份有 per_file、中位数 1 文件——**多模块靶子必须自建**（§2）。

## 1. 模块切分（确定性，绝不让 LLM 定边界）

| 语言 | 切法 |
|---|---|
| Python | 有 __init__.py 的目录；否则顶层 .py 文件 |
| JS/TS | src 下一级子目录；无则逐文件 |
| Go | 每个 package 目录 |
| HTML/页面 | 每页面文件一模块 |
| **上限** | 按 LOC×复杂度排序取 Top 15，其余归"未纳入"如实标注（防 200 文件仓爆预算） |

## 2. 自建靶子项目（demo，半天）

构造 5 模块项目 `data/demo/multi-module-demo`：utils 纯函数（有 docstring）/ api_handler（FastAPI 路由）/ db_access（SQL 调用）/ web/index.html（表单+按钮）/ config.py（纯配置）。每模块植入 1 个已知缺陷（附答案键）——它同时是 E 版对照实验和路线卡-D 的验收场。

## 3. 画像字段（9 维，全静态可得）

语言/类型、LOC、文件数、圈复杂度（radon/gocyclo）、**扇入度**（被 import 次数——核心模块权重）、自带测试有无、Web 入口特征（路由装饰器）、DB 调用特征、纯数据/配置判定（无可测函数→建议跳过）。

## 4. 策略规则表（确定性优先，LLM 只兜底）

| 特征 | 建议路线 | 理由 |
|---|---|---|
| 纯函数+有 docstring | 单元（等价类/边界/PBT） | 输入输出契约清晰 |
| 纯函数+无规格 | 属性+差分 | 无预期值可写 |
| API handler | 契约+场景 | 接口契约可提取 |
| HTML 页面 | UI 交互（任务卡-D 幂等路线） | 只能外部行为测 |
| DB 写入 | 单元+db_assert | 需验证状态变化 |
| 纯数据/配置 | **跳过**（标注"无可测行为"） | 省预算 |
| 复杂度≥C 且扇入高 | 权重×2 优先 | 缺陷高发+影响面大 |

规则未命中的模块 → LLM 语义分类一次（"业务规则/工具/胶水"），**理由必须落库**（可审计）。
