# zcode 总攻计划提示词：从当前状态到答辩（2026-10-31）

> 用途：让 GLM-5.3 / 其他强模型在闲时任务里**先体检、再规划、再自我红队**，产出
> 一份能直接交给下一轮 Agent 执行的总攻计划。重点不是"列阶段"，而是把每个任务
> 拆到有输入、有命令、有验收、有依赖、有降级方案。

## 一、让 LLM 多干活的 7 个写法

1. **先证据后计划**：强制它跑基线、读代码、查库、看 git log；没有证据的现状判断一律标"未验证"。
2. **交付物合同**：明确要求 3 个文件（主计划 / 机器可读 backlog / 首 3 日执行包），不交不算完成。
3. **三段式自我迭代**：初稿计划 → 魔鬼代言人挑刺 → 修订定稿；不允许一次成型就收工。
4. **任务粒度硬约束**：每个任务 ≤ 1 个 Agent 会话（2-3h），必须有"完成判据 + 验证命令"；
   写"继续完善/持续优化"这种任务直接打回。
5. **关键路径 + 砍单清单**：不仅排要做的事，还要明确"为了保答辩，哪些事现在不做"。
6. **双线并行**：工程线（系统/实验）与论文线（写作/评审/格式）分开排，但每周有同步点；
   论文是唯一不可压缩的关键路径，不能被工程挤掉。
7. **交接友好**：计划要能让另一个没读过全仓的 Agent 直接执行——每个任务写清文件、命令、上下文。

```text
任务：从当前状态出发，制定一份"到最终答辩"的可执行总攻计划。你要尽可能多做实际分析，
不要只给高层阶段；没有证据的判断一律标"未验证"。

【最终目标（Definition of Done）】
2027-04-24 初次答辩通过，具体包括：
1. 系统：L1-L4 四级双轨闭环可演示（L1 单元 / L2 集成 / L3 系统半自动 / L4 验收辅助），
   跨级 RTM 溯源链、报告页四级视图、Docker 沙箱、SQLite 台账均可现场演示；
2. 实验：E1-E8 数据齐全且可复现（n≥3 或按设计说明），成本-质量分析、威胁有效性章节有素材；
3. 论文：2.8-3 万字全稿，符合学院格式规范，引用全部来自已核验清单，第 6 章数据可回溯；
4. 答辩：演示脚本、PPT、问答准备、备份演示视频/截图齐备。
硬节点：中期 2027-02-25（L1 完整+L2 可演示+论文初稿）；定稿 2027-04-09；初答辩 2027-04-24。
当前日期 2026-10-31。

【已知状态（只作校准，必须独立复验）】
- HEAD 7397e0b，工作树应干净；pytest 299 passed/1 skipped；module_check 105 OK。

- 外部阻塞：DeepSeek 402，E7/E6/E8 与 L1 存量实验（A1/B1/C1/X6/X7）未跑。
- 历史文档允许保留旧数字；当前口径以 README/AGENTS 为准。

【硬约束】
- 本轮只做分析与规划，不改产品代码、不改实验数字、不提交、不 push、不装依赖。
- 不写真实库 data/test_agent.db；不清理 workspaces；不跑 run_task/run_grid/run_e7 等真实任务链

  git log/status、只读 SQL、文件检索、读取关键文档。

【必读材料】

test_agent/ 目录树、tests/ 目录、scripts/ 入口、最近 20 条 git log。

【执行流程（必须按阶段产出）】
阶段 0 现状审计（约 20 分钟）：
- 跑基线命令并记录原始输出；
- 用只读 SQL 盘点任务/报告/场景/实验台账的真实数据量；
- 看 git log 估算最近开发吞吐（每天提交数、改动规模）；
- 输出"能力矩阵"：最终目标所需能力 × 当前状态（完成/部分/缺失/坏了）× 证据。

阶段 1 差距清单（约 20 分钟）：
把"到最终目标还缺什么"穷举成 4 类：系统能力、实验数据、论文/评审、答辩/行政。
每条 gap 标：严重度、是否关键路径、依赖、可并行性、证据、可能的降级方案。
至少找出 25 条 gap；不要只写 10 条。

阶段 2 总攻计划（约 40 分钟）：
- 先算关键路径（最长依赖链），指出真正的瓶颈（例如论文文风校准/用户时间/实验数据）；
- 再排阶段：现在→中期→定稿→答辩；每阶段有里程碑、演示证据、风险缓冲；
- 任务粒度 ≤1 个 Agent 会话（2-3h）；每个任务必须写：
  ID、目标、输入/文件、执行命令、完成判据、验证命令、依赖、预计工时、
  优先级（P0/P1/P2）、降级方案；
- 工程线与论文线分开排，但每周至少一个同步点；
- 明确"保答辩砍单清单"：哪些功能/实验/章节在时间不足时先砍，砍单顺序要可执行；
- 估算要用本仓实际吞吐校准（复盘说人类估算保守约 3 倍），不要按教科书工期拍脑袋。

阶段 3 魔鬼代言人（约 20 分钟）：
- 找出计划最可能滑铁卢的 5 个原因（用户时间、DeepSeek 余额、论文返工、实验方差、格式/模板）；
- 每条给触发信号、提前预警、缓解动作、降级路径；
- 然后修订计划：删掉不可执行的任务，补上遗漏的依赖，重排优先级。

阶段 4 交付（约 20 分钟）：
写 3 个文件（只写这 3 个）：
1. docs/总攻计划-20261031.md：现状能力矩阵、gap 清单、关键路径、分阶段计划、
   完整任务表、砍单清单、风险登记册、Definition of Done、首 3 日执行包摘要；
2. docs/总攻计划-任务清单.json：机器可读 backlog（id/phase/title/deps/files/commands/
   acceptance/verify/estimate/priority）；
3. docs/总攻计划-首3日执行包.md：未来 3 天每天做什么，逐任务可直接复制给下一轮 Agent。
最后对话只回：关键路径、Top 5 风险、首 3 日任务、3 个文件路径。

【质量门槛（不满足就重做）】
- 每个任务必须有"完成判据 + 验证命令"，禁止"继续完善/持续优化/视情况"。
- 每个里程碑必须有可展示的证据（命令输出/截图/报告文件/测试数）。
- 引用文件必须真实存在；引用命令必须实际可运行或明确标注"需充值后"。
- 数字必须能回溯到 SQL/测试输出/结果文件；不要编造 E6-E8 数据。
- 计划必须能被另一个没读过全仓的 Agent 直接执行；上下文不足的任务要补"必读文件"。
- 至少给出 30 个任务；至少 10 个是 P0/P1；至少 5 条"现在不做"的砍单项。

现在开始：先输出阶段 0 的能力矩阵与基线原始输出，再继续。不要提前结束，不要只给提纲。
```

## 三、如果 LLM 想偷懒，追加这段

```text
检查你刚才的计划：
1. 是否有任务写成"完善/优化/继续推进"而没有完成判据？有就重写。
2. 是否每个任务都能在 1 个 Agent 会话内做完？超过就拆。
3. 是否每条 gap 都有 evidence？没有就补命令或标未验证。
4. 是否排了"论文写作"这条关键路径？没有就重新排。
5. 是否给了首 3 日可复制执行包？没有就补。
6. 是否明确"为了保答辩先不做什么"？没有就补砍单清单。
按以上 6 条修订后再交。
```

## 四、产出后你怎么验货

- 主计划里是否有"能力矩阵 + gap 清单 + 关键路径 + 30 个任务 + 砍单清单"五件套。
- 任务表是否每个都有 `文件 / 命令 / 完成判据 / 验证命令`，而不是只有标题。
- 是否明确指出瓶颈（论文/用户时间/余额），而不是平均用力。
- 首 3 日执行包是否可以直接贴给另一个 Agent 执行。
- backlog JSON 是否能被脚本读取，字段是否齐全。
