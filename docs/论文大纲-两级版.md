# 论文大纲（两级版：稳定版 + 完整版）

> 日期：2026-10-29｜用途：开题报告用稳定版（章级，抗设计演化）；论文撰写用完整版（节级，自由展开）。
> 与开题报告的关系：草稿 docx 中的大纲节保持稳定版粒度即可；本文档是写作期的骨架底稿。

## 一、演化规则（改大纲前先读）

1. **章级锁死**：六章骨架（绪论/理论/总体设计/关键机制/实验/总结）是工程类学位论文标准结构，
   与系统实现怎么演化无关——改章序或砍章会造成开题→中期→答辩叙事断裂，不做。
2. **节级自由**：论文正文的小节结构无人对照开题逐条核对，写作时按材料现状自由展开。
3. **数量词降级为维度词**：大纲字面禁写"九节点/18 表/五种方法/三道闸"这类数出来的清单
   （接 Java、加方法、加表都会让数字作废）；用"测试流程编排/数据模型/设计方法族/质量闸"等维度词。
4. **章级若真需调整**：在中期检查表或论文绪论加一句"相对开题方案的调整及原因"——学术上正常操作，
   显得研究跟着证据走。

## 二、稳定版（开题/中期口径，每章一句范围）

一、绪论：研究背景与意义、国内外研究现状（自动化测试生成、大模型 Agent、测试质量评估三条线索）、本文研究内容与组织结构。

二、相关理论与技术：软件测试过程与用例设计方法理论、大模型与 Agent 编排技术、容器化隔离执行、测试预言问题与变异测试——为后续机制设计提供理论依据。

三、系统总体设计：面向"分析—设计—执行—评估"四阶段的系统架构与分层设计、测试流程编排（主流程与补测闭环）、全链路可追溯的数据模型设计。

四、关键机制设计与实现：围绕"生成可信、修复收敛、执行隔离、评估可靠"四个维度展开——需求驱动的用例生成与质量闸、失败归因与补测闭环（含缺陷如实上报）、容器沙箱执行、确定性评估与报告二次审查。

五、实验与结果分析：容器性能对比、修复策略受控对比、归因有效性标定、报告审查有效性、方法组件消融共五组实验，并讨论有效性威胁与边界。

六、总结与展望。
