# 阶段 B 整理协议模板（B1）+ 月度例行入口（B4）

> 设计真源：docs/agent记忆规划策略.md §11、附录 B。本文件=B1 交付（整理员提示词模板+对账表模板）与 B4 交付（月度入口提示词）。

## 一、整理员提示词模板（每轮整理时粘贴给执行会话）

```text
你是记忆整理员。按《agent记忆规划策略》§11 做一轮整理。

输入：
- 项目 AGENTS.md 的标题层与常量表
- 本期间入池的条目：编号范围 F-____-__ 到 F-____-__（用 forget.py --recall 逐条取，不要整文件读）

你要做的：
1. 按主题聚簇，列出簇清单（簇名 / 包含的编号 / 终态是哪一条）。
2. 每簇写一条记忆行：叙事 ≤200 字符；硬信息进 @ 和 ;# 槽；行尾列出全部编号。
3. 标出被取代的链，只留终态。
4. 硬信息对账：本期间每个数字、路径、决策，标注它现在在哪（常量表的键 / 记忆行的槽 / 判定过期及理由）。
5. 提议哪些"坑"值得进记忆目录或项目经验。只提议。

铁律：
- 不改池里的任何字符。
- 你写的每一个数字、路径、哈希，都必须能在你引用的池条目或常量表里逐字找到。不许推断，不许换算。
- 叙事里不写日期和 commit 号，那些在槽里。
- 输出是提案文件，不是直接改 AGENTS.md。

产出：docs/遗忘池/整理提案-YYYYMMDD.md（簇清单、记忆行、对账表、候选清单）。
```

## 二、硬信息对账表模板

```markdown
## 对账表（本期间 = F-____-__ … F-____-__）

| 硬信息（逐字） | 出处编号 | 现在在哪 | 分类 |
|---|---|---|---|
| 88.7%±5.1pp | F-1123-09 | 常量表「bench3 检出率」；bench3 簇记忆行 ;# 槽 | 常量表+槽 |
| （示例行） | … | … | 常量表 / 槽 / 过期（理由） |

分类三选一：已在常量表 / 已在某条记忆行的槽 / 判定过期并写明理由。
验收：表里不许有"未分类"项。
```

## 三、一轮整理的验收清单（§11.5，审查者用）

- [ ] 全文层不超过 30 行
- [ ] 没有悬空编号：每个被引用的编号都在池里（forget.py --verify 全绿）
- [ ] 叙事全部 ≤200 字符（forget.py --lint 零 L1）
- [ ] 对账表里没有"未分类"项
- [ ] 溯源检查全过（forget.py --check-provenance）
- [ ] 池零改动（git diff docs/遗忘池/pool-*.md 为空）
