## 件 2：A 轨归因精确率验证协议（预注册，执行待批量窗口）

**做什么**：把"归因精确率 ≥80%"从承诺变成可执行的实验设计——协议现在定稿，跑数等低价窗。

**怎么做**：
- **样本**：A 轨真值集（BugsInPy tarball 通道，codeload 已验证可达）扩到 10-15 bug/语言起步（Python 先行）——每个 bug 是"已知真缺陷"（fail-to-pass 口径）；
- **流程**：每个真值 bug 走全链（L1）→ 记录平台归因标签（product_defect/case_defect/env）vs 真值标签 → 2×2 混淆矩阵；
- **指标**：精确率=（归因为 product_defect 且真值=product_defect）/（全部归因 product_defect）——**只测"报缺陷时报得对不对"**（这是大纲承诺的口径），召回率另列；
- **成本对账**：每格 ~20k tok ≈¥0.04，15 格 ≈¥0.6；+差分闸开启（MTA_DIFF_GATE=1）的对照组 +50% token；
- **判据（预注册）**：精确率 ≥80% = 大纲承诺达成；<80% 如实报告+归因分析（哪类真值被误报）。

**为什么这么设计**：①真值先行——没有标准答案的"精确率"是空话，BugsInPy 是唯一有外部真值且通道已验证的来源；②只测精确率不测召回——平台"宁可误报不可造假"的设计哲学下，召回天生受证人机制约束（不知道的缺陷本来就不会报），测了也是口径混乱；③预注册判据——防止跑完后挑好看的子集汇报（历史上 E9 A4 格"需求极薄价值有限"的教训：事后解释的空间要提前锁死）。

**为什么值得做**：答辩最可能被追问的数字（"你说能归因，凭什么？"）——现在唯一的回答是"机制+一个反事实案例"，协议跑完就是混淆矩阵。

## 件 3：六语言对照 n=3 协议（预注册，执行 ~¥4.5）

**做什么**：把昨晚 n=1 的对照实验升级为有方差报告的协议。

**怎么做**：
- 六语言 × 同需求 × **3 次独立采样**（同任务参数三连跑，LLM 采样天然随机）——18 格；
- 报告口径升级：每格报 mean±std（token/覆盖率/用例数），终态判定报 3 中分布（如"3 跑中 2 done 1 真检出"）；
- 与基线（n=1）的对比声明诚实化：基线仍是 n=1，对照侧有方差——结论措辞限定为"方向一致"而非"显著提升"；
- 成本：18 格 × ~16k tok ≈ 29 万 tok ≈ ¥0.6（比预估的 ¥4.5 低——demo 小项目单格 ~10-20k）。

**为什么 3 不更多**：LLM 方差不是正态小方差场景（漂移时段会整批废），n=3 只能给出"稳定还是抖动"的方向性结论；要过显著性检验需要 n≥10/语言 ≈¥2——毕设数据量级下 n=3+诚实措辞是性价比最优解。

**为什么值得做**：n=1 的"token -8.2%"在答辩里一句话就被问倒（"可能是采样波动"）；n=3 的 mean±std 把这句话堵死。

## 件 4：干净语料集标注协议（零 LLM，误报率指标的数据源补缺）

**做什么**：给误报率指标补"分母"——一套**确认无缺陷**的语料清单+判定协议。

**怎么做**：
- 从现有语料选 3-5 个项目标"干净"（依据=①源码静态审读无埋缺陷②历史全链跑全部 pass 且证人=0③代码规模小可人核）——coupon-api/js-calc 是天然候选（demo 自建、行为已知）；
- 每个干净项目跑 M 次全链（这部分要跑数，不在本设计内执行）→ 统计**假缺陷报告数/总报告数**=误报率；
- 真值 manifest 扩展：corpus_truth.json 加 clean_projects 节（语言/判定依据/历史 pass 记录锚点）。

**为什么现在只做设计不做标注**：标注本身零成本但"干净"判据需要跑数佐证（历史 pass 记录），设计先行、跑数并入件 3 的批次顺带完成（同一批任务复用，不额外烧钱）。

**为什么值得做**：八指标里误报率（指标 5）是唯一没有数据源的——聚合器 c92fb3f 建好之后一直缺干净分母；没有它，"检出率高"无法反驳"是不是把好项目也说坏了"的质疑。

## 件 5：驱动器健壮性 v2（本轮直接实施——纯代码零 API）

**做什么**：把两次实锤事故（bugverify 首拍 409 六格假排队 + 18:01 定时进程死亡静默失败）的病根修掉。

**怎么做**：
1. 新建 `data/reports/e10/driver_kit.py` 公共层：
   - `ensure_server()`——点火前自检 server 活（登录探针）+Docker 活（docker info），死了当场报错不静默；
   - `create_and_run()`——创建/确认/run **每步校验响应码**，run 得 409 时读 detail：env_gate 类（环境未就绪）→等待+重试（≤3 次）；其他 409（已排队等）→如实记录不重试；
2. `run_bugverify.py`/`run_l1l2l3_e2e.py` 迁到公共层（两个事故现场）；
3. 单测：409 分流逻辑纯函数化（env_gate 重试/已排队跳过/未知 409 上抛）。

**为什么直接实施不进设计池**：纯代码、零 API、两次真机事故已实锤根因——这类修复的成本是"再出一次事故的钱"。

**为什么值得做**：驱动器是所有批量实验的唯一入口——它不健壮，件 2/件 3 的协议跑批就是建在不地基上。
