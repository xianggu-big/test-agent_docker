## 2. 做对了的（要保持）

1. **耐久文档体系**：AGENTS.md「当前状态」+ 权威蓝图（规划/蓝图/时间表）+ 记忆索引，扛过了至少 3 次上下文压缩与 2 个并行会话，零状态丢失——这是多会话开发能跑通的地基。
2. **审计驱动修复**：每轮"逐行实读 → 清单 → 逐项修 → 单测锁机制 → 回归基线上移"的循环（A1-A12、P1×3、十一轮缺口修复），把"文档声称与实现不符"类隐性 bug 系统性清掉。
3. **数字唯一来源纪律**：论文实验数字只认链路文档聚合表，杜绝多版本数字漂移；decoy 重算时旧数字保留作口径演变证据。
4. **实验先于声称**：E1-E5 每个结论都有可复现脚本与结果文件；"verification-before-completion"抓到过基线过期。
5. **控制变量 + 盲测协议**：用户原创想法被优化成三方隔离协议 + decoy 三分类，成为论文方法论贡献本身。
6. **提交纪律**：每模块/每修复即路径范围化 commit，答辩可直接展示演进（4f4ec3a→至今 100+ 提交）。
7. **用户拍板快速收敛**：两次方向变更都在一天内完成"决策→蓝图→落地计划"，没有反复摇摆。

## 3. 偏差与教训（要修正）

1. **估算系统性保守 3 倍**：搭建计划估 8-11 天实际 3 天；M2 估 11-16 实际 10-30 当天达成。原因：按"人写代码"估的，实际是"有完整上下文的 Agent 写"。→ v2 时间表已按实际吞吐校准，但仍保留缓冲位，避免从一个偏差走向另一个偏差。
2. **初始范围界定过早收窄**：先收窄到"单元测试"再扩展到四级，多了一次方向往返。教训：范围收敛应基于"系统实际能力边界"而非"题目表述的恐惧"——系统本来就是分层的，收窄是伪需求。
3. **实验瓶颈误判**：曾把"DeepSeek 余额"当最大阻塞，实际真瓶颈是 **oracle 侧断言驯化**（corpus-002 全格 0.00 跨 9 格复现）。教训：跑量之前先用最小实验定位瓶颈层，钱解决不了方法论问题——V7 断言独立性才是对症药。
4. **评测脚本自身会骗人**（两次实锤）：旧阅卷器未过滤失败用例致 recall 虚高（0.8→根修 0.4）、decoy 占位项压分母（上限 0.6→重算放开）；假数据两次（bench 缺依赖秒败 0.04s、mutation 仪器假 0）。教训：**评测协议与被测系统一样需要标定**，计时/统计必须带结果有效性守卫。
5. **论文线启动偏晚**：工程超前 2-4 个月时论文还是零。原因：计划沿袭"先系统后论文"直觉，未识别"论文是唯一不可压缩的关键路径"。→ 已修正（论文线 10-30 启动，与工程并行）。
6. **文档与实现漂移**：README 回归行停在 99（实际 223）、module_check 契约停在旧版本、db.py 声称 WAL 实则没设——**"文档声称"必须进守卫**，第十一轮把 module_check 扩到 69 项就是为此。
