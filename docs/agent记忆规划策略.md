# agent记忆规划策略（设计报告）

> **状态**：设计定稿，待他人实施。本文只写"怎么做"。
> **已定决策（用户，2026-11-25）**：路线 A→C→B；每条不超过 200 字符；索引类和具体数字类的重要记忆不能省略。
> **选案过程与调研**：`docs/AGENTS遗忘机制-设计方案三案-20261125.md`。本文是实施真源，两份冲突时以本文为准。
> **适用范围**：所有项目的根目录 `AGENTS.md`。脚本全局一份，池按项目各一份。

## 0. 一页速览

**要解决的问题**：项目 `AGENTS.md` 已约 86,000 字符，加载器只装得下约 57,900 字符（约 103,000 字节）。最老的三分之一每次会话都被无声丢掉，没有索引，也取不回来。

**方案一句话**：把记忆分成"会过期的叙事"和"不过期的硬信息"。叙事写短、按天老化进遗忘池；硬信息进槽、进常量表，永远跟着走；被用到的记忆自动回来。

| 组成 | 做什么 |
|---|---|
| 写入口径 | 每条状态行 = 标题 + 叙事（≤200 字符）+ `@` 槽（路径/编号）+ `;#` 槽（关键数字）。槽不计入 200，不许为凑字数删槽 |
| 常量表 | 硬信息的唯一真源，放 `AGENTS.md` 顶部，≤40 行，原地更新，永不自动遗忘 |
| 三层老化 | 全文层（≤15 天）→ 标题层（≤30 天，标题带槽）→ 冷层（`INDEX.md` + 遗忘池，永久） |
| 两道闸 | 时间只做上限；体积是硬闸：全文层 18,000 字符、标题层 11,000 字符、整文件 36,000 字符 |
| 四道保证 | 写时入槽 → 老化时槽随行 → 整理时对账 → 原文永在池 |
| 三个阶段 | A 机械轮转（脚本）→ C 自动召回与再加热（钩子）→ B 睡眠整理（AI） |

**阶段 A 的交付物**：`~/.zcode/cli/hooks/forget.py`、两处钩子注册、全局协议改写、首次迁移。**首次迁移的原则是"先入池、后改写"**：先把现有 109 条原句逐字节存进池，再改写热条目。这样改写再怎么出错，原文也在。

**执行方式：三个阶段一次做完，实施者不停下来等人。** 阶段之间只设机器闸门（§9.2），过了就自动进入下一阶段。原本需要你审的两处（首次迁移的差异、首轮整理的提案）改成自动应用、单独提交、留档供事后审，随时可回滚。只有遇到应变协议里的硬边界、或同一个问题修 3 轮没修好，才停下来写卡点报告。

## 1. 目标与原则

**目标**

1. 任何会话开始时，系统提示里的项目记忆不超过 36,000 字符，并且含当前需要的全部硬信息。
2. 任何被移出全文层的条目，凭编号都能取回原文。
3. 重要记忆（索引类、数字类）不因为压缩、老化、改写而丢失。
4. 老化和召回本身不花 token。

**原则**

| # | 原则 | 落在哪里 |
|---|---|---|
| P1 | 存储无损，展示有损 | 池逐字节保存；索引和注入可以截断 |
| P2 | 叙事会过期，硬信息不过期 | 硬信息只会被新值取代，不按天淘汰 |
| P3 | 时间做上限，体积做硬闸 | §5 的两道闸 |
| P4 | 用进废退 | 阶段 C 的再加热 |
| P5 | 自动动作可预演、可校验、可回滚 | dry-run、`--verify`、备份、git |
| P6 | 引用而不是复制 | 超预算的内容落文件，条目里只留路径 |
| P7 | 一个数字只有一个真源 | 常量表；其他地方只指向它 |

P1 是你在 `progress.py` 注释里立过的原则。P6 来自 Cursor 规则文档的 "Reference files instead of copying their contents"。P2 的依据是 LangMem 把语义记忆和情景记忆分成两种集合管理，见[文档](https://langchain-ai.github.io/langmem/)。

## 2. 记忆地图

先说清"什么东西放哪里"，否则遗忘机制只会把混乱搬进池里。

| 记忆类型 | 例子 | 存放地 | 生命周期 | 谁写 |
|---|---|---|---|---|
| 规则 | 硬规则、长期指令、写入口径 | 全局 `AGENTS.md`；项目 `AGENTS.md` 顶部的 `🔴` 与 `[钉]` 条目 | 只有人能改 | 人 |
| 硬信息 | 读数、路径、决策、约束、待办 | 项目 `AGENTS.md` 的常量表 | 原地更新，旧值进池 | 会话在收尾时写；阶段 B 的整理员写 |
| 事件 | 做了什么、为什么、踩了什么坑 | 项目 `AGENTS.md` 的当前状态 → 标题层 → 遗忘池 | 三层老化 | 会话在收尾时写 |
| 经验 | 每轮问了什么、得到什么 | `项目经验.md` | 只追加，不进系统提示 | 钩子自动追加，人偶尔精炼 |
| 工作材料 | 设计稿、台账、完工报告 | `docs/` | 项目文件 | 会话 |

**三条防重复的规定**

1. 数字只在常量表维护。状态行和记忆索引可以引用，但要指向常量表的键。
2. 记忆目录（`MEMORY.md` 及其主题文件）只放指针，指向常量表和 `docs/`。
3. `项目经验.md` 是流水，不读回系统提示。

**预算**（加载截断线约 57,900 字符 / 103,000 字节）：

| 部分 | 预算 | 说明 |
|---|---|---|
| 标题 + 硬规则 | 2,000 字符 | 现有 1 条 `🔴` + 2 条 `[钉]` |
| 常量表 | 40 行，8,000 字符 | 四组各 ≤10 行，典型 4,000 |
| 当前状态（全文层） | 18,000 字符 | 约 15 天 |
| 遗忘索引（标题层） | 11,000 字符 | 约 30 天 |
| 指针行 | 500 字符 | |
| **整文件上限** | **36,000 字符** | 截断线的 62% |

**天数是怎么来的**：保留天数 = 预算 ÷ 日均增量。按下文的写入口径，一条平均约 280 字符：

| 每天写入条数 | 全文层日增 | 15 天后 | 结果 |
|---|---|---|---|
| 2 | 560 | 8,400 | 富余 |
| 4.2（近 26 天实测均值） | 1,180 | 17,600 | 刚好在预算内 |
| 6 | 1,680 | 25,200 | 超预算，体积闸提前下沉，实际留约 10 天 |

脚本每月重算：

```
全文天数 = clamp(18,000 ÷ 近 14 天全文层日均字符, 5, 15)
标题天数 = clamp(11,000 ÷ 近 14 天标题层日均字符, 15, 45)
```

## 4. 写入口径：200 字符规则与硬信息豁免

### 4.1 条目模板

```
- **<图标> <标题>（YYYY-MM-DD）**：<叙事> @<路径或编号>;#<关键数字>
```

| 部分 | 规则 | 上限 |
|---|---|---|
| 标题 | 写"对象 + 结果"。不带日期、commit 号、括号补充 | 30 字符 |
| 叙事 | 结论句在前，理由或坑在后。可以没有 | **200 字符** |
| `@` 槽 | 路径、文件名、任务号、卡片号、commit、池编号。多项用 `；` 分隔 | 120 字符 |
| `;#` 槽 | 读数、成本、阈值、版本、有时效的日期。多项用 `；` 分隔 | 100 字符 |
| 可选标记 | `[钉]`（钉住）；`原文 F-MMDD-NN`（改写自池中原文）；`[取代:F-…]`（阶段 B 用） | |

**叙事字符数怎么数**：从 `**：` 之后，数到第一个 ` @` 或 ` ;#` 之前。槽不计入。脚本用 Python `len()`。

**为什么用 ` @` 和 `;#` 这种纯 ASCII 标记**：这个项目踩过十几次 GBK 编码坑。标记只用 ASCII，脚本就不会在 Windows 控制台或非 UTF-8 编辑器里出问题。脚本自己的输出一律用 UTF-8，并对无法编码的字符做替换。

### 4.2 什么必须进槽

| 类 | 例子 | 什么时候必须进 |
|---|---|---|
| 路径 | `docs/…`、`data/reports/…`、`test_agent/…:行号` | 结论依赖的那份真源 |
| 编号 | `#2601-2603`、`T3`、`Q4`、commit 短哈希、`F-1120-07` | 复查时要凭它找到东西 |
| 读数 | `88.7%±5.1pp`、`189/213`、`1508 绿 1 skip` | 会写进论文、报告、答辩的数字 |
| 成本与预算 | `≈¥1.12/40 格`、`停车线 ¥5` | 涉及花钱 |
| 阈值与版本 | `窗口∈(0.5,1.0)s`、`v2`、`39 张表` | 以后要拿来对比 |
| 日期 | 拍板日、截止日 | 有时效的决策 |

不进槽的：过程数字（试了几次、第几轮）、能从真源重新查到的中间量。

### 4.3 "不能省略"靠四道保证

| # | 保证 | 谁来做 | 机制 |
|---|---|---|---|
| G1 | 写时入槽 | 写状态行的会话 | §4.1 的模板；lint 检查（§7） |
| G2 | 老化时槽随行 | 脚本 | 条目降到标题层时，`@` 和 `;#` 槽原样带进索引行；再降到 `INDEX.md` 也带着 |
| G3 | 整理时对账 | 阶段 B 的整理员 | "硬信息对账表" + 数字溯源检查（§10） |
| G4 | 原文永在池 | 脚本 | 逐字节保存 + sha256 校验 + 自动召回 |

### 4.5 常量表的行

```
- <键>｜<值>（YYYY-MM-DD）→ <真源路径>
```

- 四组固定、顺序固定：读数 / 路径 / 决策与约束 / 待用户。
- 一个键一行。值变了就原地改这一行，旧行追加到 `docs/遗忘池/常量表历史.md`。
- 每行不超过 200 字符。

### 4.6 收尾三步（写进全局协议，所有会话都执行）

1. 按模板写状态行。
2. 过 lint。钩子会自动检查并提醒；也可以手动跑 `forget.py --lint`。
3. 有新读数、新路径、新决策，就更新常量表对应的行。

## 5. 条目生命周期与老化规则

```
 写入（合规条目）
      │
      ▼
 ┌────────────┐ 超过 N_full 天，或全文层超预算 ┌────────────┐ 超过 N_title 天，或标题层超预算 ┌──────────────┐
 │ 全文层      │ ───────────────────────────▶ │ 标题层      │ ───────────────────────────▶ │ 冷层          │
 │ 当前状态    │ ◀─────────────────────────── │ 遗忘索引    │ ◀─────────────────────────── │ INDEX.md+池  │
 └────────────┘   阶段 C：被用 ≥2 个日子，      └────────────┘   阶段 C：被用到，回到标题层      └──────────────┘
                  以"复活行"升回                                                    并重新计龄
```

原文在第一次下沉（全文层 → 标题层）时进池。此后全文只存在于池里。

### 5.1 参数

| 参数 | 默认 | 含义 |
|---|---|---|
| `FULL_DAYS` | 15 | 全文层保留上限（天），每月自适应重算 |
| `FULL_BUDGET` | 18,000 | 全文层预算（字符） |
| `TITLE_DAYS` | 30 | 标题层保留上限（天），每月自适应重算 |
| `TITLE_BUDGET` | 11,000 | 标题层预算（字符） |
| `TABLE_MAX_LINES` | 40 | 常量表行数上限 |
| `FILE_CAP` | 36,000 | 整文件上限（字符） |
| `FRESH_DAYS` | 2 | 这么多天内的条目不被体积闸下沉 |
| `REHEAT_DAYS` | 3 | 阶段 C：这么多天内被用过算"热" |
| `REVIVE_DAYS` | 2 | 阶段 C：被用超过这么多个不同日子，升复活行 |
| `RECALL_TOP_K` | 3 | 阶段 C：一次最多召回条数 |
| `RECALL_CAP` | 2,500 | 阶段 C：注入封顶（字符） |
| `RECALL_MIN_SCORE` | 5 | 阶段 C：召回分数线 |

参数放在 `~/.zcode/progress/forget.json`。项目可以在根目录放 `forget.json` 覆盖任意一项。

### 5.2 下沉的顺序

每次整理按下面的顺序执行，全部幂等：

1. **时间闸**：全文层里超过 `FULL_DAYS` 且未钉住的条目，从最旧的开始下沉。标题层同理。
2. **体积闸**：全文层仍超过 `FULL_BUDGET`，继续从最旧的未钉住条目下沉，直到达标。`FRESH_DAYS` 内的条目不动；实在降不下来，在文件头插一行 `[记忆超载]` 提醒，不硬删。标题层同理。
3. **整文件闸**：仍超过 `FILE_CAP`，同样只提醒不硬删。

### 5.3 钉住

只认两种：`🔴` 开头；标题里带 `[钉]`。`▶️` 不自动钉，因为多数是过期的"进行中"标记。首次迁移时，把两条长期指令手工加上 `[钉]`。

### 5.4 解析不了的行

没有日期、或不符合 `- **…**：` 形态的行，脚本一律不归档，只在 `--stats` 里报出来。

## 6. 遗忘池与索引

每个项目一份，放在项目仓库里，进 git。

```
docs/遗忘池/
  pool-2026-11.md        # 按月一个文件，只追加
  INDEX.md               # 总索引
  常量表历史.md           # 常量表被替换掉的旧行
  archive.log            # 每次整理的记录
  heat.jsonl             # 阶段 C：热度日志
```

**池里的每一条**

```
<a id="F-1120-07"></a>
## F-1120-07 · 2026-11-20 · ✅ G7-G10 真机格补跑收官
<!-- archived=2026-11-28 from=AGENTS.md chars=1204 sha256=… -->
- **✅ G7-G10 真机格补跑收官（2026-11-20 晚，……）**：……（原句整行，逐字节）……
```

**编号**：`F-月日-序号`，按原条目的日期编，同一日期内按出现顺序。短、可排序、可 grep。

**INDEX.md 的一行**

```
| F-1120-07 | 2026-11-20 | G7-G10 真机格补跑收官 | @docs/… | #2 核心 PASS | 2 次用到 | pool-2026-11.md |
```

**三条硬规定**

1. 池只追加，不改写。`--verify` 逐条重算 sha256。
2. 池文件按月约 100–150 KB。**永远不整文件读进上下文**，只按编号取。
3. 复活是把原句复制回全文层作为新条目，并注明"（复活自 F-1120-07）"。池里那份不动。

## 7. 脚本 forget.py

全局一份：`C:/Users/xianggu/.zcode/cli/hooks/forget.py`。用 `ZCODE_PROJECT_DIR` 定位项目（与 `progress.py` 同一做法）。

### 7.1 命令

| 命令 | 作用 |
|---|---|
| `forget.py`（无参数） | 钩子模式：从 stdin 读事件 JSON，按事件分发 |
| `--dry-run` | 只打印整理计划，不写任何文件 |
| `--apply` | 立即整理一次 |
| `--lint` | 检查写入口径，列出不合规的行 |
| `--recall F-MMDD-NN` | 打印一条原文 |
| `--grep <词>` | 在标题、槽、INDEX.md 里搜，打印命中条目的原文 |
| `--touch F-MMDD-NN` | 记一次"被用到" |
| `--verify` | 校验 sha256；检查索引行与池条目一一对应 |
| `--stats` | 各层字符数、自适应天数、近 14 天增速、池大小、不合规行 |
| `--recall-audit` | 阶段 C：列出近期的自动召回命中记录，供事后抽查 |

### 7.2 内部结构

| 函数 | 职责 |
|---|---|
| `parse_entry(line)` | 解析出日期、标题、叙事、两个槽、标记；解析不了返回空 |
| `parse_document(text)` | 把文件切成五块：硬规则 / 常量表 / 全文层 / 标题层 / 指针行 |
| `plan(doc, now, cfg)` | 按 §5.2 算出要下沉、要滚动的条目 |
| `apply(plan)` | 原子写入；追加池；写 archive.log |
| `lint(doc)` | §7.4 的七条规则 |
| `recall` / `grep` / `touch` / `verify` / `stats` | 对应命令 |
| `match_recall(prompt, rows)` | 阶段 C：打分召回 |
| `check_provenance(line, pool, table)` | 阶段 B：数字溯源检查 |

### 7.3 安全

- 钩子模式下**永远退出码 0**，所有异常写进 `~/.zcode/progress/_forget.log`。绝不阻断会话。
- 写文件先写临时文件再替换。
- 检测到合并冲突标记（`<<<<<<<`）就跳过，并记日志。
- 改写前留最近 3 份备份到 `~/.zcode/progress/backup/`。
- 有 `forget.lock` 就跳过。
- 文件读写一律显式 `encoding="utf-8"`。

### 7.4 lint 的七条规则

| # | 规则 | 级别 | 提示语要点 |
|---|---|---|---|
| L1 | 叙事超过 200 字符 | 错误 | 压到 200 以内；硬信息移到槽，不许删 |
| L2 | 叙事里出现路径或 commit 哈希 | 警告 | 索引类信息应进 `@` 槽 |
| L3 | 叙事里出现带单位的读数 | 警告 | 具体数字应进 `;#` 槽，或进常量表 |
| L4 | 标题超过 30 字符，或以日期开头 | 警告 | 标题要写成将来的索引 |
| L5 | 解析不出日期 | 错误 | 这一行永远不会被自动归档 |
| L6 | 常量表行超过 200 字符，或缺 `｜`、缺日期 | 警告 | |
| L7 | 槽超长 | 警告 | 超出的内容落文件，槽里只留路径 |

lint 只提醒，不阻断。`UserPromptSubmit` 钩子每个会话最多提醒一次，格式如下：

```
[记忆规范] 上一轮写入的条目有 2 处不合规：第 12 行叙事 312 字符（L1）；第 14 行正文含路径（L2）。请在本次收尾前改写，口径见《agent记忆规划策略》§4。
```

"上一轮写入的条目"靠快照判定：把上次 lint 时每行的哈希存进 `~/.zcode/progress/forget_state.json`，只报新增或改动的行。

## 8. 钩子接线

ZCode 一共七个钩子事件，没有压缩前事件；`SessionStart` 只在启动和恢复时触发（依据：钩子文档、`progress.py` 注释里的引擎源码结论）。所以"自动整理"的含义是**每次开新会话时整理**。

### 8.1 配置

在 `~/.zcode/cli/config.json` 的 `hooks.events` 里，于现有 `progress.py` 旁各加一项：

```json
"SessionStart": [
  { "matcher": "startup|resume",
    "hooks": [
      { "type": "command", "command": "D:/Users/xianggu/anaconda3/python.exe C:/Users/xianggu/.zcode/cli/hooks/progress.py" },
      { "type": "process", "command": "D:/Users/xianggu/anaconda3/python.exe",
        "args": ["C:/Users/xianggu/.zcode/cli/hooks/forget.py"], "timeoutMs": 8000 }
    ] }
],
"UserPromptSubmit": [
  { "hooks": [
      { "type": "command", "command": "D:/Users/xianggu/anaconda3/python.exe C:/Users/xianggu/.zcode/cli/hooks/progress.py" },
      { "type": "process", "command": "D:/Users/xianggu/anaconda3/python.exe",
        "args": ["C:/Users/xianggu/.zcode/cli/hooks/forget.py"], "timeoutMs": 4000 }
    ] }
]
```

### 8.2 事件契约（与 `progress.py` 一致）

- stdin 是事件 JSON。字段：`hook_event_name`、`session_id`、`transcript_path`、`cwd`。
- 输出是一个 JSON 对象，原样照抄 `progress.py` 的写法，并设 `ensure_ascii=True`：

```json
{"hookSpecificOutput": {"hookEventName": "SessionStart", "additionalContext": "…"}}
```

- **输出上限是 32,768 字节，超限会被静默丢弃**。中文经转义后每字占 6 字节，所以注入正文必须控制在 4,000 字符以内。这是把自动召回封顶定在 2,500 字符的原因。

### 8.3 两个事件各做什么

| 事件 | 阶段 A | 阶段 C 追加 |
|---|---|---|
| `SessionStart` | 整理一次；有动作时注入一行摘要 | 同左 |
| `UserPromptSubmit` | lint 提醒，每会话最多一次 | 自动召回 + 记热度 |

摘要的格式：`[记忆整理] 归档 5 条进遗忘池（F-1105-01…05）；滚动 12 条标题进 INDEX.md；AGENTS.md 现 23,400 字符。`

### 8.4 需要先验证的两点

1. 同一事件挂两个钩子、各自返回 `additionalContext` 时，两段是否都被注入。若不是，改为在 `progress.py` 里 `import forget`，合并成一份输出。
2. `PostToolUse`（匹配 `Read`）的 payload 里是否带被读文件的路径。带的话，阶段 C 可以多一个热度来源：AI 读了池文件里某一条，就记一次 touch。不带就省略这个来源。

## 9. 阶段 A：机械轮转

### 9.1 任务卡

| 卡 | 交付物 | 验收 |
|---|---|---|
| A1 解析器 | `parse_entry`、`parse_document` | 用现有 `AGENTS.md` 当夹具：110 行里解析出 110 个日期和标题；叙事、槽、标记的边界各有一例单测 |
| A2 老化引擎 | `plan`、`apply` | 时间闸、体积闸、钉住、索引滚动各有单测；连跑两次第二次零改动；注入冲突标记时拒绝写入；备份恰好 3 份轮换 |
| A3 工具命令 | `--dry-run`、`--apply`、`--recall`、`--grep`、`--verify`、`--stats` | dry-run 的计划与 apply 的结果一致；篡改池里一个字符后 `--verify` 报错 |
| A4 lint | `lint` 及七条规则 | 每条规则一个正例一个反例；只报新增或改动的行 |
| A5 钩子接线 | §8.1 的配置 + 契约测试 | 喂样例 stdin，输出是合法 JSON；任何输入下退出码都是 0；耗时 < 1 秒；§8.4 第 1 点有结论 |
| A6 协议改写 | 全局 `AGENTS.md` 换成附录 A 的文本 | 改之前先备份原文件（全局文件不在 git 里）；只替换第 2、5 条并新增第 6–8 条，其余原样；留一份差异摘要供事后审 |
| A7 首次迁移 | §9.3 的 M1–M6 | §9.4 的验收 |
| A8 未迁移项目的保护 | §9.5：第一次遇到就全量入池；每次会话提醒一次 | 用另一个项目 `AGENTS.md` 的副本当夹具：跑完后池里有全部原句、`--verify` 全绿、提醒文案只出现一次 |

测试放在 `~/.zcode/cli/hooks/tests/test_forget.py`，用 `python -m pytest` 单独跑。**不要放进项目仓库的 `tests/`**，那会改变项目的 pytest 基线。测试目录里放一个只含 `[pytest]` 的 `pytest.ini`，运行时把 `--rootdir` 和 `--confcutdir` 都指到这个目录：在仓库之外跑 pytest，根目录会被推断到系统盘的祖先目录，撞上"拒绝访问"（2026-11-25 实测过两次）。

### 9.2 阶段之间的闸门

闸门是机器可验证的条件，不是"跑满几天"或"等用户发话"。过了就自动进入下一阶段；不过就按应变协议的六步循环修；同一个问题修 3 轮没修好，才停下来写卡点报告。

| 从 | 到 | 条件（全部满足） |
|---|---|---|
| A | C | A1–A8 全部验收；在真实的 `AGENTS.md` 和池上 `--verify` 全绿、lint 零错误；§8.4 第 1 点有结论 |
| C | B | C1–C5 全部验收；离线回放评测达标（显式编号 100% 命中、抽检准确率 ≥ 70%） |

为什么不需要等真实使用天数：自动召回的准不准，可以拿 `项目经验.md` 里本项目 412 条历史提问离线回放来测（C3）；再加热的三条规则用合成的热度日志就能测（C5）。

### 9.3 首次迁移：先入池，后改写

| 步 | 做什么 | 谁 |
|---|---|---|
| M1 | `git commit` 现状；把 `AGENTS.md` 另存一份 `AGENTS.pre-migration.md` | 人或执行者 |
| M2 | **全量入池**：把现有 109 条原句逐条写进池并编号，生成 `INDEX.md`。`--verify` 应报 109/109 | 脚本 |
| M3 | **生成骨架**：硬规则区（`🔴` 一条 + 两条 `▶️` 加 `[钉]`）；常量表空壳（四组）；标题层放 15 天以前的 46 条（标题 + 日期 + 编号）；全文层放 15 天以内的 63 条原样，每条标 `原文 F-…`；末尾指针行 | 脚本 |
| M4 | **改写**：① 从 109 条里提炼常量表（读数、路径、决策、待用户，每行带真源路径）；② 把 63 条热条目改写成模板，保留 `原文 F-…` 标记；③ 给 46 条索引行补槽 | AI 会话，一次专门任务 |
| M5 | **机器核对**：数字溯源检查、路径存在性检查、lint 全过、`--verify` | 脚本 |
| M6 | **自动应用并单独提交**。同时生成一份差异摘要（改了哪些行、常量表新增哪些键），留档供事后审。没通过 M5 机器核对的行，保留原文不改 | 脚本 |

**为什么这样安全**：M2 一做完，今天的 `AGENTS.md` 就已经逐字节在池里了。M4 的改写是在"原文已有保底"的前提下做的。改写行带着 `原文 F-…`，老化时脚本直接复用这个编号，不会在池里产生第二份。

### 9.4 首次迁移的验收

- `--verify`：109 条原句全部在池，哈希一致。
- 新文件每一行里的数字、路径、哈希，都能在池或常量表里找到出处。
- 新 `AGENTS.md` 不超过 30,000 字符（估算：常量表约 4,000 + 63 条 × 约 300 + 46 条索引 × 约 85）。
- 每条索引行与池条目一一对应。
- lint 零错误。

### 9.5 还没迁移的项目

脚本是全局的，一接线就对所有项目生效，但 §9.3 的迁移只做当前这一个。别的项目的 `AGENTS.md` 还是旧格式，没有槽。处理办法是不让它等迁移：

- **第一次遇到就全量入池。** 某个项目的 `AGENTS.md` 还没有对应的 `docs/遗忘池/` 时，脚本先做 M2：把现有条目逐条入池并编号，`--verify` 通过后才继续。
- **之后照常老化。** 标题取加粗头部。旧格式条目没有槽，索引行里就只有标题，硬信息留在池里，凭编号可取回。
- **每次会话提醒一次。** 只要该项目还有旧格式条目，`SessionStart` 注入一行：`[记忆整理] 本项目 AGENTS.md 尚未迁移（N 条旧格式）。迁移做法见《agent记忆规划策略》§9.3 的 M3–M6`。
- **迁移逐个项目做。** M3–M6 可以交给闲时任务，一次一个项目，不需要你参与。

## 10. 阶段 C：自动召回与再加热

### 10.1 自动召回

`UserPromptSubmit` 钩子里做，顺序如下：

1. **取提问文本**。与 `progress.py` 相同：先读 transcript 里最后一条用户消息，读不到再用 payload 的 `prompt` 字段。
2. **抽取查询词**。
   - 显式编号：`F-\d{4}-\d{2}`、`#\d{3,4}`、`task_\d+`、卡片号 `[TQPG]\d{1,2}`。
   - 英文词：长度 ≥ 3，转小写，去停用词。
   - 中文词组：对提问里的中文串取全部 2 字和 3 字片段，去掉停用片段（怎么、什么、这个、可以、一下、需要……）。
3. **给候选打分**。候选是标题层的行和 `INDEX.md` 的行。

| 信号 | 分值 |
|---|---|
| 显式编号命中 | 10 |
| 英文词命中，且该词出现在不超过 20% 的候选里 | 每个词 3 |
| 中文片段命中 | 每个 1，封顶 6 |
| 标题整串出现在提问里 | 另加 5 |

   分数 ≥ `RECALL_MIN_SCORE` 才算命中。取前 `RECALL_TOP_K`，同分取日期最近的。
4. **注入**。总量封顶 `RECALL_CAP`，单条截到 800 字符：

```
[自动召回] 本次提问命中 2 条已遗忘的记忆（原文节选；完整原文：python forget.py --recall <编号>）
◆ F-1120-07 G7-G10 真机格补跑收官（2026-11-20）
  <原句前 800 字符>…
◆ F-1123-02 …
```

5. **记热度**。每条命中往 `heat.jsonl` 追加一行：`{"id":"F-1120-07","ts":"2026-11-25T23:10:00","src":"prompt","score":9}`。
6. **去重**。同一会话最近 3 轮已注入过的条目不再注入。

开关：`FORGET_AUTO_RECALL=0` 关闭。另有只记录不注入的调试模式，用来事后调阈值。

### 10.2 再加热

| 规则 | 做法 |
|---|---|
| 热条目重新计龄 | 近 `REHEAT_DAYS` 内被用过的条目，老化时钟从最近一次被用算起。索引行末尾追加 ` ↻11-25` |
| 冷层回标题层 | 冷层条目被用到，索引行回到 `AGENTS.md` 的标题层，带 `↻` 标记 |
| 复活行 | 被用超过 `REVIVE_DAYS` 个不同日子，以"复活行"升回全文层：标题 + 一句话 + 槽，叙事 ≤ 200，并注明"（复活自 F-…）" |
| 全文不回热 | 原文不自动回全文层，保护体积。需要常驻时由会话手工复制 |

### 10.3 任务卡

| 卡 | 交付物 | 验收 |
|---|---|---|
| C1 热度日志 | `touch` 命令；`heat.jsonl` 读写 | 重复 touch 只追加不去重；损坏的一行不影响其余 |
| C2 匹配器 | `match_recall` | 显式编号 100% 命中；无命中时不注入；注入量永不超封顶 |
| C3 离线回放评测 | 评测脚本 + 报告 | 用 `项目经验.md` 里本项目 412 条历史提问回放；随机抽 50 条命中，由实施者标注相关与否并列成清单（留给你事后抽查），准确率 ≥ 70%；单次匹配 < 50 毫秒 |
| C4 开启自动召回 | 更新 forget.json；保留"只记录不注入"的调试开关；`--recall-audit` 命令 | 阈值按 C3 的报告定；C3 通过后立即开启，不等真实使用天数 |
| C5 再加热 | 重新计龄、冷层回归、复活行 | 三条规则各有单测；用合成的热度日志驱动，不依赖真实使用 |

### 10.4 一个必须写进协议的事实

钩子注入的内容是消息，不是系统提示，**会被下一次压缩吃掉**。召回来的内容如果这一轮很重要，会话要把它落盘成复活行。

## 11. 阶段 B：睡眠整理

### 11.1 什么时候跑

- **首轮**：首次迁移（§9.3）完成后立即执行。那时池里已经有 100 多条可整理，不需要等。
- 每月一次闲时任务。
- 触发条件：距上次整理，池里新增 ≥ 60 条；或标题层用量 ≥ 预算的 80%。

### 11.2 流程

| 步 | 做什么 | 产出 |
|---|---|---|
| 1 | 跑阶段 A 的整理，提交 | 一个干净的起点 |
| 2 | 读标题层、常量表、本期间的池条目（按编号取，不整文件读） | |
| 3 | 按主题聚簇。依据：同一对象、同一任务卡、同一缺陷家族、同一文档谱系 | 簇清单 |
| 4 | 每簇写一条记忆行：终态 + 原因 + 坑 + 指向的编号。叙事 ≤ 200，槽照常 | 记忆行 |
| 5 | 标出被取代的链，只留终态，其余编号收进"含前史" | |
| 6 | **硬信息对账**：本期间池条目里的每个数字、路径、决策，三选一——已在常量表 / 已在某条记忆行的槽 / 判定过期并写明理由 | 对账表 |
| 7 | 提议哪些"坑"进记忆目录或 `项目经验.md`。只提议，不自动写 | 候选清单 |
| 8 | 产出提案文件；数字溯源检查通过后直接应用；单独一个提交。提案文件留档，供事后审 | `docs/遗忘池/整理提案-YYYYMMDD.md` |

### 11.3 防错

| 措施 | 做法 |
|---|---|
| 池不可改 | 整理员只能写索引行、常量表行、记忆行，且每行必须引用池编号 |
| 数字溯源 | 新写的每一行里的数字、路径、哈希，必须能在它引用的池条目或常量表里逐字找到。`check_provenance` 报错就拒绝 |
| 先审后用 | 应用前，由一个没看过实现上下文的审查者（子代理或新会话）按 §11.5 的验收清单过一遍，相当于 Letta 的 Dreaming 的"应用前再审一遍"。提案文件留档，你随时可以事后审、随时回滚 |
| 行数守卫 | 整理后全文层若不降反升，回滚 |

### 11.4 任务卡

| 卡 | 交付物 | 验收 |
|---|---|---|
| B1 整理协议 | 整理员提示词模板（附录 B）+ 对账表模板 | 两份模板落盘，并对照 §11.2 的八步逐条齐全 |
| B2 数字溯源检查器 | `check_provenance` | 编造一个数字能被抓到；改写但数字照抄能通过 |
| B3 首轮整理 | 第一份提案 + 对账表 | 硬信息对账 100% 分类；无悬空编号；提案与对账表留档 |
| B4 例行化 | 每月闲时任务的入口提示词 | |

### 11.5 一轮整理后的验收

- 全文层不超过 30 行。
- 没有悬空编号：每个被引用的编号都在池里。
- 叙事全部 ≤ 200 字符。
- 对账表里没有"未分类"项。

## 12. 观测与调参

每周看一次 `forget.py --stats`：

| 指标 | 健康范围 | 不健康时怎么调 |
|---|---|---|
| 全文层字符数 / 预算 | < 80% | 连续 3 周顶到预算：收紧叙事，或把 `FULL_DAYS` 上限降到 10 |
| 标题层字符数 / 预算 | < 80% | 索引行槽太长：把长内容落文件，槽里只留路径 |
| lint 不合规率 | < 10% | 提醒语加示例 |
| 自动召回抽检准确率 | ≥ 70% | 提高 `RECALL_MIN_SCORE` |
| 60 天内从未被用到的池条目占比 | 观察值 | 越高说明老化越可以更激进 |
| `--verify` | 全绿 | 任何一次红：立即停用钩子，从备份恢复 |

## 13. 风险与对策

| 风险 | 对策 |
|---|---|
| 钩子改写 `AGENTS.md` 时，编辑器里开着未保存的旧版本 | 只在会话启动时整理；整理后注入摘要提醒；3 份备份；git |
| lint 提醒变成噪音 | 每会话最多一次；只报新增或改动的行 |
| 自动召回注入无关内容 | 分数线、封顶、去重；回放评测不过就不开 |
| 整理员摘要失真 | 先入池后改写；数字溯源；独立审查者过一遍；单独提交；提案留档供事后审 |
