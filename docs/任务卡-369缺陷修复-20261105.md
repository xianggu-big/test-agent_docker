## 二、任务详情

### A1【P0】classify_failure 补 TypeError/ReferenceError → case_defect

- **根因**：`graph/repair.py:16` `CASE_OWN_DEFECT_ERRORS` 集合与 `:122` classify_failure
  正则均无 TypeError/ReferenceError。该集合有 **3 处同口径消费点**，必须联动：
  1. `repair.py:122` classify_failure → 归类（369 误诊点）
  2. `skills/gen_tests.py:690` ②定向修复剪除（TypeError 失败用例现不会被剪除重建）
  3. `skills/repair_strategy.py:83` 修复策略分流
- **方案（带防反向误诊的共现约束，非裸加）**：classify_failure 的 case_defect 分支追加
  规则——文本含 `TypeError|ReferenceError` **且** 同文本共现用例侧标记
  （`evalmachine|test_gen_r|test_imported|test_gen_fb`，即错误堆栈指向用例文件/vm 沙箱）
  → case_defect。裸 TypeError 共现被测源文件路径的不动（保留 product_defect 可能）。
  集合本身（①②③剪除口径）加 `"TypeError", "ReferenceError"`——剪除只作用于
  agent_file（test_gen_r*/test_imported 前缀已有守卫，自带测试不受影响）。
- **旗标决策**：**不挂旗标**。这是既有启发式集合的缺项修补（369 实锤的 oversight），
  属 bug fix 非新特性；防造假证人语义（AssertionError→product_defect）不动。
- **验收（369 确定性重放，零容器）**：单测用 369 四条真实错误消息
  （`TypeError: Assignment to constant variable` + `evalmachine.<anonymous>:1` 堆栈）
  断言：修复前 classify_failure→product_defect、修复后→case_defect；
  `decide()` 端到端：修复前 stop（疑似产品缺陷）、修复后 repair_gen（round_no=2 预算内）。
  保留证据=修复前失败/修复后通过两态单测。
- **量**：~1.5h（含单测 4-6 个）。**风险与诚实边界**：产品抛 TypeError 且堆栈无用例
  标记的场景仍归产品侧（共现约束已收窄）；A2 进一步精确化。

### B1【P1】JS 自导自演静态闸（文本启发式）

- **根因**：_static_filter 对 JS 跳过（无 AST 闸），生成用例可对导出数据数组重新赋值
  （`QUESTIONS = QUESTIONS.filter(...)`）自测自演——JS 侧无任何生成后审计。
- **方案**：gen_tests 生成后、写盘前，对 JS code 文本检测（正则启发式，无新依赖）：
  1. 顶层对全大写导出标识符的重新赋值：`^\s*(?:const|let|var)\s+[A-Z][A-Z_0-9]+\s*=\s*[^=]`
     或 `[A-Z][A-Z_0-9]+\s*=\s*[A-Z][A-Z_0-9]*\s*\.\s*(filter|map|concat|slice)`
  2. （可选加强）全文件未出现对 require 的被测函数的调用形态 → 提示性剔除
- **旗标**：挂 `DEFENSE_V2_ENABLED`（与 N1/N2 同层，默认关）。P1 环境契约第 6/7 条
  已有提示词对偶（"mock 禁令"段可扩展"禁重组被测数据"措辞——顺带一行）。
- **验收（确定性重放）**：369 的 4 条失败用例代码原文重放 → 剔除；正常调用型用例（如
  registerSubject vm 沙箱用例）→ 放行不误杀；旗标关=逐字节不变。
- **任务 415 标本升级（2026-11-06 增补，比 369 更极端的红队实锤）**：415（需求
  "验证登陆注册系统是否有异常"，同 853 项目）的登录注册族 **11 条用例全部零产品引用**
  （require/readFileSync/vm 计数全 0，login/register/sanitize 全部内联定义在测试体内）——
  11 条"通过"全是**空洞通过**（测自己的 mock），唯一失败的 BUG-01 死于自己 mock 没写
  长度校验，却被判 product_defect 停机。**B1 检测规则据此加一条**：JS 用例全文零产品
  引用（无 require/无 readFileSync/无 vm 加载）= 自包含用例 → 整案剔除；415 全族 11 条
  为验收标本（全剔），369 registerSubject vm 沙箱用例为放行对照（require+vm 引用真实
  被测文件，不误杀）。
- **量**：~2h（含单测）。**诚实边界**：文本启发式，误杀/漏杀可能，论文如实标注
  "启发式闸，拦截率由 F4 红队格度量"。

### E【P1】缺陷去重/同根因聚类（369 专家点名缺口；2026-11-05 增补）

- **调研锚点（研究先行纪律，2026-11-05 检索核验）**：

- **签名设计（零 LLM，确定性，与"评估数字全确定性"口径一致）**：


  - JS 堆栈来源：test_case_results.message 已存错误全文（含 jest failureMessage），

  1. `skills/defect_handoff.py` 新增纯函数 `defect_signature(row)` + `cluster_defects(list)`——可单测
