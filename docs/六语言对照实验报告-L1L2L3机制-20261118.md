**1）测试是否成功？** 6/6 合法终态，零链路故障——

- **诚实出口 1**：php 走 api_blackbox_stop——**该出口上线以来首次真机自然触发**（23 用例全过 0 败但插桩不可达 → "接口级通过数为准"如实声明，不再像基线那样 13 败卡死）。

**2）用量少？** 总 token **-8.2%**（104,633→96,002）。分解：java -36%、js -36%、ts -26%、php（对修复后基线）-88%；go +15%（路由命中后闭包+端点清单注入提示词的成本——诚实报告不藏）；python +2.9%（接口对账注入 vs 用例数减半，基本对冲）。**平铺单文件项目（js/ts）路由未命中也降了 token**——这部分是 LLM 采样波动+用例数自然减少，**不归因路由**（诚实归因：路由生效格=python/go/java/php，其中 java/php 降、go 微涨、python 持平）。

## 四、诚实边界

1. n=1 每语言——波动未控（js/ts 的 token 降幅含 LLM 采样随机性）；路由净效应的严格归因需 n≥3；
2. demo 项目多为平铺/单模块——路由价值（模块锁定+闭包）在 demo 上天然受限，主战场是多模块真实项目（格 A/B 已证）；
3. go +15% 是路由注入成本的实证：接口对账/闭包注入提示词有代价，收益（端点对账、聚焦）在本格体现为用例 12→19（覆盖持平+检出同型）——**净收益评估留给更大样本**；
4. php token 涨（对 #1160）是服务编排多轮的合理成本，对照修复后基线 #1161 是大幅下降。

## 五、结论

六语言矩阵在新机制下**无退化、三处提升（java 转 done/python 覆盖满格/php 正确性质变）、总量 token -8.2%**；接口对账轨 2 格真机触发、api_blackbox 诚实出口首次自然触发；检出能力与基线逐型一致。机制可继续保持在跑批默认开启。
