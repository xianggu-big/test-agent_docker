## 预算规则（钱是硬边界：触线即停，不许自己加）

- **总停车线 = min(¥5, 余额 − ¥1)**。本轮全部 DeepSeek 花费累计到此线，立即停掉一切付费调用。
- 分项上限（都在总停车线之内）：

| 用途 | 单次上限 | 累计上限 | 备注 |
|---|---|---|---|
| 复检用的真机抽验 | ≤ ¥0.15 / 格 | ¥1.5 | 每轮复检 ≤ 2 格 |
| 黄金演示 live（T10-1） | ≤ ¥0.15 / 次 | ¥0.5 | 最多 3 次 |
| 指标测量批（T10-2） | — | ¥3（B 案）/ ¥1.5（A 案） | 先 1 格冒烟再放量 |
| 独立审查（可选） | ≤ ¥0.05 / 次 | ¥0.3 | 见"换视角" |

- **时段**：批量（测量批）只在低价窗 00:30–09:00 / 12:00–14:00 / 18:00–24:30。高峰段 09:00–12:00、14:00–18:00 只做不花钱的工作，单格小验每轮最多 1 格。
- **先冒烟后放量**：任何批量前先跑 1 格，核对账本四表齐全，再放其余。
- **钱紧时的优先级**：先保测量批（至少 A 案 15 格），其次黄金演示 live，最后才是额外的复检抽验。
- 每次烧钱前，在台账里写一行：预期花多少、上限多少。每次烧钱后对账（`llm_calls` 或驱动器结算），记进台账的花费账。
- 触线后：停掉该项付费动作，继续做不花钱的工作；被钱卡住的关键步骤写请示卡。抽验额度用完后，"真机端到端"这一维改用夹具库复验，并在轮次记录里注明"本轮无真机抽验"。

### 循环点：复检-修复（轮次号全局递增：R1、R2……）

每一轮按这个顺序走，顺序不可跳：

1. **复检**——八个维度全查一遍（见下表）。每条都要有**本轮**的证据：命令输出、查询结果、页面截图、留档路径。上一轮的结论不算数，要重新执行。
2. **登记**——发现的问题全部进台账的问题台账：编号、轮次、维度、严重度。
3. **分诊**——每个问题过三问，三问全过才修：
   - 能复现或对码证实吗？拿出证据。
   - 在本规划范围内吗？范围外 → 请示卡，不修。
   - 修法触及硬边界吗？触及 → 请示卡，不修。

   定性四选一：文档错了 / 代码有 bug / 环境问题 / 判据本身不合理。
4. **修复**——先红后绿，最小改动，不顺手重构。每个修复单独 commit。设计稿错了就按应变协议改设计稿，留四件套。
5. **复验**——把修复所影响的维度重跑一遍。**修了没复验 = 没修。**
6. **回归**——全量 pytest + 守卫。涉及采集、指标、页面的修复，预算允许时加一次真机抽验。
7. **记账**——更新台账，写一份轮次记录：查了什么 / 发现什么 / 修了什么 / 没修的为什么 / 花了多少。

| 维度 | 查什么 | 怎么查 |

| A 回归与守卫 | 全量 pytest 绿且数量只增不减；`scripts/module_check.py` OK；账本开关关时图形态与消息逐字节不变 | 跑 |
| B 卡片验收重放 | 设计稿 §12 里本段每张卡的验收条目 | 逐条重新执行，证据路径写进台账 |

### 换视角（每轮至少做到两条）

- **只看产物不看实现**：拿验收条目去对测试输出、库里的行、页面、导出件，不读自己写的代码。
- **换一条独立路径算同一个数**：SQL 直算、`run_metrics` 函数、页面显示，三方必须一致。
- **派一个没看过实现的审查者**：能用子代理或新会话就派一个，只给它验收条目和产物。
- **可选：调 DeepSeek 当独立审查员**。给它验收条目和差异，请它专门找"验收不成立"的证据。它的每条意见你都要先复现才算数。
- **当验收官**：对着学院进度文档每个"已完成"问"证据在哪"，三秒内指不出来就算未完成。

- 台账里没有打开的问题。需要用户裁决的，已写成请示卡并标"待拍板"。

### 什么时候必须停（整个任务结束）

- 收敛且 T11 完成 → 收尾结束。这是正常终点。
- 总停车线或某个分项触线，并且剩下的关键步骤都需要钱。
- 同一个问题修了 3 轮还没解决。这时不许试第 4 次：登记为卡点，写清已试方案和怀疑方向，继续做不依赖它的工作；**只有它阻塞主线时才整体停手**，写卡点报告。
- 同一个循环点复检超过 8 轮仍不收敛 → 写卡点报告。
- 基线 pytest 红且不是你造成的。
- 任何硬边界（预算、预注册判据、安全边界、范围外）需要现场改。
- 需要重启生产 server，而它上面有在途任务。

### 真机验证怎么做

- **旗标**：server 环境同时带 `MTA_AGENT_LOOP=1` 和 `MTA_RUN_LEDGER=1`。放格前自检 `GET /api/runs` 返回 `ledger_enabled: true`，否则不放格。
- **日常复检**：优先用进程内临时库模式（参照 `data/reports/agent_loop_2x2/run_2x2.py`），不动生产 server，不污染生产库。要看页面时，起一个带夹具库或临时库的验证 server（参照 `data/reports/ui_nav_verify_20261123/run_nav_check.py`）。
- **只有 T10 必须落在生产库**：重启生产 server 前确认没有在途任务，验完恢复无旗标启动。
- **容器名唯一**：放格前 `docker ps` 确认没有同名容器。

## 执行台账（`docs/学院达标-执行台账.md`）

它是你的断点，也是上下文被压缩后的保险。每完成一张卡、每一轮循环、每一次烧钱都更新并 commit。五块内容：

5. **未决请示卡**：每张一句话，在等谁。

## 硬纪律（违反任何一条 = 停手写卡点报告）

1. **应变协议优先**：结果与设计稿不符 → 六步循环（停 / 取证 / 定性 / 改文档留四件套 / AGENTS 记账 / 断点重跑）。
2. **硬边界不许现场改**：预算与停车线、预注册判据、安全与治理边界、范围外事项。触线写请示卡（选项 + 推荐 + 代价）放 `docs/`。
3. **修了必须复验**，并且先红后绿。
4. **生产库不做历史数据的回填、清理、修复**。设计内允许的写入只有三样：新表自动补建、T10 落库、正常的平台运行写入。
5. **写代码用 Write / Edit，禁 heredoc**。
6. **TaskState 里跨节点用的键必须显式声明**，否则被 LangGraph 静默过滤。
7. **指标诚实**：没数据就报"无数据"或 `null`，不许报 0；历史近似值带 `approx` 标；不同批次、不同口径不混算。
8. **每个发现先过三问再修**；范围外的不修，写请示卡。
9. **批量只在低价窗，先冒烟后放量**。
