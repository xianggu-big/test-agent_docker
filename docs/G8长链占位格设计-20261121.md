# G8 长链占位格设计（java 级长链——竞态真机格改进项）

> 来源：G8 未达成定性（docs 修复验证批 g7_g10_judgment）——js-calc 快链 ~80s 撑不住
> 阶段一窗口，stop 到时已 running 按设计 409；A4 分支已由 D 包单测 13 例覆盖。
> 本设计给竞态格一个**prep 阶段足够长**的占位项目，让"放行 3s 内 stop"落在可制造窗口内。
> 状态：设计稿（待实施）；预估 0.5 天零 API + 真机 1 格 ≈¥0.1。

## 1. 竞态窗口需求回顾

A4 三道闸的竞态点：worker 认领（两步）与用户 stop 之间的瞬间。真机复现需要：
**放行 → 在 prep 阶段（cloning/analyzing 等）耗时 ≥3s 的窗口内 stop**。js-calc prep
~80s 看似够长，但 G8 三跑全 miss 的实锤原因=放行到 stop 的驱动器延迟（409 判定
按设计）——窗口制造依赖**可控时长的 prep 慢点**而非长任务。

## 2. 占位项目：java-multimodule-slow

- 形态：Maven 多模块（3 模块 pom 聚合）+ 每模块 1 个空测试类——链路本身合法
- **慢点注入（确定性好、不依赖网络）**：父 pom 的 `maven-antrun-plugin` 在
  `generate-sources` 阶段 `sleep 45`（纯 java 系镜像内可执行，无外网依赖）
- prep 长点落在 **provision 预热**（mvn 依赖解析/编译）——比 clone/analyze 稳定
- 镜像：mta-test:jdk17-maven（已有）；项目放 data/demo/java-multimodule-slow

## 3. 竞态脚本改造（run_g8_cancel_race.py v2）

- 三档窗口试探：stop@放行后 1s / 3s / 8s（v1 固定 3s 三跑全 miss 的教训）
- 判据不变：**任一档 stop 成功（cancelled 终态+零执行轮次）即 PASS**——竞态是
  概率窗口，多档采样比单档三跑更有效
- 对照格保留：全流程健康格（不 stop 跑到终态）证明占位项目链路本身通

## 4. 验收

- [ ] 占位项目链路真机 done（健康格）
- [ ] 三档窗口至少一档制造出 cancelled+零执行
- [ ] A4 审计：认领守卫/队列条件更新留痕（[a4] 消息）
- 判据与 G8 原判据同源（cancelled 终态一致性）
